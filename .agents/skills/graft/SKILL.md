# graft — codebase context graph

**Mental model:** `graft` is a pre-built map of the repo — 17k+ symbol/file/type nodes with call and
import edges, generated by tree-sitter from the working tree. Querying the map is cheaper than
re-exploring the tree with Glob/Grep/Read, and every answer cites `path:line` you can jump to.

Graft is an npm global (`npm install -g @nanonets/graft`). The graph lives in `graft/` at the repo
root — a **local, regenerable cache**: git-ignored, never committed, rebuilt per machine with
`graft build` (~36s full, incremental by content hash afterwards). Every query auto-refreshes
changed files first, so answers reflect uncommitted edits.

## When to Use

Reach for graft **first** on navigation and comprehension questions, before a broad search:

| Question shape                                     | Command                             |
| -------------------------------------------------- | ----------------------------------- |
| "Where is X implemented / how does X work?"        | `graft ask "how does X work?"`      |
| "What calls this symbol / blast radius of a edit?" | `graft callers <symbol>`            |
| "What is this file's public API?"                  | `graft skeleton <path>` (no bodies) |
| "Exhaustive regex hits across indexed code"        | `graft grep "<pattern>"`            |
| "What is the architecture / where do I start?"     | `graft map`                         |

Then confirm with `Read` on the cited `path:line` before editing — graft locates, it does not
review.

## When Not to Use

- Full file contents or edits — use Read/Edit.
- Non-code assets (Markdown prose, YAML, generated output) — graft indexes code files only; use
  `rtk grep`.
- One-off known-file lookups where you already have the path.
- If `graft` is not on PATH or `graft/` is absent and the task cannot afford the ~36s first build,
  fall back to `deno doc` + `rtk grep` per `AGENTS.md`.

## Setup / freshness

```bash
npm install -g @nanonets/graft   # once per machine
graft build                      # first build (~36s on this repo); incremental afterwards
```

`graft build --deep` (LLM enrichment, needs `GRAFT_API_KEY`) is **not** part of the standard
NetScript setup — the structural graph is the supported tier. Do not commit `graft/`, and keep the
root `.ignore` file (it re-admits `graft/` to ripgrep despite the gitignore).

## Relation to existing tooling

- `deno doc <module>` stays the authority for a package's _public publish surface_; graft covers
  cross-file wiring and discovery inside the repo.
- `rtk grep` stays the cheap raw-text search (including Markdown); `graft grep` is scoped to indexed
  code and returns symbol-aware hits.
