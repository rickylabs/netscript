## Scope

`packages/fresh/src/runtime/ai/create-chat-connection.ts`'s `toNetScriptChatResponse()` wraps the
third-party `toDurableChatSessionResponse`, which already accepts `mode?: 'immediate' | 'await'` and
`waitUntil?: (task: Promise<unknown>) => void` — but `NetScriptChatResponseOptions` exposes neither,
and `defaultToResponse` never forwards them. Add both, forward them, and extend the pluggable
`toResponse` seam's input type so a custom adapter doesn't lose them either.

**Exact fields to add to `NetScriptChatResponseOptions`** (types match the upstream transport
exactly — do not rename or reshape):

```ts
/** Completion mode forwarded to the transport. Defaults to `'immediate'` (transport default) when omitted. */
readonly mode?: 'immediate' | 'await';
/** Background-task registration forwarded to the transport (e.g. a Worker's `ctx.waitUntil`). */
readonly waitUntil?: (task: Promise<unknown>) => void;
```

Forward both into `defaultToResponse`'s call to `toDurableChatSessionResponse({...})`. Add the same
two fields (both optional) to the `toResponse` custom-adapter input type, and forward `options.mode`/
`options.waitUntil` into that call site in `toNetScriptChatResponse` as well — a consumer who
overrides `toResponse` must still receive them.

**Do not change the default behavior.** Omitting `mode` must produce byte-identical behavior to
today (the transport's own `'immediate'` default applies; do not write `mode ?? 'immediate'` into
the wrapper itself unless doing so is truly behavior-neutral — prefer passing `options.mode` through
undefined and letting the transport apply its own default, matching LD-4).
