## What this leaf is

#1466's acceptance is six lines, and four of them are traps if read loosely:

1. `NetScriptProcedureMeta` has a **public, versionable, NetScript-owned** shape.
2. **Existing contract error literals remain preserved end to end.**
3. Metadata reaches direct clients, generated clients, and query factories **without casts or
   `any`**.
4. Positive **and negative** type fixtures exercise **real exports**.
5. Public docs explain ownership and compatibility boundaries.
6. Required SDK/contracts gates and IMPL-EVAL pass.

Point 2 is the whole difficulty. S1 (#1350) repaired the concrete error channel through `safe()`;
this slice adds metadata **without regressing that repair**. Metadata that erases the error union is
worse than no metadata, because it converts a typed failure into a silent `unknown` at every call
site downstream.

Point 3's "without casts or `any`" is a testable property, not a style note — an `as` that bridges
your new vocabulary to oRPC's types is exactly the defect. This lane rejected precisely that pattern
one leaf ago: a public type was declared wider than the upstream contract it fronted and an
assertion silenced the mismatch, which type-checked while silently skipping a conversion path. Do
not reintroduce it here.

Point 4's "**real exports**" means the fixtures must import from the package's public entrypoint,
not from internal paths. A negative fixture that cannot fail — or that passes because it tests an
internal declaration nobody ships — is not a guard.
