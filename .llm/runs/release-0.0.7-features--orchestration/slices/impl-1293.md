## Read this before you read the issue — the issue's premise is stale

I verified the live package myself. **Do not start from the issue text.**

**Gap 1 in the issue is accurate.** `src/adapter.ts:319` declares `class PrismaMySqlAdapter` with no
`export`, and `src/mod.ts:40` re-exports only `PrismaMySql` and `PrismaMySqlAdapterFactory`. The
class an example would need to name is genuinely unreachable.

**Gap 2 in the issue is wrong, and the truth is worse.** The issue says "No connection-error hook."
In fact `src/types.ts:35-40` already declares

```ts
export interface PrismaMySqlOptions {
  /** Database schema name */
  database?: string;
  /** Callback when connection errors occur */
  onConnectionError?: (err: Error) => void;
}
```

and `src/mod.ts:51-58` already re-exports `PrismaMySqlOptions`. The package publishes at version
`0.0.6`, so **that option is already shipped**. It is also **never called**: a repository-wide search
for `onConnectionError` returns exactly three hits — the declaration, `examples/basic-usage.ts:39`
which passes a callback that can never fire, and `docs/site/reference/prisma-adapter-mysql/index.md:23`
which tells readers the hook "is not supported by the shipped adapter and is blocked on #1293".

So this is a **published option whose predicate can never fire**, shipped next to an example that
looks like it uses it. That is the exact defect class this lane has already caught twice on #1502.
Your job on gap 2 is therefore not "add a hook" — it is to decide between **wiring the option that is
already published** and **removing it**, knowing the two are not symmetric: wiring is additive,
removing is a breaking change to a published surface.
