## Hard constraints from the plan and the evaluator

- **Do not export `link`, `ClientLinkPort`, `ClientLinkCallOptions`, or anything under `./internal`.**
  Exporting `link?:` would make #1349 pre-empt #451. LD-1.
- **`port` and `timeout` stay accepted and `@deprecated`** — not removed. Their disposition belongs to
  #1351. LD-2.
- **No `before`/`after`/`requires`/`priority` on descriptors**, and **no environment flag**. The RFC
  forbids both. Dependency-ordering rejection resolves as `SDK_CONTRIBUTION_INVALID` shape
  invalidity; Desktop rejection is the **existing excess-property check** on
  `CreateDesktopServiceClientOptions` plus construction-time
  `SDK_CONTRIBUTION_TRANSPORT_UNSUPPORTED`. LD-6/LD-7.
- **Keep `TError` in the third `ServiceClientMethod` slot**, context appended fourth. #1350 forbids
  erasing the error channel; slice gate 5 asserts it.
- **Defaulted context generics must leave every existing call site compiling unchanged.** This is a
  hard acceptance criterion, not a nicety. Apply the compatibility defaults from the RFC table
  directly, row by row.
- **Tuple arity law:** 16 contributions succeed, 17 fail, at construction.
- **`isolatedDeclarations`-safe:** public types must be explicitly annotated and emittable; inference-only
  helper types that cannot be emitted are unacceptable because publish dry-run is a gate.
- Slice 1 is **types and public contract only** — no adapter, no behaviour. The private adapter,
  prepared-call epoch logic, and stable-v1 adapter are **Slice 2** and must not be started.
- The evaluator's note: the types-accepted-but-unconsumed window between Slices 1–3 **must not
  publish**. Keep the `ports/mod.ts` edit to exports only.
