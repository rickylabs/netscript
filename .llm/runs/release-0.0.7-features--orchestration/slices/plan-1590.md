## The problem, in the issue's own terms

Fresh 2.3.3 does not reliably order overlapping full-page and named-region partial requests. A late
response from navigation A can repaint after navigation B, call `replaceState(A)`, or reuse a mounted
partial boundary registered under the previous region name. **Aborting the browser fetch is not a safe
workaround under Vite dev** — the server-side abort surfaces as an unhandled `AbortSignal` overlay.

NetScript should own a documented partial-navigation coordinator providing:

- **last-intent-wins ordering** — navigation generations, late page/region bodies dropped *logically*;
- **abort-safe disposal** — superseded responses **drained**, not aborted;
- **remount-safe dynamic region names** — keyed Fresh partial comment boundaries so a changed name
  remounts cleanly;
- **route-change subscription** and programmatic client navigation.

Applications must not patch `fetch`, `history`, or server HTML markers. The removal condition is that
EIS Chat can delete `apps/dashboard/lib/client-nav.ts`.

## Research this before deciding anything

1. **What Fresh 2.3.3 actually does today.** Read the partial-navigation client in the installed
   `@fresh/core` — how it issues partial requests, applies bodies, and manages `history`. Cite line
   references. Do not design against a guess about upstream.
2. **Where the seam belongs in `packages/fresh`.** Archetype 4 is a DSL/builder package; a client
   runtime coordinator must sit somewhere principled. Justify the placement against doctrine, and say
   what the public surface is versus what stays internal.
3. **The drain-not-abort constraint.** Establish *why* aborting breaks under Vite dev, from evidence,
   and what "drain" must mean concretely (read to completion and discard? detach the reader?).
4. **Region identity.** Determine how Fresh keys partial boundaries today and what changing a dynamic
   region name currently does, so "remount-safe" has a measurable definition.

## Open questions the plan must lock, each with rationale

- Generation/ordering model: monotonic counter, per-region or global, and what happens to an in-flight
  region request when a *full-page* navigation supersedes it.
- Whether `replaceState` suppression is a coordinator concern or a caller concern.
- The subscription API shape, and whether it is public surface for 0.0.7 or internal.
- What is **out of scope** for this issue versus the broader navigation story.
