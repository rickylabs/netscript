## Scope

The scaffold template
`packages/cli/src/kernel/assets/plugins/service-context.ts.template` is 123 lines emitted into every
generated project. **69 of those lines (56%) are a `LazyPluginKv` class** that implements
`WatchableKv` by deferring `getKv()` — both of which are `@netscript/kv` types. It has zero
plugin-specific content and belongs in the package that owns its contract.

**Publish `createLazyKv(config?: SharedKvConfig): WatchableKv` from `@netscript/kv`**, then delete
the template's local class and import it instead.

**Behaviour must match the existing class exactly** — read it as the reference implementation:
`supportsWatch = true`; memoized resolution (`getKv` called at most once); async-generator delegation
for `list`/`watch`/`watchPrefix`; `[Symbol.asyncDispose]` delegating to `close()`; every other member
awaiting resolution then forwarding.

Put the implementation in its **own single-reason module** under `packages/kv/application/` (do not
append to `shared.ts`), export it through `packages/kv/application/mod.ts`, and re-export from
`packages/kv/mod.ts` alongside `getKv`.

Then regenerate the assets barrel (`deno task gen:assets-barrel`) and commit
`packages/cli/src/kernel/assets/embedded.generated.ts` — the template is embedded through it and
`check:assets-barrel` guards it.

**Nothing else in the template changes.** `getDatabaseClient`, the `createPluginServiceContext`
factory, and the contracts/logger/env composition all stay exactly as they are.
