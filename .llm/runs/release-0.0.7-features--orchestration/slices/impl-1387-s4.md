## Evidence — the lessons already paid for in this run

- **`run-gate.ts` requires `--gate <catalog-key>`**; anything after `--` is *appended* to that gate's
  argv, not substituted. Passing a full command there duplicates it.
- **A shell loop over gates can exit 0 even when every gate throws**, writing no receipt while a
  stale prior-slice receipt sits on disk looking current. Verify every receipt by `invocationId`,
  `gitHead == actualGitHead`, and `durationMs` — never by exit code alone. A short duration is not
  itself proof of a replay (`check` caches; `publish:dry-run` does not) — read the receipt's own
  stdout for evidence of the work.
- **Archive the previous slice's receipts by move, not copy**, into a `slice-N-<head>/` folder, then
  verify each moved file byte-identical to what was at HEAD before the move. A copy-then-recut leaves
  any receipt without a successor sitting at the top level looking current — that is exactly how a
  Slice 2 evaluator caught a real defect (D-6). Slice 3's receipts already sit at
  `receipts/slice-3-c297064aa/` (or similar) — check the actual directory name in the worktree rather
  than assuming, and follow that pattern for Slice 4's own archiving before you recut.
