# 2026-10-31 — Final S2 resumption lessons

- Preserve the existing PR and retained reviewer session when resuming an interrupted delivery. Owner-specific Refs-only/no-label/STOP-at-READY instructions take precedence over generic issue-closing or new-PR boilerplate.
- Serialize docs/carrier regeneration before starting consumers of their imported constants. A test process can retain old module bytes while a later import sees newly generated prose, producing a misleading parity failure even though subsequent freshness checks pass. A stable complete rerun is the evidence; keep the initial result visible.
- A newly merged root quality baseline remains a failed root gate. Verify the flagged file matches main, run architecture separately because the chain short-circuits, and report the package/plugin scan independently. Do not suppress the finding or repair unrelated upstream code to manufacture a green gate.
- Native Opus review successfully resumes after quota reset with the owner's exact command, closed stdin and explicit read-only tool list. Preserve the same session for terminal test-evidence confirmation; a source PASS issued before the last test result is not READY until that result is verified.
- Structured test reports record commands/cwd/results without a Git SHA. Keep source unchanged throughout the run/review and state that provenance limit. Durable allowlisted gates separately record the immutable head.
- The exact scaffold runtime gate still fails before resource startup when Docker is unavailable. Preserve the runtime/cleanup limitation and leave all unproven resources untouched.
