## Design

1. **Portable bounded journal.** Introduce core KvSagaEventFeed in the existing ./adapters subpath, consuming the existing WatchableKv port. No second generic bus, transport, lifecycle registry or datastore abstraction. Default policy SAGA_EVENT_HISTORY_LIMIT=256 is fixed for journal format1: one small head plus256 directly addressed ring slots, at most257keys. No time-based TTL or background pruning. A large event retains the backend's existing per-value limit; no smaller arbitrary payload cap. Slot storage avoids a single aggregate array exceeding native Deno KV's value limit. KV namespace isolates an application, as before.

2. **Atomic append and order.** Prefix ['saga','event-feed','v1']; head key [...prefix,'head'], slots [...prefix,'slot',index]. Head {format:1,epoch,sequence}, epoch from crypto.randomUUID in the adapter, safe nonnegative integer sequence. Atomic compare head versionstamp then set both next slot and next head in ONE existing kv.atomic commit. Slot contains epoch,sequence and an immutable detached event snapshot. Slot index (sequence-1)%256. Successful commit defines global publish order across API processes; concurrent invocation order is not promised. Expose opaque stable id epoch:sequence, never derive order from backend versionstamps. Refuse malformed/corrupt metadata and safe-integer exhaustion instead of wrapping/resetting. Retry CAS conflict at most64times, then a structured retryable unavailable error; native IO error has an unknown outcome and is not blindly retried by the feed. No new Redis command or Lua/Streams requirement.

3. **Canonical types and public surface.** Move the existing SagaSSEEvent/SagaSSEEventType declarations into existing domain/saga-message.ts (message/notification vocabulary), retain identity imports/re-exports at contracts/v1 so existing clients and schema stay compatible. Domain/errors.ts owns a small structured SagaEventFeedError with invalid-cursor/history-lost/unavailable reason and optional oldest/latest ids/cause, using the existing saga error family. No new domain file/cardinality or root export. Adapter module owns explicit SagaEventFeedEntry {id,event}, SagaEventFeedItem ready/event union, subscribe options {afterId?,signal?}; public class append(event,{signal?}) and subscribe(options):AsyncIterable<SagaEventFeedItem>. Existing adapters entrypoint names only the reachable types/classes/constants needed by this contract. No exported Zod implementation or upstream barrel mirror. Public quick-start is designed in S1 before policy implementation.

4. **Live subscription and startup barrier.** Each subscription owns one fixed-head kv.watch({initial:true,signal}) and its own cursor. Redis's existing KV adapter multiplexes same-key subscriptions through its shared subscriber; do not add a hidden process singleton or cross-request registry. Start iteration before awaiting optional native ready; for a third-party handle without ready, require its initial frame. After acknowledgement, reread head before yielding a ready item. A subscription without afterId starts at that current head (live-only); an initially empty history adopts the first append epoch at sequence0. The router emits its connected heartbeat only after ready. Writes racing the initial snapshot/ready cannot be lost: a native watch is already active and every wake rereads head rather than trusting notification order. The ready/heartbeat carries no id, preserving the last data cursor. A client that has never received a data id has no replay position and starts live again.

5. **Coalescing and bounded readers.** A continuously running, per-subscription watch pump drains native head notifications independently of SSE backpressure. It retains one wake token/terminal failure, not a per-event queue. The consumer captures a wake token BEFORE reading head, then reads the known slot keys from cursor+1 through the snapshot head, at most256, via native getMany or bounded Promise.all fallback. Validate every requested slot epoch/sequence. Advance the reader cursor per record; yield in numeric sequence order. A wake during a read/yield resolves the captured token, preventing a lost wake. Duplicate/coalesced notifications cannot duplicate a data id in one iterator. No list/watchPrefix/SCAN and no polling timer, including idle and initial connection. Retained read buffers never exceed256events. No new clock port is needed: retention is by count, timestamp is supplied by the existing publishing edge, and this adapter adds no timers or sleep/backoff loop.

6. **Resume and gaps.** Read native oRPC handler lastEventId and pass as afterId. Absent/empty means live-only. Bound header length to100characters; canonical UUID:nonnegative safe-integer decimal syntax, no leading-zero ambiguity. A cursor from this epoch may resume when sequence is at least oldest-retained-minus1 and no later than current head. Replay all later retained records, then live notifications. A cursor older than the window, from another epoch, missing head after prior history, or missing/overwritten required slot produces explicit history-lost, never a silent live reset or incomplete replay. A malformed/future cursor produces invalid-cursor. Filtering remains the existing sagaName presentation filter, applied after global cursor advancement; filters do not get independent retention windows. Existing sagaId/topic filter behavior is unchanged.

7. **Native wire errors.** Presentation maps invalid-cursor to native ORPCError BAD_REQUEST/status400, history-lost to CONFLICT/status409 with available oldest/latest ids, and backend/corrupt-history/unavailable to SERVICE_UNAVAILABLE/status503. Native streaming transport can already have HTTP200/initial comment committed: these are standard oRPC SSE error frames followed by close, not a promise of a409HTTP response. Private real-router protocol probe confirmed exact native frame shape. Clients handle the error and obtain a fresh snapshot/reconnect without old cursor after a gap. Do not add a new event kind or widen SagaSSEEvent's existing schema.

8. **Lifecycle, cancellation and failures.** Named private subscription state starting/watching/failed/closed. Each iterator owns an AbortController combined with caller signal; finally aborts and joins only its watch pump, never closes the caller's KV. Unexpected watch end/error terminates with structured unavailable; do not swallow or silently loop. Use @std/async abortable for pending KV get/getMany/atomic waits, reusing the already locked standard library with an explicit core import mapping if needed. Propagate the existing request signal into default event append; injected legacy event writer remains source compatible and its wait is abortable. Abort can abandon native IO with an unknown commit outcome; it does not undo a committed append. A custom KV lacking atomic/watch capability fails explicitly, with no racy non-atomic fallback. General backend subscriber recovery remains owned by KV issue2639, not duplicated here.

9. **Publish and delivery guarantee.** Replace only the existing default API event writer with journal append; keep runtime acceptance-before-event-write ordering and injected writer seam. Observation is not a transaction with saga state/runtime acceptance. An uncertain backend commit or publish retry may produce another notification; stable ids support deduplication across reconnect. Within retained history and healthy storage, each connected reader gets every matching event in commit order; an overtaken slow reader receives explicit gap rather than silent loss. Backend durability/eviction still follows its own configuration; API process restart preserves ids when KV survives. No new engine/event publishers or saga transports wired.

10. **Upgrade boundary.** Legacy random-key events and per-connection numeric ids cannot be reconstructed into an ordered log. Use the new versioned prefix. Drain/stop old API instances during upgrade; old cursors are invalid and clients start a fresh subscription. No legacy prefix scan or destructive migration on connection/append. Existing obsolete keys may be removed once through an operator's KV maintenance path; they are not read or extended by the new feed. The documented257-key bound applies to the new journal. No incremental background GC or cross-version rolling delivery guarantee.

## Quick-start contract (to write publicly before implementation)

## Risk register

- Aggregate Deno value limit: per-event slots, explicit large-native-event test; count bound does not claim a smaller payload cap than provider encoding.
- Concurrent appends: one head CAS+slot transaction; exact matching sequence/epoch and multi-adapter writer tests, bounded conflict failure.
- Snapshot/subscribe race: watch first/ready/reread, wake token captured before reads; injectable real boundary race tests.
- Slow client memory/data loss: independent coalescing watch pump, <=256read buffer, explicit retained-window gap; no append queue per client.
- Retention overwrite during read: validate requested slot identity, report history-lost; never return later payload for old id.
- Reset/eviction/old upgrade id: epoch binding and explicit errors, no accidental reset or migration SCAN.
- Notifications coalesced/duplicate/out of order: reread durable head, use own numeric sequence; never sort Redis stamps.
- Cancellation/unknown outcome: std abortable waiting and owned controller/pump cleanup; do not close host KV or retry a thrown ambiguous commit.
- Native SSE error status: test standard error frames, not HTTPstatus assumption; heartbeat id absent.
- First-party capability vs custom KV: atomic/watch required; unsupported adapters fail explicitly, no unverifiable fallback.
- JSR/folder debt: canonical types in existing small domain files, adapter files<500, contract shrinks, no root mirror/dependency-version churn; all new refs must close with zero diagnostic growth.
- External resource ownership: exact creation IDs/labels/native mounts retained privately; maintained leak/teardown preview and exact cleanup, foreign left alone.
