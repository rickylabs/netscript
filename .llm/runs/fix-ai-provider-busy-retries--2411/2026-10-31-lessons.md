# 2026-10-31 — provider busy retry lessons

- TanStack AI 0.68 moves adapter retryAfterMs into metadata.tanstack when normalizing RUN_ERROR; inspect both supported seams rather than assuming the raw adapter shape survives chat().
- OpenAI error code takes precedence over HTTP status in TanStack's projection. The known rate_limit_exceeded alias maps to 429; insufficient_quota must remain nontransient. Do not infer HTTP status for unknown symbols.
- JavaScript timer overflow can turn a huge server wait into an immediate retry. An explicit provider delay above the retry ceiling must fail without another request, preserving its metadata, rather than clipping the minimum.
- OpenAI-compatible SDK maxRetries belongs in ClientOptions, not modelOptions. Preserve it in the opaque registry reader as well as the directly typed constructor. Both supported APIs need request-count tests.
- A wrapper that retries thrown errors also needs to consume retryable error events before yielding anything; after any output, preserve the terminal event and never replay the stream.
- Full-export doc lint's combined exit can be green while individual entrypoints retain private-type-ref diagnostics. Compare per-entrypoint counts and exits to baseline; ai-doc-private-ref-baseline-2036 remains applicable.
- Import-map negative controls need explicit scoped dependency subpaths when a mutated adapter is moved outside its package. Reject process/compile failures as negative proof.
