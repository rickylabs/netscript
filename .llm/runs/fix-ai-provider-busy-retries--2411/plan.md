# Plan & Design — READY FOR REVIEW

Issue #2411, F1, direct-to-main leaf. Archetype 2 integration. LOCKED: preserve the existing error-event contract, using AiRateLimitError as cause for known busy RUN_ERROR. Busy code mapping is a named closed map: 429 -> 429, 503 -> 503, rate_limit_exceeded -> 429; insufficient_quota and unknown symbolic codes are not retried. Shared bridge behavior intentionally applies to all providers using this boundary. Add optional numeric status to that existing owned error; preserve safe code/status and validated retry delay, never raw provider request/header objects. Read retryAfterMs from the normalized metadata.tanstack seam, with direct field fallback.

LOCKED: retry wrapper consumes retryable error events only before any output; throw their cause inside the existing retry try/catch. Once any text/reasoning/tool/finish event is visible, never retry; preserve partial-stream terminal errors. Non-retryable error events retain existing behavior. Exhaustion throws AiRateLimitError with attempts, status and retryAfterMs. Generic thrown 429/503 also qualifies. Abort always wins; existing injected abort-aware sleep is retained. Provider Retry-After is a minimum, not a value to clip. maxDelayMs is the retry-wait ceiling: if the server delay exceeds it, fail immediately with typed attempts/status/retryAfterMs and make no further request. Delays within it are honored exactly. The absolute timer ceiling is 2^31-1 ms even if the caller supplies a larger maxDelayMs, avoiding timer overflow. Default ceiling remains 5,000 ms; callers wishing to wait 120 seconds must explicitly configure it. Sleep remains abortable.

LOCKED: optional maxRetries on OpenAiCompatibleModelProviderConfig flows through direct and registry constructors to upstream SDK options; zero disables SDK retries. Omission keeps SDK default; validate explicit values as finite nonnegative integers. No retry fields on request JSON or provider-neutral port. Docs explain ownership: configure maxRetries:0 when using AiRetryPolicy.
