# Existing-issue relationship map — Aspire 13.5 adoption & stabilization

> Draft, 2026-08-29. **No GitHub mutation was performed.** Every issue number below was re-verified
> with `gh issue view` on 2026-08-29 (state, milestone, labels). "Sub-issue" ids (`S-xx`) refer to
> `sub-issues/NN-*.md`; the epic is `E`. GitHub wins on conflict once the coordinator files.

Vocabulary: **closes** — a sub-issue PR carries `Closes #N`; **supersedes** — the sub-issue replaces
the premise, close the old issue with a comment at filing; **unblocks** — the epic delivers what the
issue waits on (relabel `status:blocked` → `status:triage` at filing); **depends-on** — must land
(or be explicitly accepted as a gap) before the epic's verdict; **sequence-after** — downstream work
that should be authored against the post-13.5 surface; **regression-check** — closed issue whose fix
is version-sensitive and is re-run by the verification slice; **related-only** — no epic action.
