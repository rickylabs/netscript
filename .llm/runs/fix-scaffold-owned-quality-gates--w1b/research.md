## Current generated quality contract

`packages/cli/src/kernel/templates/workspace/deno-json.ts` currently emits:

- `check`: `deno check apps/**/*.ts services/**/*.ts contracts/**/*.ts`
- `lint`: bare `deno lint`
- `fmt`: bare, mutating `deno fmt`

This is asymmetric and untrustworthy: check omits TSX, plugins, background runtimes, the AppHost,
and helpers, while lint/fmt traverse non-product material. There is no `fmt:check` task.

The closest established generated-tool pattern is `.netscript/verify-node-modules.ts`, generated by
`scaffoldRoot`, tracked through `SCAFFOLD_FILES`, and called by a root task. The repository's
`run-deno-check.ts`, `run-deno-lint.ts`, and `run-deno-fmt.ts` establish the F-19 conventions W1-B
must retain: explicit roots/files/extensions, explicit exclusions, deterministic file enumeration,
non-zero on an empty selection, batching, and structured selection/failure evidence.

The new generated contract should be one dependency-free `.netscript` quality runner with modes for
`check`, `lint`, format-check, and format-write. Root tasks call it without shell globs. It is
always scaffolded, independent of optional agent initialization.

## Owned-source selection

The selection contract is mode-aware and explicit:

| Surface                                                        | Check                  | Lint/fmt           | Why                                                    |
| -------------------------------------------------------------- | ---------------------- | ------------------ | ------------------------------------------------------ |
| `apps/**` (`.ts`, `.tsx`)                                      | direct                 | direct             | Fresh server and UI code                               |
| `services/**`, `contracts/**`, `plugins/**`                    | direct                 | direct             | AppHost service/plugin graph and contracts             |
| `workers/**`, `sagas/**`, `triggers/**`, `streams/**`          | direct                 | direct             | default background runtimes                            |
| `aspire/apphost.mts`, `aspire/.helpers/**/*.mts`               | direct                 | direct             | executable generated AppHost product source            |
| `.netscript/*.ts`, root config, scaffold tests, DB user source | direct                 | direct             | generated project tooling/source, where present        |
| imported runtime registries/clients                            | reached by check graph | no direct lint/fmt | generator-owned machine output, not user-edited source |
| `aspire/.aspire`, `node_modules`, caches, `.data`              | no                     | no                 | dependency/cache output                                |
| `.llm`, `.agents`, `.claude`, offline docs/skills              | no                     | no                 | optional agent/offline assets, not product source      |

The current root config excludes `aspire/.helpers`; that is incompatible with the second acceptance
item because those `.mts` files are executed by `aspire/apphost.mts`. W1-B must remove that
false-green path for type-check rather than merely passing their names to a command that the Deno
config excludes. Dependency-owned `aspire/.aspire` remains excluded.

## Architecture, JSR, and gate classification

- Primary archetype: **Archetype 6 — CLI and Tooling**. No overlay is selected: generated app,
  service, and background code are the CLI's output contract, not framework-layer feature work in
  this slice.
- Contract order: selected-file/report schema and generated tasks, then negative/positive proving
  tests, then generator implementation and defect fixes.
- Relevant doctrine: explicit public/generated contracts, AP-2 layering, AP-9 registry ownership,
  AP-18 semantic tests, AP-25 effect boundaries, and F-19 scoped source gates.

  assets ship in `@netscript/cli`: keep ESM, dependency-free generated runner source, checked-in
  asset freshness, clean publish file list, no slow-type/public-doc regression, and run CLI
  doc-lint/publish dry-run as static package gates. No publication is authorized.
- Scaffold output changes make `scaffold.runtime` mandatory at merge readiness. `e2e-cli-prod` is
  post-publish release authority and is out of scope because this run does not publish or cut a
  release.
