# Intake drain ownership addendum

## Reason and reproduction

S3 work exposed a hidden dependency in the approved pause barrier design: RedisListener.stop starts a timer equal to visibilityTimeout; when it expires, it aborts settlement, stops receipt IO and resolves the listen generation even if a callback is still running. KV polling also ends its listen generation after its native visibility-based wait. A supervisor pause barrier cannot represent admitted work if its backend ends that generation first. This is the same production behavior as main; no owner-control implementation has been made yet.

New listener-drain-owner_test.ts uses a50ms native drain and a callback held across500ms, with an extra proposed option passed through a variable so it executes against the old public contract. Live Redis/Garnet and KV polling:3owner-option cases FAIL because listen ends before callback completion;3ordinary-default controls PASS,0ignored. Redis/Garnet lease is extended2s before cancellation, separating the short listener drain from claim expiry; the owner case must keep receipt renewal usable as well. The first200ms KV polling probe was too close to its100ms loop cadence and is excluded as nondeterministic;500ms settles the distinct control and ownership outcomes. The S2 native handback/fencing gates remain28/28green.

## Locked additional contract

Add optional ListenOptions.drainTimeoutMs for Redis and KV polling only. Omission retains the existing visibilityTimeout-based post-intake drain. Values are finite positive safe integers through2,147,483,647, or positive Infinity. Reject NaN, zero, negative, fractional and excessive finite values before listener allocation. The value controls backend waiting after intake cancellation; it does not extend visibility or change the worker total budget.

Infinity delegates admitted-callback lifetime to a bounded outer owner. Worker passes this option for jobs, task and trigger listeners because its core drain already owns one25s total deadline with19s work/5s abort cleanup/1s settlement. Pause has no stop deadline: active jobs continue with their existing execution signals and available lease-renewal capabilities. Resume still waits the previous listener generation. Stop still cancels execution after its work window and rejects within its original total if cleanup/close cannot settle. No timeout bypass or unbounded stop is introduced at the Worker boundary; direct queue consumers get their existing finite default.

Redis policy keeps the existing default and finite-validation source names. For Infinity, do not arm the native post-intake expiry timer; keep settlement/receipt IO alive until admitted callbacks settle, then run existing close. Native expiry/reclaim/attempt counting, Lua commands, all receipt fencing and outbox semantics are unchanged. KV polling uses the explicit owner budget for its finally wait; retain its old default/visibility behavior when omitted. No change to lease visibility/renewal semantics on any provider; no long visibility timeouts used as a workaround. Native Deno KV/Postgres/memory and the planned AMQP native-channel implementation already join callbacks without this independent short timeout, so they need no new behavior for the option.

A claim committed before pause but delivered to the Worker after pause remains an ordinary charged requeue. Draining handback remains the shutdown-only opt-in. All previous config, default, typed first-cause, count, fencing and ownership decisions stand. No Redis Streams, saga transport or generic pause/transport abstraction.

## Risk / open decisions

No open design decision. Required before code: independent feature PLAN-EVAL follow-up for this added public option (same primary route, fresh session per T3). The main risk is accidentally making default queue stop unbounded:3negative controls and retained native stop/reclaim tests pin omission behavior. The companion risk is conflating visibility with drain waiting: explicit JSDoc, policy separation and extended-live-lease oracle pin it. Worker must never pass this option without the separately enforced total drain; explicit forwarding plus noncooperative budget tests pin that boundary. Existing visibility limitations of providers without extendVisibility remain unchanged and documented; the option promises callback joining, not stronger delivery exclusivity. No new dependency/lock/command or root surface; primitive numeric field adds no slow type/private reference risk.
