# Published-consumer verification lessons

An explicit jsr: import inside a workspace can still resolve to a same-version local member. Copy a non-discoverable probe into a standalone directory with no workspace ancestry and inspect every NetScript URL in deno info --json; the import spelling alone is not provenance.

Deno2.9 records workspace.dependencies even in native standalone locks. Require its exact two-dependency shape while rejecting workspace members/links/overrides. Preserve the generated consumer lock as an artifact and use a new cache with frozen install for reproducibility; never delete existing caches.

Repository wrapper imports and the child under test have different config requirements. run-deno-test.ts needs the root tooling @std/path map; launch the parent with frozen root config, then forward the standalone config explicitly to every child. Run both from the consumer cwd/cache and hash both locks before/after.

A storage fixture can verify the real public writer without manufacturing its records: accept POST bodies verbatim and relay only framing. Remove native records solely at relay for a clearly scoped negative oracle. Require a named semantic assertion failure and reject process/timeout/compile/connection failures; record the identical positive/control probe hash.

Durable Streams Offset -1 means start of stream. Array.slice(Number(offset)) is wrong for that sentinel and can silently return only the last native batch, making single-batch tests appear green. Normalize -1 to0 in the controlled fixture and verify multi-batch reload parity. A reopened chat subscriber receives suffix events only, so assert disposal on its pending read rather than waiting for per-reader history replay.

Deno's cached source files append a denoCacheMetadata footer with variable HTTP data. Strip that footer when hashing published source bodies, and validate its URL against deno info's graph URL first. Never publish the raw cache footer.
