# 2026-10-31 — Temporary consumers need a complete recorded graph

A direct OpenTelemetry API bump looked sufficient for an unlocked oRPC peer, but violated the existing SDK's <1.10 peer bounds. Inspect the whole peer cohort before choosing the version change. Publishing a deliberate instrumentation import preserves the bounded peer in the emitted graph.

Copying a workspace lock into a temporary --config is insufficient: metadata, peer IDs, generated Prisma imports, private UI type graphs and nested subprocesses all matter. Let Deno construct the consumer graph, constrain it to recorded versions, validate hashes, then execute frozen. Include runtime-generated/dynamic entrypoints. Keep a known-bad requirement control and verify lock bytes do not change. Never mistake a warm-cache integrity experiment or an ignored backend test for proof.
