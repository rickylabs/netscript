# Caveats for the complementary #2406 issue

Collected during this run (theming/primitives/guidance side) and from sibling harness#751
(CLI/scaffold side, verified by that session on `a833dfa`). Not fixed by #2407 or #2408 unless marked.

## Theme / tokens / primitives (this run)

1. `packages/fresh-ui`: `deno task tokens:build` / `tokens:check` fail under `--lock=deno.lock --frozen`
   (`lru-cache` resolves to 6.x for style-dictionary's `path-scurry`, which imports `{ LRUCache }`). The
   `--no-lock` run is byte-identical to the committed output. No CI job runs `tokens:check`, so DTCG sources and
   `registry/theme/*` can drift silently.
2. Foregrounds are not derived: `--ns-primary-fg` (and the other `*-fg`) must be picked by hand for contrast.
   CSS `contrast-color()` is not baseline yet; a build-time contrast check or documented pairs would help.
3. One theme item (`theme-seed`) ships, so `ui:add --theme <name>` has nothing to select, and there is no
   generator that turns seed values (brand hue, radius, font) into a full token set. Presets exist only as docs (#2408).
4. `/design/tokens` hard-codes the ramp list (`RAMP_ORDER = gray, copper, teal, slate, red, amber` in
   `routes/(design)/design/(_shared)/tokens.ts`), so a brand ramp an app adds (e.g. indigo) never appears there.
5. No page-level shell primitive: every page re-types `ns-shell ns-section ns-stack ns-stack--lg` + `PageHeader`
   compound parts; `PageHeader` has no title/description props, so heading hierarchy is left to each page.
6. The upstream tokens are copied once; existing apps keep the 0.0.8 hard-coded tints until `ui:add theme-seed --force`
   (which also overwrites local token edits). There is no token-only upgrade path.

## CLI / scaffold (from harness#751)

7. The data-bound `ui:add page --island` island renders `<pre>{JSON.stringify(query.data, null, 2)}</pre>`
   (`application/ui/page/web-scaffold.ts` data/query island templates). It has no DataTable/ResponsiveTable and no
   Skeleton/EmptyState/error states, so every generated data screen starts as a raw JSON dump.
8. The `ui:add island` signal template renders a bare `<button>` rather than the `Button` primitive.
9. Query-loader template `…ListInput = { limit, page, sortBy, sortOrder } as const` overflows lineWidth 100 for
   long page names and breaks the generated project's `deno fmt --check`.
10. The "Design" top-bar link always shows, but `routes/(design)/design/_middleware.ts` 404s when MODE != development.
11. `health-view.tsx` wraps in `min-h-screen`; under universal chrome (#2407) `/health` scrolls by the bar height.
12. `routes/_app.tsx` hard-codes the Google Fonts URL (DM Sans/DM Mono): changing type means two hand edits
    (`_app.tsx` link + `--ns-font-*`), with no helper.
13. The top bar has no responsive collapse (`ns-cluster` wraps); with `ui:add page` auto-linking (#2407) it crowds
    phones. App chrome has no SidebarShell variant switch (only `/design` uses `SidebarShell`).
14. Pages generated by a pre-#2407 CLI cannot be removed by `ui:remove page` after the template change (fails closed).
15. Context only (fixed in #2407): `ui:add <registry item>` deleted everything below
    `/* App-specific custom styles below. */` in `assets/styles.css`.

## Docs pipeline (this run)

16. The agent-docs Markdown renderer double-prefixes xref links: `{{ "howto:x" |> xref |> url }}` renders as
    `https://rickylabs.github.io/netscript/netscript/...` in `_site/**/index.md` (HTML is correct, so `check:links`
    passes). Every MCP/offline-docs reader sees broken links on pages that use xref (e.g. `web-layer/fresh-ui` has 5).
17. `{{ comp callout }}` bodies containing inline `<code>` render to agent Markdown as one fragment per text node
    (each `<code>` becomes its own quoted paragraph), which is hard for agents to read.
