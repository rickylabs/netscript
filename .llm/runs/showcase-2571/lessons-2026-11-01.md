# Lessons — 2026-11-01

- Bound a next tracker leaf at a complete user-visible unit. Northwind data/typed
  pages can ship independently while app-owned MCP and durable/authenticated chat
  need separate composition. Keep the parent acceptance open and explicit.
- Existing --from was descriptive but unused. A closed resolver can implement the
  first preset without adding a third overlapping init selector. Normalize before
  prompts and before maintainer package sync; preserve explicit false vs omission.
- A schema variant must update real Prisma, initial Zod, seed and typed projection
  together. Real generation/typechecking catches placeholder-only confidence.
- Demo seeds should upsert stable unique references with update:{}; verify both row
  count and a user edit, not merely rerunning the command without an exception.
- New domain data can expose layout weaknesses even when shared templates previously
  passed. Compare live rows, not backend-absent screens. App-owned table composition
  can improve density while preserving registry APIs and default scaffold hashes.
- A service-ready check must fail with the service stopped; a separate unavailable
  probe must pass. A live native SQLite proof is useful but is not Docker/full-suite
  or published-package proof. Keep those evidence categories separate.
