## Archetype

Archetype 6 controls because the behavioral output is generated CLI scaffold tooling. The small
`@netscript/aspire` contract extension is folded into that larger concern; doctrine independently
classifies `@netscript/aspire` as Archetype 2.

## Current Doctrine Verdict

- `@netscript/cli`: **Restructure** — existing tracked package debt; do not deepen it.
- `@netscript/aspire`: **Keep** — existing `helpers/` naming debt is unrelated and unchanged.

## Goal

Every HTTP-advertising executable resource generated by NetScript registers an Aspire HTTP health
report, unless its config explicitly opts out with `HealthCheckPath: false`.

## Scope

- Remove the pinned-port precondition for `type === 'app'` health probes.
- Add `HealthCheckPath?: string | false` to service/plugin types and Zod schemas.
- Register the same endpoint-named health probe after HTTP endpoint registration for services and plugins.
- Add semantic tests for unpinned defaults, ordering, custom path, and explicit opt-out.

## Non-Scope

- No changes to `tauri`, `desktop`, `task`, background, or tool resources.
- No CLI health-reporting/status consumer.
- No change to Aspire's upstream collapse of zero health reports to `Healthy`.
- No scaffold runtime E2E unless implementation changes scaffold output beyond generated helpers.

## Hidden Scope

- Schema tests must prove the new service/plugin opt-out survives parsing.
- Existing pinned-port tests must remain valid because `Port`/`HostPort` still control endpoint pinning only.

## Locked Decisions

| ID | Decision | Rationale |
| --- | --- | --- |
| D1 | Probe every `type === 'app'`, independent of `Port`/`HostPort`. | Endpoint existence, not host-port pinning, is the readiness precondition. |
| D2 | Include services and plugins. | NetScript service builder exposes `/health`; plugin factory unconditionally composes that builder health surface. |
| D3 | Use `/health` via `RESOURCE_DEFAULTS.AppHealthCheckPath` for all three resource classes. | It matches the evidenced service/plugin route and avoids duplicate literals. |
| D4 | Preserve `HealthCheckPath: false` as the only explicit opt-out and emit the probe after endpoint registration. | Prevents false-unhealthy resources and preserves endpoint resolution order. |
| D5 | Prefer semantic string assertions over whole-output snapshots. | Doctrine AP-18 requires generated-output tests to assert behavior, not giant snapshots. |
