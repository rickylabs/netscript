## Source corrections and native upstream ownership

Current legacy arrays are **6 methods /9 allowed headers /12 exposed headers**, not the old plan's
6/11/14. Preserve the actual arrays byte-for-value; do not invent four protocol headers. Freeze
internal readonly defaults; copy those defaults when native mutable-array types require it, while
passing caller-provided arrays by reference. Compose only the three defaults plus caller fields;
omitted origin stays absent for native environment behavior, credentials/maxAge appear only when
supplied. Legacy wildcard origin remains exclusively in the existing legacy owner until S6.

Ownership follows actual native code: `ServiceBuilderImpl.serve()` runs logging/start hooks and
builds before `startServiceListener`; a failed front bind has no RunningService and no native
shutdown coordinator to call the upstream hook. Therefore the factory must own that failure path.
Once `createStreamsServer` returns, put upstream start and every subsequent front composition/
serve step inside try/catch. Normal successful serve installs `onShutdown: [async () => await
server.stop()]`; native idempotent stop/drain owns that hook. On rejection, await native
`server.stop()` and rethrow the identical original error. Cleanup rejection is deliberately
secondary and caught with a narrow documented primary-error comment, matching evaluated plan4.10.

Pinned `@durable-streams/server`0.3.9 owns the actual upstream store, HTTP server, subscription
manager, pending waits and SSE connections. Its stop cancels waits/subscriptions/SSE, closes HTTP,
then closes file-backed store. No plugin direct store-close, duplicate shutdown coordinator or
private-field patch. Native stop can itself reject (including early listen failure); do not claim
cleanup succeeded in that case. S6 must observe actual old-port release after a front collision,
primary error preservation and normal stop/abort. No such lifecycle runtime proof exists in S4/S5.
