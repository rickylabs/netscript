Upstream: rickylabs/netscript#2406 items 1 and 4 (items 2 and 3 are #752's half; see
`supervisor.md`). Archetype **6 (CLI tooling)** with **SCOPE-frontend** (scaffold output) and
**SCOPE-docs** (published skill). Doctrine verdict for `packages/cli`: existing A6 layering mode;
`kernel/application/ui/*` is function-module style, which new code matches.

## Locked decisions

1. **Chrome is opt-out, not opt-in.** `_layout.tsx` renders the top bar for every page except
   paths under `chromelessRoutePrefixes`, which ships as `[/design]` only. Both branches keep the
   single `<Partial name='page'>` wrapper. *Why:* any page an agent adds is inside the app frame
   without a code edit; `/design` is the one route that owns its own shell.
2. **Navigation is data in an app-owned `navigation.ts`.** It exports `appNavigation`
   (`{ href, label, match: 'exact' | 'prefix' }[]`), `chromelessRoutePrefixes`,
   `isCurrentNavigation()` and `rendersAppChrome()`. `_layout.tsx` maps over it. *Why:* the CLI can
   append to a data list deterministically (same technique as `router.ts`), while the layout's
   markup stays free for humans and agents to restyle.
3. **`ui:add page` links top-level pages by default.** One-segment paths append
   `{ href: appRoutes['<id>'].href(), label, match: 'prefix' }`; nested paths do not.
   `--nav [label]` forces a link (optional label), `--no-nav` suppresses it. An implicit link with
   no `navigation.ts` (apps scaffolded before this change) is skipped with a printed note; an
   explicit `--nav` without it fails with the remedy. Re-runs are idempotent.
4. **`ui:add page` prints next steps** — where chrome, navigation and theme come from — so the CLI
   output itself teaches the frame.
5. **Generated pages start from the house rhythm**: `<main class='ns-shell ns-section ns-stack
   ns-stack--lg'>` + `PageHeader` around the page's layer, for static and data-bound pages alike.
6. **`ui:remove page` reconciles the nav entry** it would have written (matched by route id),
   never failing when the entry or `navigation.ts` is absent.
7. **`styles.css` keeps its custom tail.** `writeStylesAggregator` preserves everything below
   `/* App-specific custom styles below. */` across `ui:add`, so the app-wide theme override
   location #752 documents is durable.
8. **`netscript-build` skill** documents `generate routes`, `ui:remove page`, the chrome/nav
   files and the `--nav`/`--no-nav` flags, and points to MCP `get_doc
   web-layer/how-to/customize-fresh-ui` for theming.

## Gates

- Static: `run-deno-check.ts` / `run-deno-lint.ts` / `run-deno-fmt.ts` on changed CLI files
  (temp no-exclude config method, per prior evaluator acceptance), `deno task quality:scan`,
  `deno task arch:check`.
- Unit: `run-deno-test.ts` on `kernel/application/ui/`, `public/features/ui/`,
  `kernel/templates/app/`.
- Generated carriers: `deno task check:assets-barrel`, `check:publish-assets`.
- Consumer: render the templates and `ui:add page` output, run `deno fmt --check` with the
  generated workspace's fmt options; scaffold a local-source project and `deno check` + render
  `/notes` with the chrome (route check). Full `scaffold.runtime` is the merge-readiness gate in
  CI (Aspire/Docker); recorded **unproven locally** if it cannot run here.
