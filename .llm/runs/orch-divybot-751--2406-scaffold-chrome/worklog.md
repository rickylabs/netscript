## Design

1. **Public surface**
   - Scaffolded app: new `apps/<app>/navigation.ts` (`appNavigation`, `chromelessRoutePrefixes`,
     `isCurrentNavigation`, `rendersAppChrome`, types `NavigationItem`, `NavigationMatch`);
     `routes/_layout.tsx` renders the top bar for every non-chromeless page.
   - CLI: `netscript ui:add page <path> [--nav [label]] [--no-nav]`; output gains a
     `navigation-registration` file line and `Next:` hint lines. `ui:remove page` also prunes the
     page's nav entry.
   - `UI_DATA_SCREEN_FILE_ROLES` gains `navigation-registration`.
2. **Domain vocabulary**
   - *App chrome* — the top bar + nav rendered by `routes/_layout.tsx` around a page.
   - *Chromeless prefix* — a route prefix whose pages render their own chrome.
   - *Navigation entry* — one `appNavigation` item; *navigation registration* — the CLI's
     idempotent append of one entry.
   - *Custom styles tail* — the part of `assets/styles.css` below the app-custom marker.
3. **Ports** — existing `FileSystemPort` only (scaffold reads/writes `navigation.ts`); existing
   `GeneratedSourceFormatterPort` for removal comparison. No new port.
