# Plan

PLAN-EVAL selected: runtime lifecycle and additive public contract decisions. Hard stop before implementation until separate-vendor PASS.

Decisions locked: retain one upstream StreamDB and collections for lifetime; wrap only its public read seam with a session supervisor. Use a native DurableStream instance wrapped at its stream method and first response subscription/closed seam; bound instance methods to their native target. No private SDK access or second dispatcher. Default wrapper owns optional preload/stop/dispose, delegates close and cancels its recovery controller; alternate factory passthrough stays compatible. Add owned reconnect options (maxRetries, initialDelayMs, maxDelayMs); default finite retries and capped exponential backoff. Validate nonnegative integer retries and finite positive delays with max >= initial before I/O. Inner native fetch maxRetries zero avoids multiplying budgets. Empty successful batch marks live and resets outage budget, because server responded at a valid retained offset.

Resume: advance checkpoint only after subscribed batch callback has returned successfully and cancellation has not fired. Every new read session starts at this checkpoint; never clear existing collections or silently replay from origin. Only network transport errors and retryable HTTP missing-stream/rate-limit/server errors recover. Auth, invalid schema/protocol/payload, invalid/expired offset and intentional closed stream fail/finish without retries. A clean nonterminal session close may retry; streamClosed true finishes. Terminal exhaustion rejects the supervised closed promise; startup exhaustion rejects preload. Expose no sensitive diagnostics or new logs. Stop/unsubscribe aborts both active session and backoff and is idempotent. Native subscriber callback failures must not be reclassified as transport errors.

Internal named state: connecting/live/retrying/stopped/failed, attempts and last committed offset; identity remains source URL plus existing collection IDs. Read seam is transport port, abort-aware delay is clock port; default timer only in a named adapter. Delivery follows upstream committed-batch semantics, single consumer and retained offsets. No new UI status hook: safe to defer because optional in requested scope, no branch rework. No full-log replay or stream-recreation policy: fail closed when retained offset is rejected. Owner shared dependency maintenance deferred to separate PR and not a design fork here.
