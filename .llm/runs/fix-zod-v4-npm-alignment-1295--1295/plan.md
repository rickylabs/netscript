## Archetype

The dependency edit crosses existing package/plugin archetypes without changing their source
architecture. The new enforcement lives in repo tooling, so Archetype 6's static, consumer, and
publishability expectations govern the guard while each package retains its existing archetype.

## Current Doctrine Verdict

Existing per-package verdicts remain unchanged. This slice applies wrap-don't-reinvent and the
single-home dependency policy; it does not restructure package surfaces.

## Goal

Resolve workspace and AI/MCP peers onto npm Zod 4, document the two approved hard-v3 parents, and
make any expansion of that boundary a CI-visible failure. Full collapse moved to #1320.

## Scope

- Add `zod: ^4.4.3` once to the root npm catalog.
- Replace 18 member JSR specifiers with `catalog:`.
- Move every source import of `@orpc/zod` to `@orpc/zod/zod4`.
- Regenerate and review `deno.lock`; retain only the documented AG-UI/kvdex v3 boundary.
- Add a dependency guard with negative controls and integrate it into `deps:check`.
- Document the residual boundary and #1320 watch signals.

## Non-Scope

- No Zod API/schema rewrites unless type checking proves an npm-v4 incompatibility.
- No dependency version upgrades beyond relocating Zod 4.4.3; specifically no TanStack 0.43/canary AG-UI move.
- No JSR publication while #1312 blocks it.

## Hidden Scope

- Generated/scaffold templates that intentionally emit npm Zod are checked but are not converted to workspace `catalog:` because generated consumers do not inherit the monorepo catalog.
- Lock peer suffixes throughout the AI/oRPC graph must be reviewed, not accepted as opaque churn.
