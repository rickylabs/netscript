# Plan

## Locked scope and contracts

Resolve #2630 and #2631 together. No merge/publication, no saga transport modifications, no Redis Streams dependency.

1. **Final termination is explicit on every process-owned path.** After drain/cleanup completes or expires, invoke Deno.exit with the computed code on clean, fatal and timed-out paths; never rely on natural event-loop drain. ChildHealthProcessOptions gains hostname (default loopback, explicit override), drainTimeoutMs (35 s total including up to 5 s reserved for cleanup), bounded onShutdown hooks, and exitOnShutdown (default true for process ownership; false for embedded/tests). Preserve the one-second observable fatal-health grace. Exit 0 clean, 1 fatal/cleanup failure, 2 drain timeout. The default work drain is 30 s; cleanupTimeoutMs defaults to min(5 s, one fifth of the total). The total bound includes closing the health listener; the pre-existing one-second fatal-observation grace precedes this bound.
2. Service signal shutdown explicitly invokes Deno.exit with the computed code after drain and resource cleanup, on clean and failed paths symmetrically. It uses the same exit-code vocabulary. Manual stop and external cancellation remain embeddable; an explicit exitOnSignal option lets a host retain process ownership. Shutdown hook failures are nonzero. Hooks are attempted on timeout rather than skipped; a cleanup phase reserved within the existing 30 s total (default min(5 s, one fifth of total)) prevents one hook from hanging process termination. A timed-out work-drain hook cannot prevent remaining resource cleanups from being invoked. Existing LIFO ordering and idempotency remain.
3. Close process-owned shared KV (and its Redis client/subscriber) on executable-role signal shutdown by calling the singleton-aware closeKv(), a no-op when unused. Never use the lazy PluginServiceContext KV wrapper close() for process disposal: it resolves-on-close and is not a disposal path for these roles. Add explicit cleanup callbacks to generated background glue. Generated host bootstrap tracks only DB clients it actually acquired and provides an idempotent disposal callback; never resolve an unused DB merely to close it. Add optional disposal to PluginServiceContext so generated service entrypoints can register owner-provided cleanup. Native caller-owned contexts stay untouched unless their host explicitly supplies disposal. When that callback owns database disposal, ServeOptions.disposeDatabaseOnSignal:false disables automatic raw-builder database disposal to avoid double-disconnecting the same client; default remains true. KV is disposed once by the process edge, not by the generated database callback.
4. Register identity-deduplicated Prisma $disconnect cleanup at the raw service builder withDatabase boundary, inherited by defineService and createPluginService. Run it in the reserved, signal-path-only cleanup phase so the raw-builder S1 subprocess test passes and aliases disconnect exactly once. Remove the redundant preset-only health-client hook. Prisma cleanup covers every acquired client, not only the health-check client. Standard sagas background wiring must dispose its acquired host DB context as well as shared KV. The builder records already-supplied DB client identities; generated composition supplies disposal for separately acquired host DB clients. No cleanup resolves a new database. Manual stop/external cancellation do not invoke process-owned KV/DB disposal; opaque embedded caller resources remain host-owned.
5. OTel's SIGTERM handler retains bounded flush and listener removal but drops Deno.exit entirely. This deliberately changes standalone SDK behavior: embedders without a NetScript runtime compose a runtime or own signal termination themselves. Document this in the S3 telemetry documentation and include it in docs:accuracy scope; the composing runtime owns all exit codes.
