# Component-contract migration lessons

Keep design vocabulary separate from explicitly named runtime compatibility values. Render real implementations before assuming a data-part survives a compound getter: getter defaults must preserve deliberate caller anatomy. Context-only, native and pseudo anatomy need explicit metadata, not fabricated DOM wrappers.

For versioned app-copy migrations, reviewed contextual source edits handle existing dynamic components without a parser dependency. Literal JSX edits need nested attribute-expression traversal and disjoint byte spans; preserve quote delimiters and skip comments, strings and regex literals. Preflight the whole app, format proposed outputs, recheck originals, and retain rollback originals before writing. Replay an actual older source scaffold, including format/type tasks and a second zero-change run.

Visual parity must use identical compiler settings, the correct host theme attributes, each revision's own runtime, identical token bytes and recorded input hashes. A text wrapper with display:contents can hide an axe contrast target without changing pixels; real inline text anatomy preserves measurement. Re-key structural accessibility targets only after reviewing complete scans and preserving every case's rule/impact/count totals. Keep zero-allowance Utility cases at zero.

Retain environment and evaluator failures as failures/unavailability. Docker preflight failure does not prove runtime acceptance; a reviewer API usage limit does not produce an independent verdict. Keep the PR draft when required signoff is absent.

Use real older selector names in migration fixtures; public component names can differ. Compare transformed CSS independently from authored CSS. Keep layout utility aliases at equal specificity, refuse controlled component prop overrides, and recognize delegated wrappers without requiring an ns class string. A source-equivalence check against the registry catches structural copies that compilation alone would miss.
