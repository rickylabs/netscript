# 2026-10-31 — Redis admission and settlement

A claim consumes a delivery attempt when it commits, before the handler sees it. If abort lands in
that gap, dispatch and drain the committed receipt; a blind requeue on its last attempt can send
unseen work to the dead-letter queue. Keep intake cancellation separate from settlement, and test
that last-attempt race against real backends.

A bounded pool must include acknowledgement work in its slots. A replaceable completion signal
avoids repeatedly adding Promise.race listeners to a slow handler or an unresolved abort promise.
Keep the worker's existing per-context heartbeat; the queue should not create infinite renewals.

Measure delayed pickup from the actual persisted eligibility score. State initialized-connection,
capacity, backlog and event-loop assumptions alongside polling bounds. Public factory/environment
proof is stronger than exercising only the adapter constructor, and queue spans cannot establish
native-filesystem-to-feed latency before admission.

Preserve the existing producer-only disconnect ordering and callback grace when adding consumer
drain. A passing focused correction does not substitute for the planned complete queue suite;
independent review should receive observed results, not a promise that tests should pass.

Generated export/prose carriers are part of a public API/docs change. Use native generators and
freshness checks; git-diff-based carrier checks require the generated changes to be committed before
their final clean comparison. Keep that checkpoint explicit, without weakening the gate.
