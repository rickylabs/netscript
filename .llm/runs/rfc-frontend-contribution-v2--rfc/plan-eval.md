## Verdict: CHANGES_REQUESTED

### Executive Summary
Do not freeze W1 contracts or close the Wave-0 issues on this draft. The Fresh 2 mount-order, partial-response, and CSS cascade observations are useful, but the proposed spine changes owner-ratified RFC 0005 contracts, and Probe C does not establish the claimed secret, authorization, or streaming guarantees. A viable `0.0.10` cut remains: preserve the accepted identity and host boundaries, prove one portable loader and one authorized Workers procedure, and move unproved transport and tooling work off the critical path.

### Blockers

- **B1 — The “shared” contract is wire-incompatible with RFC 0005, and the guide’s manifest fails its own probe.** RFC §§1–2, lines 111–133, 163–191, 204–236, and F-1/F-2 at 675–676 replace `{ family, major }` with `{ id, version }`, an envelope of family-validated contributions with a per-item envelope, and host-assigned `installationId`/`mountId` with `packageName#localId`. Two installations of the same package and local contribution therefore get the same proposed key. `rfcs/0005-devtools-contribution.md:932–952,964–986,1013–1044,1074–1081` specifies the opposite: DevTools owns the initial spine, the host assigns mount identity, and sibling envelopes share one pointer. Moreover, `C:240–243,443–469` requires exactly `{ export, framework: 'fresh' }`; the RFC example omits `framework` and adds four unrecognized keys. `C.log:2–3` is green for the old pointer, not the published example. **Fix:** use one canonical wire schema and host-assigned identity, with explicit re-exports or an owner-approved versioned amendment. Validate the verbatim guide example, a mixed-family export, and two installations of one package before freezing W1.

- **B2 — The six state names survive, but ordering, diagnosis, and failure policy do not.** RFC §2, lines 238–258, treats an anchor as a target slot, sorts by `(order, contributionId)`, and defines `window-mismatch` using NetScript semver. In `rfcs/0005-devtools-contribution.md:1209–1227,1237–1251,1262–1272,1344–1351`, the zone is the target; `anchors[]` pins particular contributions *first*, the remainder sort by `(order ?? 0, mountId, id)`, and out-of-range order is a generation error. An unsupported **family major**, a known zone absent from this host, and an unsupported **zone major** have distinct outcomes. DevTools validation failure also must not fail installation; the per-family knob was deferred, not granted to each contributor (`:1395–1409,1419–1424`). **Fix:** adopt the accepted matching and ordering algorithm and host-owned failure policy. Test pinned capacity winners, an unserved zone version, an absent known zone, an unsupported family major, and an invalid DevTools item alongside a valid app item. These are the actual `#1471` gates in `.llm/runs/plan-devtools-contribution--seed/filing/issues/W1-a-contracts-unit.md:54–75`.

- **B3 — The proposed browser-safe secret handle discloses a fingerprint, and the mandatory leak check can miss marked secrets.** RFC §6.1, lines 405–433, and §9.3 line 554 claim protection across SSR and hydration. `C:2189–2206,2496–2512` computes an unkeyed truncated SHA-256 of the stored value, renders it, and **asserts its presence in HTML**. Downstream redaction contracts explicitly forbid browser-visible digests to prevent equality and offline-guessing oracles (`acme` reference redaction contract). Separately, `C:2310–2328` drops schema information for array elements; `C:2332–2375` cannot recognize an ordinary string marked secret by a lost schema and stops inspecting objects that resemble handles. `C:2496–2528` uses hand-embedded JSON and known fixture strings, not Fresh’s island serializer. Thus `C.log:10–11` is not an end-to-end disclosure gate. **Fix:** expose presence only; keep fingerprints server-side. Preserve secret annotations through nested arrays, records, and schema conversion; validate an allowlisted outbound shape at service, gateway, SSR, partial, and hydration boundaries. Exercise real Fresh serialization and a secret nested under a non-sensitive field name.

- **B4 — The gateway proof does not authorize the proposed Workers dogfood.** RFC §§3/6.2, lines 283, 435–445, and 453 name Workers trigger/cancel as examples. `C:1139–1169` uses the real `authContract` but defines `cronsContract` **inside the probe**. Real Workers uses `oc.errors(...)` with empty metadata and declares `getJob` and `triggerJob` without access policy (`packages/plugin-workers-core/src/contracts/v1/workers.contract-definition.ts:72–97,459–487`). `compileProcedures` returns no policy for such a route (`packages/service/src/auth/contract/contract-procedure-index.ts:76–85,206–233`); the probe gateway then denies it even for an authenticated caller (`C:923–955`). It also uses the router’s *matching pattern* as an upstream URL, copies all incoming query parameters, and obtains a service credential from a callback taking no principal or resource (`C:683–689,990–1008,1283–1290`). `C.log:5–7` does substantiate the tested CSRF, method, and redirect denials, not resource-bound delegation. **Fix:** specify the grant as host-approved procedure × owning service × caller/resource policy; use a published server-policy seam and typed parameter binding. Prove one real Workers request succeeds for the authorized resource and fails for another, with no upstream call on denial. Keep the SDK’s client metadata fix separate from server authorization.

- **B5 — Probe C proves neither `eventIterator` delivery nor RFC 0009 revocation fencing.** RFC §§6.3/9.3 and F-4, lines 449–455, 553, 678, say stream endpoints are skipped and iterator support was validated. `C:2133–2151` checks an iterator’s method/path, **expects `compileProcedures` to throw** on a nested stream descriptor, and checks only `typeof` for the chat proxy. The gateway buffers the entire response before returning (`C:1050–1077`). For Durable Streams, the real test server sits behind a **probe-local** proxy: it awaits a Boolean and enqueues data frames and control separately; the test revokes *before* producing the next batch (`C:1598–1613,1813–1826,1870–1895,1983–1996`; `C.log:8–9`). That is valuable resume/withholding evidence, but not a stale-allow race, idle expiry, or pre-drain shutdown test. `rfcs/0009-authorizing-stream-proxy.md:623–631,1494–1547` requires sibling exports, a post-await epoch/expiry fence, and one atomic pull-driven enqueue. Its proposed proxy is not exported by baseline `packages/plugin-streams-core/deno.json:6–14`. **Fix:** keep ordinary HTTP, iterator RPC, and Durable Streams acceptance separate. Defer iterator support or demonstrate first delivery before EOF plus abort/reconnect on a real procedure. Depend on RFC 0009’s implementation for revocable feeds; do not close `#927` on this result.

- **B6 — The containment proof trusts the directory whose containment it must establish.** RFC §2.7, lines 265–268, and §9.3 line 552 claim project-root physical containment. `deriveGeneratedArtifactPath` checks against the resolved `.netscript/generated` directory, not against the trusted project root (`C:345–382`). The sole physical negative case places a symlink **below** that directory (`C:601–613`); `physicalPath` also handles a failed `realPath` as a missing path (`C:331–342`). `C.log:4` therefore does not prove containment of the output root itself, the production alias resolver, or actual writes. `packages/cli/src/kernel/application/ui/registry.ts:310–317` and `packages/cli/src/public/features/generate/plugins/installed-runtime-registry-generator.ts:384–400` confirm the baseline defects. **Fix:** anchor every expanded/staged destination to a trusted real project or package root; fail closed on unresolved symlinks, and confine contributor output to host-owned staging. Retain RFC 0005’s real write-path, subprocess-argv, and permission-denial gates (`rfcs/0005-devtools-contribution.md:2901–2907,2921–2922,3107–3116`).

- **B7 — Fresh 3/GPUIX portability is a plausible design, not a property of the declared route ABI.** RFC lines 81–105, 278–281, 333–334, and 391–399 promise an unchanged portable loader while showing one module importing Fresh `page` and `PageProps`. The successful P2c fixture imports Fresh 2 `Context`, `PageProps`, and `RouteConfig`, mutates Fresh state, and reads `isPartial` (`P/probe-a-fixtures/plugin-route-pure-data.tsx:1–25,36–47`). `normalizeFreshRouteModule` checks export names and function shapes, then casts and returns the handler; it does not enforce purity or prevent `ctx.render()` (`A:415–450,467–485,507–512`; `A.log:34–39`). The GPUIX PoC expects a different `RouteContext`, `handler`, and `page` interface (`.llm/runs/rfc-gpuix-desktop--rfc/poc/app/client/router.ts:14–30`), and RFC 0007 explicitly rules out unchanged Fresh HTML/CSS pages (`rfcs/0007-gpuix-native-desktop-renderer.md:96–106`). **Fix:** give the data loader a separately importable, framework-free input/result type; keep web views, CSS, and `isPartial` in adapter entrypoints. Type-check and run the *same* loader through Fresh 2 and the native PoC without resolving the Fresh view. Describe Fresh 3 as a migration target until exercised.

- **B8 — The Wave-0 closure and “acyclic” claims exceed the acceptance evidence.** RFC §§10–11, lines 564–567, 581–585, 591–598, 611–618, mark `#925/#1469/#1470` satisfied. Probe B uses localhost HTTP aliases and one Fresh app root; its Vite fixture explicitly disables page-module route binding (`B:1043–1056,1081–1093`; `P/probe-b-fixture/apps/web/vite.config.ts:83–101`; `B.log:224–247,267–272`). It does not answer whether **two route roots in one process** contend for `.generated/`, nor establish the clean-cache published-JSR matrix. Both are stated gates (`rfcs/0005-devtools-contribution.md:4480–4487,4506–4508`; `.llm/runs/plan-frontend-contrib--seed/plan.md:55–65`). W3a→W3b removes the **code import** cycle, but [#940’s acceptance](https://github.com/rickylabs/netscript/issues/940) still requires Workers green in CI and [#933](https://github.com/rickylabs/netscript/issues/933) requires the suite green. **Fix:** record partial proofs as partial; explicitly move the Workers acceptance receipt to W3b or leave `#940` open through W3b. Give W3a an independent fixture and a failing-budget control. Do not authorize issue closure by RFC acceptance.

### Material Improvements

- **M1 — Share generator logic, not a production import graph or mutable diagnosis file.** RFC lines 131–137, 194–196, 243–258, 503–511 specify one literal-loader registry and put request-time failures in generated diagnosis. RFC 0005 requires both structural absence of DevTools from production **and** independent runtime refusal (`rfcs/0005-devtools-contribution.md:752–769,2924`), plus staged type-check, rollback, deterministic empty output, and byte-identical regeneration (`:3083–3093`). Emit separate app/DevTools projections from one canonical input; keep runtime quarantine observations outside generated files. Add crash, last-plugin removal, production-artifact absence, and two-app targeting tests. `resolvePluginAppReferences` can return multiple consumers, while the RFC registry example has one `targetApp` (`packages/cli/src/public/features/plugins/install/plugin-app-references.ts:17–29`; RFC lines 163–166).

- **M2 — State exactly what survives a plugin failure.** RFC lines 330–356 overstate the tested facade: `GuardedPluginApp` subclasses `App`, overrides *all* `onError`, and does not override `fsRoutes` (`A:327–370`; `A.log:32–33`). The resolver failure preserves a sibling, but a synchronous JSX throw fails the page and a nested async throw can leave empty output with an unhandled rejection (`A.log:40–56`). The seed explicitly distinguished these cases (`.llm/runs/plan-frontend-contrib--seed/design/canonical/04-host-runtime.md:123–130`). Specify an allowlisted facade, host-owned scoped error registration, and a bounded resolver deadline. Test the post-hydration boundary separately; do not promise per-zone SSR render isolation from a data-phase catch.

- **M3 — Make entity zones and descriptors typed at the host boundary.** RFC lines 51–77, 278–280, 303–318 name schemas, a zone, and `DescriptorTabSpec`, but do not show how that zone constrains component context, tab input/output, or entity authorization. RFC 0005 provides an implementable precedent: `DevToolsZoneContextMap` and `DevToolsPanelContribution<Z>` (`rfcs/0005-devtools-contribution.md:1544–1582`). A downstream consumer (`acme`) keeps its versioned domain validation authoritative and exports JSON Schema as a form description; its generic plugin inspector is a design assumption, not runtime proof. Define the JSON wire projection, typed zone-to-context map, and per-kind renderer registration. Enforce `fixedByPlugin`, secret, override, and entity access rules on writes; a widget hint or `match` predicate is not authorization. This preserves AP-3/AP-24 without making the neutral core a renderer.

- **M4 — Use the shipped widget write protocol and keep catalog uncertainty explicit.** RFC lines 317, 426–433 claim one-to-one mapping. `#2670` has merged on inspected `origin/main`: `resolveSecretFieldSubmission` returns `replace`, `keep`, `clear`, `unset`, or `invalid`, and rejects conflicting action/value pairs (`packages/fresh-ui/src/runtime/secret-field/secret-field.utils.ts:77–96,112–163`). `C:2378–2415` additionally accepts raw strings and treats raw `null` as clear; `C.log:11` did not test this adapter. Map the full result explicitly, preserve absence, and require intentional deletion. Likewise, RFC lines 464–497 put runtime health, compatibility, and update availability in one status and key a *plugin* catalog by contribution. Downstream consoles (`acme`) distinguish linked version, unobserved running version, health, quarantine, update, and doctor freshness. Keep these independent so an installed plugin with no UI, or an unhealthy plugin with an update, remains representable.

- **M5 — Test a real shell transition and delivery of package-owned CSS.** RFC lines 337–344, 369–381 correctly identify redundant chrome and normal layer precedence. `A.log:9–10,22–23` measures response markers; `B.log:141–171,191–199` measures fixture CSS and computed color. The mounted route’s successful CSS URL, however, points to a file already placed in the **host’s** `static/` (`P/probe-b-fixture/packages/local-plugin/route-explicit.tsx:1–7`; `P/probe-b-fixture/apps/web/static/mounted-explicit.css:1–13`). The scaffold also imports design and workspace CSS globally (`packages/cli/src/kernel/assets/app/client.ts.template:1–4`), and its active navigation and breadcrumb are computed outside the proposed persistent partial (`packages/cli/src/kernel/assets/app/routes/_layout.tsx.template:39–64,81–86`). Specify asset ownership, base-path URLs, plugin/portal scoping, and shell-state refresh. Gate full→partial→back navigation, stylesheet arrival before paint, active breadcrumb, and cross-tab/system theme changes (beyond retaining `ns-theme`).

- **M6 — Preserve the work hidden by “absorbed.”** RFC lines 566–567, 597, 619–623 absorb `#427` into an app zone and `#432` into a CLI verb. The DevTools filing record keeps `#427` as its panel implementation and `#432` as a dashboard caller of the shared scaffolder (`.llm/runs/plan-devtools-contribution--seed/filing/FILING-LOG.md:32–36`; `design/T9-supersession/supersession-map.md:112–117` in that same run). The seed also requires app-owned starter drift reporting, typed route-ref merging, and install→render→hydrate→remove (`.llm/runs/plan-frontend-contrib--seed/design/canonical/05-scaffolding-and-cli.md:23–37,43–58,79–93`). Preserve those gates or assign explicit successors. Separate `#936/#939` from the automation critical path: `rfcs/0002-runtime-versioned-automation.md:513–522,678–679` expressly excludes later DX slices and makes A7 a gate only for A8’s cockpit journeys.

### Owner Forks (F-1 to F-5) Assessment

- **F-1 — Amend the choices.** A separate small contract package is reasonable; neither listed choice preserves the ratified `packages/devtools-core` ownership. Prefer that owner plus re-exports, or explicitly reopen the decision with a migration and compatibility gate. RFC line 675; `rfcs/0005-devtools-contribution.md:939–956,4536–4545`.
- **F-2 — Prefer one pointer with sibling envelopes.** Neither “keep two keys” nor “introduce `ui`” is the accepted default. If two keys are approved, specify mixed-manifest conflict handling and exactly one effective declaration. RFC line 676; `rfcs/0005-devtools-contribution.md:1074–1081`; `C.log:2–3`.
- **F-3 — Endorse `x-ns-ui` with a host overlay adapter (owner subsequently chose Option B strict `x-ns-ui` only).** Define field-level precedence and forbid an overlay from weakening redaction or write restrictions. The whole-object fallback at RFC line 316 does not define mixed-hint behavior; the consumer’s schema remains authoritative (`acme` reference schema).
- **F-4 — Choose B, HTTP-only, for this cut.** Promote iterators after one real procedure delivers incrementally, aborts, and reconnects under the intended authorization policy. RFC line 678 cites a test that only compiles metadata (`C:2133–2151`; `C.log:9`).
- **F-5 — Endorse owner-led reassignment, not automatic placement in `0.0.10`.** All six named issues were open in `Frontend Contribution` on read-only inspection; `#2568` had no labels, and `#2531` had `area:fresh-ui` but not `epic:design-system`. Use each issue’s owning theme unless release scope is agreed. RFC lines 573, 624, 679.
