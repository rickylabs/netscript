## Independent red-first probes on current main

### #1262 — model schema, placebo seed

The generated schema template contains a model, but the generated seed only runs `SELECT 1` and
prints success. Probe exit: **1 (red)**.

```json
{
  "hasModel": true,
  "writesRows": false,
  "placebo": true,
  "successBanner": true
}
```

This directly reproduces the filed defect. `DatabaseScaffolder` always renders a concrete model name
(default `ExampleRecord`), while `database/seed.ts.template` never uses it.

### #1263 — missing generated CRUD rows become undefined 500s

An executable probe used the current generated router behavior with the live NetScript contract and
OpenAPI handler stack. Probe exit: **1 (red)**.

```text
GET    /api/users/999 -> 500 {"defined":false,"code":"INTERNAL_SERVER_ERROR","status":500,"message":"User 999 not found"}
PATCH  /api/users/999 -> 500 {"defined":false,"code":"P2025","status":500,"message":"Record not found"}
DELETE /api/users/999 -> 500 {"defined":false,"code":"P2025","status":500,"message":"Record not found"}
```

The generated get-by-id handler throws `Error`; generated update/delete allow Prisma `P2025` to
escape. Neither is translated into the contract's defined `NOT_FOUND` response.

### #1263 — OpenAPI 404 projection filed symptom cannot be reproduced

The current `createCrudContract` composes `baseContract`, whose common error map already projects a
404 for every CRUD operation. Probe exit: **0 (green)**.

```text
get    200,401,403,404,422,429,503
patch  200,401,403,404,422,429,503
delete 200,401,403,404,422,429,503
```

Approved fallback: reproduction is impossible at the frozen SHA because current main already
contains the projection. The implementation must preserve it with a scaffold-level regression
assertion; it must not manufacture a redundant contract change.

## Code and contract findings

- `database/seed.ts.template` imports the generated database facade, obtains a client, performs
  `$queryRaw\`SELECT 1\``, and prints a misleading success banner.
- `schema.prisma.template` renders one CRUD model with `id`, `name`, `createdAt`, and `updatedAt`.
- `v1.ts.template` has the Prisma-backed handlers. The repository-standard domain translation is
  `notFound({ errors, path, resourceId })` from `@netscript/contracts`.
- `v1.memory.ts.template` has a matching generic missing-row branch and should stay behaviorally
  aligned.
- The template engine supports substitutions and pipes, not conditional sections.
- `generate-engine-mod.ts` currently injects the entire connection-helper asset for every engine.
- `generate-prisma-config.ts` renders a single template containing every provider parser.
- Generated assets are embedded into `embedded.generated.ts`; the repo-native `gen:assets-barrel`
  task must refresh that mirror and `check:assets-barrel` must verify it.
- The existing runtime verifier `verify-live-db-endpoint.ts` already owns the live database service
  path. Extending it avoids creating another gate in an over-cap directory with open architecture
  debt.

## Doctrine and archetype classification

- Selected profile: **Archetype 6 — CLI/tooling**.
- Public surface: generated consumer workspaces and runtime semantics, not new CLI exports.
- Contract-first seam: generated seed behavior, generated defined-error behavior, and per-provider
  generated source content.
- The planned implementation wraps Prisma and existing NetScript contract primitives; it does not
  introduce a parallel ORM/error/parser abstraction.
- Existing debt in the large scaffold-runtime gate directory must not be deepened. The plan extends
  the existing live DB verifier instead of adding a sibling gate.
- No new architecture debt is expected if the frozen boundary is amended narrowly. Any broader
  refactor is deferred.

## Public/JSR surface inspection

- `deno doc packages/cli/mod.ts` succeeds and shows the existing exports (`.`, `./scaffolding`,
  `./testing`). No public export change is planned.
- The publishable CLI includes `src/**/*.ts` and `src/**/*.template`; E2E sources/tests are not
  published.
- Internal `@netscript/*` pins remain exact. No dependency change is planned.
- Material publish risks are stale embedded template assets, runtime filesystem/import-meta reads,
  and isolated-declaration failures. These are covered by asset freshness, JSR audit, doc lint, and
  publish dry-run gates.

## Research conclusion

This leaf is not mechanical. It has material choices around model-aware seed generation, empty
schemas, race-safe Prisma error translation, provider-specific helper emission, and consolidation of
acceptance into one runtime verdict. `PLAN-EVAL: N/A` is prohibited. A separate PLAN-EVAL is
mandatory after the boundary gaps in `drift.md` are resolved.
