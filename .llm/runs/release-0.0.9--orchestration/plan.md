## CI flow (PLAN-EVAL 1)
CI schedules no jobs on draft PRs, and e2e-cli runs only with the `e2e-cli-gate` (or `ci:full`) label. Leaves open a draft early, mark it ready once their IMPL-EVAL is clean so the required checks run, and re-run the final IMPL-EVAL at the final head. The coordinator arms `e2e-cli-gate` on one PR at a time (the single global expensive gate, as in 0.0.8) when a leaf's READY says runtime E2E is required.

## Merge gate (per PR)
READY on the issue · IMPL-EVAL `VERDICT: MERGE <sha>` from an opposite-family session at the exact head · CI fully green at that head (latest run per check; a READY may report runtime E2E pending, but merge waits for the successful e2e-cli verdict at the evaluated head) · review threads answered · issue Acceptance evidenced · diff audit (no new lint ignores / unsafe casts outside `.llm/runs/**`; docs-lane PRs touch no `packages/**`/`plugins/**` except canonical generated documentation carriers regenerated by their generator tasks). Squash-merge with `--match-head-commit <sha>`. Then close the issue with the evidence comment when every box is met.
