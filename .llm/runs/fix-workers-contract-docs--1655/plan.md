# Public workers graph repair — design review

Archetype 5 connector over Archetype 3 core; public types only, no runtime behavior changes. Goal remains every #1655 acceptance item, including zero full-export doc diagnostics, preserved complete exports, exact real oRPC inference/capabilities, green publication/tests, and closing the two corresponding debt entries only after proof.

Proposed source direction: publish the complete precise owned route/schema type closure under deliberate workers contract vocabulary, then bind the context-capable implementer without a private named upstream reference. Preserve all existing symbol identities and consumer capabilities. Use the upstream API, never fork a parallel router or schema implementation. Public schema/route types must have documentation; no @internal hiding, suppressions, erasing casts, broad unknown validators, skipped targets or blanket vendor re-exports.

Must resolve at PLAN-EVAL: a concrete visibility-safe representation of the upstream implementer preserving the whole API. Local alias/interface/import-query variations demonstrably fail; directly publishing the graph exposes a transitive upstream frontier. Determine whether a bounded source design exists within these invariants, or whether the zero-native-doc requirement needs an owner decision under the already-sanctioned upstream exception. No acceptance change is authorized and no implementation starts before a viable plan passes.

Slices once resolved: (1) bootstrap/baseline/design; (2) exact public graph + strengthened consumer controls; (3) documentation carriers and both debt closures only after all-export zero proof; (4) independent exact-head evaluation and CI. Fewer than 30 files. Gates: structured scoped check/test/lint/fmt; all workers/core package and plugin tests and public consumers; plugin/core full-export doclint with per-target comparison; native publish dry-runs; quality:gate; JSR audits and generated carrier freshness. Coordinator owns expensive merge-readiness scheduling.

Deferred: runtime fixes, schema semantics, dependency/version changes, issue acceptance edits and any consumer migration.
