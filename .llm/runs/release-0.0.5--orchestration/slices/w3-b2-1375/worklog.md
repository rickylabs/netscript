## Design

### Public surface

- Existing commands remain `agent init --with-docs` and `agent mcp --docs-root`; no command name,
  option name, or package export-map key changes.
- `resolveDocsRoot` preserves its synchronous call signature and adds project probing after explicit
  flag/environment resolution.
- `TOOL_OUTPUT_SCHEMAS.list_docs` and the live `list_docs` result add
  `corpus: { kind, root, documentCount }`; existing `count` and `docs` remain.

### Domain vocabulary

- `DocsCorpusKind` — finite values `filesystem | embedded`.
- `DocsCorpusMetadata` — selected kind, resolved root or `null`, and total indexed document count.
- `EmbeddedDocsProvenance` — schema/framework/source/path/hash/byte/count evidence for generated
  fallback prose.
- `InstalledDocsRoot` — `<projectRoot>/.netscript/docs` only after successful generation.

### Ports

- Existing `DocsCorpusPort` remains unchanged.
- Existing `AgentDocsGenerator` and `AgentInitFileSystem` remain the installer seams.
- No new public port. Corpus selection metadata is injected into the docs-flow composition rather
  than imposed on corpus adapters.

### Constants

- `DOCS_CORPUS_KINDS = ['filesystem', 'embedded']` with a derived union where a type is needed.
- `MCP_EMBEDDED_DOC_PATHS` — the five locked release-doc paths from plan LD-5.
- `MCP_EMBEDDED_DOCS_MAX_BYTES = 262_144` (exactly 256 KiB).
- Generated provenance values are typed constants, not scattered literals.

### Generated outputs

- `packages/mcp/src/publish-assets.generated.ts` carries the MCP version, README, selected prose
  strings, and provenance. It remains generated by `.llm/tools/generate-publish-assets.ts` and is
  covered by `check:publish-assets`.

### Adapters and effects

- Filesystem probing stays in `packages/mcp/src/infrastructure/filesystem-docs-corpus.ts` and uses
  the same public-path/parser policy as serving.
- Generated fallback validation stays in an MCP infrastructure adapter.
- Host JSON writes stay in the existing CLI agent-init use case; process spawning stays in the
  real CLI stdio test edge.

### Permissions

- No permission expansion. The public binary already grants `-A`; standalone MCP continues to need
  read/env/net/run as documented. Probe uses the already-required read permission.

### Semantic test strategy

- RED must fail on absent docs-root args, missing probe/metadata, absent generated provenance, and a
  real `search_docs` result that cannot find an installed-only phrase.
- GREEN requires exact config fields plus actual JSON-RPC tool results. No giant generated-string
  snapshots.
- Negative paths distinguish explicit invalid roots (structured error) from empty/absent probe
  roots (observable embedded fallback).
