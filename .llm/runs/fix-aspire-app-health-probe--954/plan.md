## Archetype

**Archetype 6 (CLI / Tooling).** The change lives in `packages/cli` — the Aspire helper generators
under `src/kernel/templates/aspire/**` and the CLI's own E2E suite under `e2e/`. A single constant
and one optional schema field are added to `@netscript/aspire` (Archetype 2), which the generators
already read; that package's shape is unchanged, so the run is not split across two archetypes
(`archetypes/README.md`: fold the smaller concern inside the larger).

**Scope overlay: service** — this is Aspire resource wiring, and it changes runtime health
semantics for a generated resource.

## Axioms in Play

| Axiom | Why it matters                                                                                                |
| ----- | ------------------------------------------------------------------------------------------------------------- |
| `A2`  | The generated AppHost's health contract is a public behaviour of the scaffold; it must be declared, not implied. |
| `A5`  | Wrap upstream rather than reinvent — use Aspire's own `withHttpHealthCheck`, not a bespoke poller.               |
| `A8`  | Finite domain values (the default probe path) become constants, not string literals in a generator.              |
| `A13` | A gate must prove the behaviour it claims. `aspire wait` claiming healthy without an HTTP probe is a false gate. |

## Goal

`aspire wait <app>` reports the generated Fresh app healthy **only when the app can server-render**.
A generated app whose SSR pipeline is broken (e.g. #953's unresolved `jsr:` specifier) shows
`Unhealthy` on the dashboard and blocks `aspire wait`, instead of showing green while every request
returns 500.

## Scope

- `packages/aspire/constants.ts` — add `RESOURCE_DEFAULTS.AppHealthCheckPath = '/health'`.
- `packages/aspire/config.ts` — add optional `AppEntry.HealthCheckPath` (`string | false`).
- `packages/cli/src/kernel/templates/aspire/helpers/register/generate-register-apps.ts` — emit
  `withHttpHealthCheck({ path, endpointName })` for `app`-type entries that expose a port.
- `packages/cli/e2e/**` — extend `scaffold.runtime` with a wait on the app resource and an HTTP
  gate that fetches the app's **home page** and asserts a 2xx HTML response.
- Generator unit tests + a route-template test that pins the SSR default of `/health`.

## Non-Scope

- **The SSR failure itself (#953).** Not fixed here; it is the reproduction vehicle, not the defect.
- **Services, plugins, background processors.** They have the same missing-probe gap, but first-party
  plugin health paths differ (`/health`, `/health/live`, `/health/ready` — research finding 10), so a
  defaulted path would be wrong for several of them and would newly gate `aspire wait` on those
  resources without a verified path. Needs its own issue with per-resource declared paths.
- **`tauri` / `desktop` / `task` app types.** They have no HTTP contract; `desktop` is not even given
  an endpoint by the generator.
- **The `@netscript/cli` Archetype-6 restructure.** Doctrine debt, unrelated to this defect.

## Hidden Scope

- The Aspire docs show `withHttpHealthCheck('/health')`. The **generated 13.4.6 TS SDK takes an
  options object**. Following the docs would emit a call that fails at AppHost start. Verified
  against a real `aspire restore` (research finding 3–4).
- The probe must name `endpointName: 'http'` explicitly: the generator binds the app endpoint via
  `withHttpEndpoint({ port, env: 'PORT' })`, whose endpoint name is `http`
  (`RESOURCE_DEFAULTS.HttpEndpointName`).
- Adding a probe changes `aspire wait <app>` from "returns as soon as the process spawns" to
  "returns when the app renders". Any consumer that waits on an app resource now genuinely waits.
- `.helpers/*.mts` are regenerated by `netscript generate`; existing projects pick the probe up on
  the next generate, not on upgrade alone.

## Locked Decisions

| ID   | Decision                                                                                                              | Rationale                                                                                                                            |
| ---- | --------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `D1` | Emit `await <id>.withHttpHealthCheck({ path, endpointName: 'http' })` for `app`-type entries with a `Port`.            | Directly removes the "no health check ⇒ Running counts as Healthy" fallback that is the root cause.                                    |
| `D2` | Probe the app's own SSR `/health` route rather than a socket check or the home page.                                   | It is already scaffolded, it renders through the Fresh app shell, and Aspire's probe takes its SSR branch — "a minimal SSR route", per the issue's suggested direction. Probing `/` would false-negative on any auth-gated or redirecting home page. |
| `D3` | Path is per-app configurable via `AppEntry.HealthCheckPath`; `false` opts out, omitted means `/health`.                | An app that deleted or moved its health route must be able to say so without losing the probe entirely, and existing configs must keep parsing. |
| `D4` | The default path is a constant in `@netscript/aspire` `RESOURCE_DEFAULTS`, beside `HttpEndpointName`.                  | The generators already import `RESOURCE_DEFAULTS`; a finite domain value does not belong inline in a template string (A8).             |
| `D5` | Regression guard extends `scaffold.runtime` with `runtime.wait.dashboard` **and** `behavior.app-home`.                 | The wait proves the probe is wired; the home-page fetch proves the issue's stated expected behaviour ("a resource reported healthy serves its home page") and is the assertion the suite was missing entirely. |
| `D6` | The `behavior.app-home` gate asserts a 2xx **and** that the body is HTML, with bounded retries.                        | A 500 body would also be `text/html`; asserting only the content type would reproduce the same class of false-green.                   |

## Open-Decision Sweep

| Decision                                     | Status               | Notes                                                                                                     |
| -------------------------------------------- | -------------------- | ---------------------------------------------------------------------------------------------------------- |
| Options-object vs string arg for the SDK call | **resolved now**     | Options object — verified against generated SDK. Deferring would ship a broken AppHost.                     |
| Probe target (`/health` vs `/`)               | **resolved now**     | `/health` (D2). Changing later would churn both generator and E2E.                                          |
| Opt-out mechanism                             | **resolved now**     | `HealthCheckPath: false` (D3). Adding it later would be a schema break for anyone who had to disable it.    |
| Services / plugins probes                     | safe to defer        | Separate issue; per-resource declared paths, not a default.                                                 |
| `statusCode` override in the probe options    | safe to defer        | Aspire defaults to 200; no scaffolded app returns anything else on `/health`.                               |

## Risk Register

| Risk                                                                                                    | Mitigation                                                                                                                                     |
| --------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `withHttpHealthCheck` absent from a user's restored SDK → AppHost throws at start.                        | Verified present on `ExecutableResource` in the pinned SDK (`SCAFFOLD_VERSIONS.ASPIRE_SDK = 13.4.6`), which the scaffold writes into `aspire.config.json`. No NuGet integration package is required — it is core `Aspire.Hosting`. |
| An existing project whose app has no `/health` route now shows `Unhealthy`.                               | `HealthCheckPath: false` opts out; the scaffold has always written `routes/health.tsx`. Called out in the PR body as an intended behaviour change. |
| New E2E gates are flaky (Vite dev server is slow to first render).                                        | The wait gate uses `aspire wait --status healthy` with an explicit generous timeout; the HTTP gate retries with backoff before failing.           |
| E2E suite cannot be executed in this environment (no docker/DB), so the new gates are unproven end-to-end. | Registration is covered by the suite-registry unit test; the PR states plainly that `scaffold.runtime` was not executed here and needs the OpenHands run. |
| Regenerating `.helpers` churns unrelated generated output in user projects.                               | The change is additive to one emitted block; generator snapshot tests pin the surrounding output.                                                 |
