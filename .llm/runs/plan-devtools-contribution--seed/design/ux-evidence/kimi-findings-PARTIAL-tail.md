**Why it matters:** Stale run-state is the single most dangerous lie a debugging tool can tell — the developer chases a failure that already recovered. The RFC names this exact false-done mode as its motivation and then leaves it to per-surface luck.
**Proposed direction:** Add a shared freshness contract: every live-fed panel renders last-observed-at, and a feed drop flips the panel to a labelled stale state (data + age + reconnecting), generalizing the Workers row. Add one sentence defining row-level partial failure (bad row renders inline-error, table survives) so surfaces stop improvising it.

### [SEVERITY: major] `DevToolsUiNode` cannot express the two things the RFC itself mandates: code and payloads
**Anchor:** §7, lines 1490–1497 (the six-node vocabulary: `stack | text | keyValue | table | badge | link`), against §11.1 line 2696 ("renders its CLI-equivalent line (`netscript …` CodeBlock)") and lines 2701–2702 ("primitive-grouped causal chain **with payloads at seams**").
**Finding:** There is no `code`/preformatted node and no structured-JSON node. The first realistic panel a plugin author cannot express: **"show the input payload and error of the failed job"** — the single most common debugging artifact — nor a cron expression, a SQL statement, a diff, or a migration preview. The host can render CodeBlocks in its own chrome (empty states, AC-2 mutations), but a *contributed* panel cannot, so the moment a plugin's diagnostic content is a command or a payload, the vocabulary is exhausted. Secondary gap: every value in the system is a `string` — no relative-time node for a product whose primary data is times (firings, deliveries, drift, staleness), and `table` rows are `readonly string[]` with no numeric alignment, so the density/scan-ability the surface lives on is under-served. Near-duplicate in the other direction: `badge` (tone ok/warn/error) versus `text` (tone default/muted/danger) overlap; if a `code` node and emphasis are added, `badge` is the fold candidate.
**Why it matters:** Payloads and commands are the content of debugging. A contribution vocabulary that can render labels and statuses but not the artifact under inspection caps every panel at "metadata about the problem," pushing real inspection back to the terminal — which is fine, but then the panel's honest job is just the deep-link, and the RFC should say so.
**Proposed direction:** Add `{ kind: 'code'; text: string; lang?: 'shell' | 'json' | 'sql' | 'cron' }` and `{ kind: 'time'; at: string; format: 'relative' | 'absolute' }`; give `table` a per-column `align?: 'left' | 'right'`. Record the payload-inspector as the worked example proving the ceiling.

### [SEVERITY: major] The contributor path is blocked at step 0, and the RFC doesn't say when it unblocks
**Anchor:** §7, lines 1666–1672: the manifest "ends in **`.strict()`** … an older CLI does **not** ignore a new top-level block — it fails manifest parsing outright and takes the whole plugin down. A schema-evolution slice … sequences **before** any pointer lands."
**Finding:** Walk the plugin author's path from the RFC alone: write `render` returning `DevToolsUiNode` (§7 contract — clear), pick a zone (blocked — finding 1), declare the contribution in the manifest (blocked — `.strict()` means the pointer block doesn't parse on any shipped CLI), get it emitted into the registry (§5 lines 629–631 say emission lives in `packages/cli`, but no sentence tells the author what they run or edit), see it in the host (§10's no-watch-loop verdict means a regeneration step the §7 story never mentions). The RFC records the blocker honestly as drift D-6 but never converts it into a sequenced "you can ship a panel when X, Y, Z land" line the author can plan against.
**Why it matters:** The difference between "documented blocker" and "usable story" is a dependency-ordered sentence. Without it, every plugin author's first attempt ends in a manifest parse failure that takes their whole plugin down — the worst possible first-run experience for the contribution model this RFC exists to create.
**Proposed direction:** Add a short "contributor path" subsection to §7: ordered steps (schema-evolution slice → manifest pointer → emission command → zone registration → regeneration), each naming its tracking issue; state the regeneration requirement inline where the author will hit it.

### [SEVERITY: minor] "Six states" is seven; the `unauthorized` arm conflates two different user experiences
**Anchor:** §11.7 line 2945 ("a surface ships only with **all six states** specified") versus the 7-arm `PanelState` at lines 2952–2959 (loading, empty, ready, degraded, incompatible, unauthorized, failure); and line 2970, where `unauthorized` covers both (a) an *outbound* Aspire link that "will prompt for dashboard token" and (b) a *panel* that cannot read its data.
**Finding:** The count drift is trivial; the conflation is not. Case (a) is a link annotation — the panel is fine, the destination will ask for a token. Case (b) is a genuinely blocked panel. Rendering both through one state arm invites a panel to show a full "unauthorized" blocked card when all that is true is "the out-link will prompt."
**Proposed direction:** Fix the count; split (a) into a property of the `DeepLink` value (the helper already models `note: 'will-prompt-for-token'`, line 2915 — the state matrix should defer to it) and reserve `unauthorized` for case (b).

### [SEVERITY: minor] A permanently-empty top-level nav slot, and a journey view with no front door
**Anchor:** §11.3 lines 2837–2838 ("`/automation/` exists from day one as a staged placeholder") and line 2798 (`<base>/flows/:correlationId` — no `/flows/` index).
**Finding:** `/automation/` will render its "awaiting runtime-automation contracts" card for an unbounded period while occupying one of seven primary nav slots — a visible dead end that trains developers to distrust the nav. Meanwhile `/flows/` has no index at all: the journey view is reachable only by inbound link from a runtime entity, so a developer holding a correlation id from a log line has nowhere to paste it.
**Proposed direction:** Keep the `/automation/` URL and placeholder card (the boundary documentation is valuable) but hide the nav entry until the surface is live. Add a minimal `/flows/` index — recent correlation ids plus a paste-an-id field.

### [SEVERITY: minor] Surfaces are named from the system's side, and the pre-host journey ends in connection-refused
**Anchor:** §11.3 lines 2803–2804 ("`<base>/generated/` Generated-artifact state") and §5 line 848 (H-F5: "a silently moved DevTools port breaks the deep-links other tools print") with line 844 (H-F1: explicit `netscript devtools` launch).
**Finding:** Two small journey breaks. (a) "Generated" and "Contracts" name how the framework is built, not what the developer wants — the user's questions are "is my generated code stale?" and "which routes are contract-bound?"; `/generated/` in particular will be misread as "things I generated." (b) The RFC acknowledges other tools print DevTools deep-links, but models no experience for following one when the host isn't running (H-F1 makes launch explicit and opt-in) — the answer today is a browser connection-refused, and H-F5's fail-loud port collision names no remedy (change `NETSCRIPT_DEVTOOLS_PORT` is never said).
**Proposed direction:** Rename surfaces by the developer's question (e.g. "Drift" or "Freshness" for `/generated/`); state in §5 that `netscript devtools` prints the URL, that printed deep-links are documented as requiring a running host, and that the port-collision error names the env var remedy.

---

## Strongest UX decision

The strongest call in this design is the **honest-degradation posture woven through every layer**: a deep-link is "a value with a reason" (line 2913) so an unresolvable Aspire base renders a disabled affordance naming the missing setting instead of a broken href; a panel with no contract surface renders a labelled degraded state *with its citation* instead of a silently empty list; an incompatible contribution renders a loud card instead of being dropped; and a throwing plugin render produces a visible error card because "a silently missing panel is a debugging trap" (line 1509). This is a coherent, argued inversion of every surveyed system's quiet-failure default, and it is exactly right for a tool whose operator is the author — the worst thing a debugging surface can do is lie by omission. Whatever gets fixed above, this polarity — degrade loudly, cite the reason, never render nothing — is the thing not to break.
