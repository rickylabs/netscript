# repo:boundary — Aspire / telemetry / MCP / Scalar / `/design` ownership surfaces

Baseline: `main` @ `2256a67bf`, worktree `/home/codex/repos/ns-rfc-devtools-contribution`.
Read-only pass. Every claim below carries a repo path + line anchor or a quoted `deno doc` command.

## Summary

Aspire owns the **resource graph, process lifecycle, and the telemetry sink** in a NetScript app.
NetScript's `@netscript/aspire` package is a *generator/contribution* layer — it produces resource
descriptors, permission sets, env vars (including the OTEL exporter env) and health-check specs; it
does **not** run or query anything at runtime (`packages/aspire/src/ports/aspire-builder-port.ts:13-31`,
`packages/aspire/src/ports/aspire-runtime-port.ts:1-9`). The Aspire dashboard is the read model, and
NetScript already has a first-class typed client for it: `@netscript/telemetry/query` exposes
`TelemetryQueryPort` (traces / spans / logs / metrics / resources / OTLP export) backed by an adapter
over Aspire's `/api/telemetry/*` endpoints
(`packages/telemetry/src/ports/telemetry-query-port.ts:15-79`,
`packages/telemetry/src/adapters/aspire-query/aspire-telemetry-query.ts:146`). A DevTools surface can
consume this port rather than reimplement OTLP parsing.

There is **no deep-link helper** to the Aspire dashboard anywhere in `packages/` — the only
dashboard-URL construction that ships to users is inline inside a scaffolded example route
(`packages/cli/src/kernel/assets/app/routes/examples/telemetry/(_shared)/telemetry-trace.ts.template:68-71`),
and it is a bare origin, not a trace/resource deep link. There is likewise no Scalar deep-link
helper; Scalar is mounted at a fixed `/api/docs` by the service builder, sourced from
`/api/openapi.json` generated by `@orpc/openapi` from the service's oRPC router
(`packages/service/src/builder/service-builder-impl.ts:468-484`,
`packages/service/src/primitives/openapi.ts:74-160`).

The MCP surface is the richest *existing* framework-state API: 22 stable v1 tools including run/trace
reads, doctor families, docs/guidance, export-surface discovery, and an OpenAPI-derived service
endpoint directory (`packages/mcp/src/domain/tool-types.ts:3-26`). It is stdio-only today
(`packages/mcp/src/infrastructure/stdio-transport.ts:4`), which is the main friction for a browser
DevTools consumer.

Generated projects already ship a `/design` route group — four pages (index redirect, tokens,
components, composition) with their own sidebar shell — and a separate `examples/telemetry` page.
These are the two nearest neighbours of any DevTools surface and the strongest precedent for where
one would live.

## Findings

### Aspire ownership

1. **Aspire owns resource kinds, references, wait-ordering, and health specs — declaratively.** The
   builder port is the whole contribution vocabulary: `addDenoService`, `addDenoBackground`,
   `addContainer`, `addPostgresDatabase` / `addMysqlDatabase` / `addMssqlDatabase`,
   `addRedisCache` / `addGarnetCache`, plus `reference(from,to)` and `waitFor(from,to)`
   (`packages/aspire/src/ports/aspire-builder-port.ts:13-31`). Resource descriptors are
   `{name, kind, port?, metadata?}` with kinds `deno-service | deno-background | container |
   database | cache` (`packages/aspire/src/domain/aspire-resource.ts:2-19`).
2. **Process lifecycle is a three-state port, not a NetScript concern.**
   `AspireRuntime { start(); stop(reason?); status(): 'idle'|'running'|'stopped' }`
   (`packages/aspire/src/ports/aspire-runtime-port.ts:2-9`). NetScript does not own start/stop/restart
   of resources; the Aspire CLI does.
3. **Health is a declared probe spec, not a NetScript health registry.** `HealthCheckSpec` is
   `{resource, url, expect, timeoutMs?}` (`packages/aspire/src/domain/health-check-spec.ts:1-11`), and
   the default probe path Aspire uses for generated HTTP executables is `/health`
   (`packages/aspire/constants.ts:118-127`, `RESOURCE_DEFAULTS.AppHealthCheckPath`). The comment there
   records the failure mode a DevTools surface must not repeat: without a registered health check,
   Aspire treats a merely-running process as healthy (#954, #1012).
4. **Telemetry export is env-var wiring owned by the Aspire layer.** `OTEL_ENV_VARS` /
   `OTEL_DEFAULTS` (`packages/aspire/constants.ts:22-55`) define `OTEL_DENO`,
   `OTEL_EXPORTER_OTLP_ENDPOINT` (default `http://localhost:4318`), protocol `http/protobuf`, sampler
   `always_on`, 1000 ms export intervals, exemplar filter `trace_based`. These are applied by
   `packages/aspire/src/application/resolve-env-vars.ts:59-77`. Dashboard-side env is
   `ASPIRE_DASHBOARD_OTLP_HTTP_ENDPOINT_URL`, `ASPIRE_ALLOW_UNSECURED_TRANSPORT`,
   `ASPIRE_DASHBOARD_UNSECURED_ALLOW_ANONYMOUS` (`packages/aspire/constants.ts:59-67`).
5. **Dashboard/OTLP ports have hardcoded defaults in the CLI env writer**: `ASPIRE_DASHBOARD_PORT`
   defaults to `18888`, `ASPIRE_DASHBOARD_OTLP_HTTP_PORT` to `4318`
   (`packages/cli/src/kernel/adapters/windows/environment/env-file-values.ts:213-214`).
6. **`@netscript/aspire`'s public `mod.ts` is diagnostics-only.** `NO_COLOR=1 deno doc
   packages/aspire/mod.ts` returns exactly `inspectAspire`, `InspectableAspireBuilder`,
   `InspectableAspireResource`, `InspectionReport`. The contribution surface lives on subpaths
   (`./config ./schema ./types ./constants ./application ./adapters ./testing ./public` —
   `packages/aspire/deno.json` `exports`).
7. **The AppHost's own runtime deep-link exists but only in AppHost JSON, not in a NetScript helper.**
   `aspire describe --format Json` resource nodes carry a `dashboardUrl` deep-link, documented
   explicitly (and deliberately *not* consumed) in
   `packages/cli/e2e/src/application/gates/scaffold/generated-app-endpoint.ts:161-169`. Detached
   `aspire start` writes `dashboardUrl` into start metadata
   (`packages/cli/e2e/src/application/gates/scaffold/aspire-dashboard-telemetry.ts:6-19`;
   `packages/cli/e2e/src/application/gates/scaffold/runtime-gates.ts:587-591`). Both are **e2e-gate
   code, not shipped API**.

### Deep-link helpers — the direct answer

8. **No Aspire dashboard deep-link helper exists in any published package.** `grep -rn
   "traceId=\|structuredlogs\|/traces/\|deep.link\|deepLink" --include=*.ts --include=*.tsx packages/`
   returns only three hits, all under `packages/cli/e2e/` (verify-live-db-endpoint.ts:79,
   generated-app-endpoint.ts:165, validate-flow-b-traces.ts:140). Marked **observed (absence)**.
9. **No Scalar deep-link helper either.** The only Scalar API is
   `createScalarDocs(options: ScalarDocsOptions)` / `createScalarJs()` /
   `createOpenAPISpec(router, config)` (`packages/service/src/primitives/openapi.ts:74,108,152`).
   `ScalarDocsOptions` is `{specUrl, title?, theme?}` (`:48-56`) — no per-operation anchor helper.

### Telemetry contracts a DevTools surface can consume

10. **`TelemetryQueryPort` is the read model, already typed.** Seven methods: `queryTraces`,
    `getTrace(traceId)`, `querySpans`, `queryLogs`, `queryMetrics`, `queryResources`, `exportTraces`
    (→ OTLP JSON) (`packages/telemetry/src/ports/telemetry-query-port.ts:15-79`). Factory:
    `createTelemetryQuery(options: AspireTelemetryQueryOptions): TelemetryQueryPort` at
    `packages/telemetry/query.ts:53` — verified via `NO_COLOR=1 deno doc packages/telemetry/query.ts`.
    Filters are Standard-Schema validated (`validateResourceQueryFilter`, `validateMetricQueryFilter`,
    `packages/telemetry/src/application/query/schema.ts:213,227`). Exported publicly as
    `@netscript/telemetry/query` (`packages/telemetry/deno.json` exports).
11. **The adapter wraps Aspire's `/api/telemetry/<path>` read endpoints** with filter params appended
    to the query string (`packages/telemetry/src/adapters/aspire-query/aspire-telemetry-query.ts:48,
    143-154`), takes `endpoint`, optional API key, `fetch` override and `AbortSignal`
    (`packages/telemetry/src/ports/telemetry-query-port.ts:~82-90`). The docstring notes the endpoint
    is often ephemeral and must come from the AppHost launcher (`:32-35`).
12. **NetScript owns exactly one proprietary attribute root, `netscript.*`, with fifteen declared
    domains** — JOB, EXECUTION, SAGA, TRIGGER, WORKER, SCHEDULER, MESSAGING, CORRELATION, DURABILITY,
    IDEMPOTENCY, RETRY, CONCURRENCY, OUTCOME, SSE, KV
    (`packages/telemetry/src/domain/telemetry-convention.ts:14,32-49`).
13. **Correlation floor is a single attribute: `netscript.correlation.id`**
    (`packages/telemetry/src/domain/telemetry-convention.ts:54-56`). This is the join key a DevTools
    surface would use to stitch a job → saga → trigger → stream story across spans.
14. **Span naming is contractually `<domain>.<operation>`**, with SpanKind, OK/ERROR status +
    exceptions, span-events-for-breadcrumbs, and verbatim OTel semconv keys — encoded as a graded
    checklist TC-1…TC-6+ (`packages/telemetry/src/domain/telemetry-convention.ts:59-83`).
15. **Semconv stability opt-in is pinned**: `OTEL_SEMCONV_STABILITY_OPT_IN =
    'messaging,rpc,gen_ai_latest_experimental'`, with a deprecated-alias window `0.0.1-beta.5` in
    `dup` mode (`packages/telemetry/src/domain/telemetry-convention.ts:3-27`).
16. **Resource attributes carried are minimal**: `service.name` (from `OTEL_SERVICE_NAME`, default
    `unknown-service`) and `service.version` (from `OTEL_RESOURCE_ATTRIBUTES`, default `1.0.0`)
    (`packages/telemetry/src/config/environment.ts:73-77,103-113`;
    `packages/aspire/src/application/resolve-env-vars.ts:63-65`). No `deployment.environment` is set.

### MCP as a DevTools data source

17. **22 stable v1 tool names, enumerable as data** (`packages/mcp/src/domain/tool-types.ts:3-26`):
    `get_app_status, list_runs, get_run, get_recent_errors, get_last_job_result,
    analyze_service_performance, analyze_db_bottlenecks, doctor, search_docs, list_docs, get_doc,
    find_guidance, find_export, list_package_exports, get_export, search_exports, list_commands,
    execute_command, record_drift, list_api_services, list_service_operations, get_operation_schema`.
18. **Every tool has a declared JSON input *and output* schema**, keyed exhaustively by `ToolName`:
    `TOOL_INPUT_SCHEMAS` / `TOOL_OUTPUT_SCHEMAS`
    (`packages/mcp/src/domain/tool-contracts.ts:105,174,353,361`). Tools carry a safety
    classification `ToolKind = 'read' | 'mutate' | 'meta'`
    (`packages/mcp/src/domain/tool-types.ts:32`) and results are a discriminated
    `ToolSuccess | ToolFailure` with a stable machine-readable `error.code`
    (`:34-58`). This is a ready-made typed contract for a DevTools panel.
19. **Endpoint directory: four discovery sources with fixed precedence + bounded probing.** Sources
    are `override`, `aspire-cli`, `run-manifest`, `appsettings`
    (`packages/mcp/src/application/service-endpoint-directory.ts:53-58`, precedence constant
    `ENDPOINT_SOURCE_PRECEDENCE` at `:2`). Defaults: 3 s per-service timeout, concurrency 4
    (`:22-25`). Conflicts are first-class (`EndpointConflict`, `:5`).
20. **`.netscript/run/endpoints.json` is an identity-bound run manifest** — it is only trusted when
    the caller supplies the current AppHost `runId` and the manifest's `projectRoot` real-path-matches
    the project (`packages/mcp/src/infrastructure/service-endpoints/run-manifest-endpoint-source.ts:19,
    31-55`). A DevTools surface reading it must satisfy the same identity gate.
21. **Generated schemas are exposed via a pure, IO-free OpenAPI projection entrypoint**
    `@netscript/mcp/openapi-projection`: `indexOpenApiOperations`, `resolveCanonicalOperation`,
    `describeOpenApiOperation`, `projectOperationSchemaViews` + `SCHEMA_VIEW_NAMES`
    (`packages/mcp/openapi-projection.ts:1-38`). Views are request/response/error/all
    (`OperationSchemaViews`, same file). This is directly reusable by a DevTools API explorer without
    running MCP.
22. **Telemetry endpoint discovery is a shared, four-arm policy** — `explicit` → `NETSCRIPT_TELEMETRY_ENDPOINT`
    → `ASPIRE_DASHBOARD_PORT` (→ `http://localhost:<port>` with an `https` fallback recorded) →
    default `http://localhost:18888` (`packages/mcp/src/domain/telemetry-endpoint.ts:1-39`). The
    resolved value reports its `source`, which is exactly what a DevTools "where is my data coming
    from" affordance needs.
23. **MCP transport is newline-delimited stdio only.**
    `packages/mcp/src/infrastructure/stdio-transport.ts:4` exports a single `runNewlineStdio`. No HTTP
    or SSE transport exists in the package. A browser DevTools panel cannot speak to it directly.
24. **Doctor is family-structured**, with aspire / plugin / project-wiring families
    (`packages/mcp/src/infrastructure/aspire-doctor-family.ts`,
    `plugin-doctor-family.ts`, `project-wiring-doctor-family.ts`) composed via
    `createDoctorFlow(probe, environment, families, projectRoot)`
    (`packages/mcp/src/application/flows/doctor-flow.ts:59`, per `deno doc packages/mcp/mod.ts`).
25. **`record_drift` is the one mutating diagnostic tool**, sharing one refusal string verbatim
    between CLI and MCP (`diagnosticEvidenceRefusal`,
    `packages/mcp/src/application/flows/record-drift-flow.ts:17,25`).

### Scalar / OpenAPI mounting

26. **Mount points are fixed by the service builder**: `/api/openapi.json` (spec),
    `/api/docs` (Scalar UI), `/api/docs/scalar.js` (the JS bundle)
    (`packages/service/src/builder/service-builder-impl.ts:468,477-484`). The root index advertises
    them as `{openapi:'/api/*', spec:'/api/openapi.json', docs:'/api/docs', playground:'/api/docs'}`
    (`:417-423`).
27. **Spec source is the oRPC router**, converted by `OpenAPIGenerator` +
    `ZodToJsonSchemaConverter` from `@orpc/openapi` / `@orpc/zod/zod4`
    (`packages/service/src/primitives/openapi.ts:21-22,55-58`). Default server URL `/api`, default
    Scalar theme `kepler` (`:26-29`).
28. **Scalar's JS is vendored inline**, a 3.48 MB generated TS module `SCALAR_MIN_JS`
    (`packages/service/src/primitives/scalar.generated.ts`, `wc -c` → 3,475,795) served with
    `public, max-age=31536000, immutable` (`packages/service/src/primitives/openapi.ts:30`).
    No CDN dependency — relevant if DevTools wants an offline-safe embedded viewer.
29. **Both presets and plugin services mount docs by default.** `defineService` calls
    `.withOpenAPI(options.openapi).withDocs()` unconditionally
    (`packages/service/src/presets/define-service.ts:227-228`); plugin services take
    `docs?: {specUrl?}` and apply `withDocs` when present, in the fixed chain
    `cors → logger → openapi → docs → database → …`
    (`packages/plugin/src/service/presentation/create-plugin-service.ts:86-87,109,149-150`).

## Drift candidates

1. **Scaffolded telemetry example bypasses the framework's own telemetry read port.**
   Expected: generated code consumes `@netscript/telemetry/query` (`createTelemetryQuery`,
   `packages/telemetry/query.ts:53`). Actual: the template hand-rolls OTLP JSON interfaces
   (`OtlpSpan`, `OtlpScopeSpans`, `OtlpResourceSpans`, `DashboardTraceResponse`) and `fetch`es
   `${base}/api/telemetry/traces` directly, re-implementing nano-duration math and
   `service.name` extraction
   (`packages/cli/src/kernel/assets/app/routes/examples/telemetry/(_shared)/telemetry-trace.ts.template:39-141`).
   Severity: **significant** — it is exactly the "reimplement rather than consume" trap a DevTools RFC
   must not repeat, and it is user-visible generated code.
2. **Two divergent telemetry-endpoint resolution policies.** Expected: one policy. Actual: MCP uses
   the four-arm `resolveTelemetryEndpoint` preferring `NETSCRIPT_TELEMETRY_ENDPOINT` then
   `http://localhost:<ASPIRE_DASHBOARD_PORT>` (`packages/mcp/src/domain/telemetry-endpoint.ts:22-39`),
   while the scaffolded app template hardcodes `https://localhost:${ASPIRE_DASHBOARD_PORT ?? 18888}`
   — **https, no `NETSCRIPT_TELEMETRY_ENDPOINT` arm**
   (`.../telemetry-trace.ts.template:68-71`). Severity: **significant** (scheme mismatch is a silent
   fetch failure in the default unsecured-transport local setup).
3. **`OTEL_SEMCONV_STABILITY_OPT_IN` is declared in telemetry but absent from the Aspire env
   vocabulary.** Expected: if it is required (`NETSCRIPT_SEMCONV_STABILITY_OPT_IN`,
   `packages/telemetry/src/domain/telemetry-convention.ts:8-9`) it should be injected with the other
   OTEL env. Actual: `OTEL_ENV_VARS` (`packages/aspire/constants.ts:22-34`) and
   `resolve-env-vars.ts:59-77` do not list or set it; `packages/telemetry/src/config/environment.ts:71`
   reads it via `OTEL_ENV_VARS.OTEL_SEMCONV_STABILITY_OPT_IN`, a key **not present** in the
   `packages/aspire/constants.ts` object quoted above. Severity: **significant**, but the exact
   `OTEL_ENV_VARS` symbol resolution used by `environment.ts` was not traced to its import — see open
   question 3.
4. **The generated AppHost helper is a hand-maintained Node copy of `@netscript/aspire` constants.**
   `_aspire-compat.ts.template` re-declares `OTEL_ENV_VARS`, `OTEL_DEFAULTS`, `DASHBOARD_ENV_VARS`,
   `DEFAULT_PERMISSIONS`, `RESOURCE_DEFAULTS`, `buildOtelEnvVars`, `parseAppSettings`
   (`packages/cli/src/kernel/assets/aspire/helpers/_aspire-compat.ts.template:95-97,276,286` and the
   embedded mirror at `packages/cli/src/kernel/assets/embedded.generated.ts:115`). It is explicitly
   labelled a D-7 workaround pending Aspire Deno runtime support (aspire#15812). Its
   `RESOURCE_DEFAULTS` copy **omits `AppHealthCheckPath`** present in
   `packages/aspire/constants.ts:127`. Severity: **minor→significant** (drifted copy of a health
   contract).
5. **Dashboard deep-link data exists in AppHost output but only e2e-gate code reads it.**
   Expected (for a DevTools surface): a supported helper. Actual: `dashboardUrl` is consumed only in
   `packages/cli/e2e/...` (`generated-app-endpoint.ts:161-169`,
   `aspire-dashboard-telemetry.ts:6-19`). Severity: **minor** (gap, not contradiction).
