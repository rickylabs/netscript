# 2026-10-31 — Pagination contracts must cover the backend and its consumer bridge

A memory-only suite hid Redis's inclusive cursor and hash-batch ordering. One portable adapter
suite, plus a real-backend multi-SCAN reproduction and a start-only negative control, separates
boundary correctness from global-order correctness. Configure SCAN count before import in a
subprocess; counting a separate raw scan does not prove the adapter traversed multiple replies.

Bounded ordered listing has a real repeated-scan cost. Enumerate internal callers before changing
it: watch polling does not need ordering and must retain a private single-pass discovery path.
Existing startup/debounce/starvation tests should pause the actual SCAN/MGET seam when public
list is no longer the discovery implementation.

The same word can name different contracts at different boundaries: KvStore.start is exclusive;
the native Deno facade used by kvdex has inclusive start. Independent implementation review found
the consumer regression and required explicit translation and a native oracle. Preserve native
typed-bound behavior rather than reapplying a string-coercing comparator to a native bound.

Existing codec/type-order limitations are separate from this pagination correction and are
explicitly documented rather than hidden behind a universal parity claim. No new architectural
debt is accepted. Raw operator execution state stays private; tracked evidence is a sanitized
summary with hashes and reproducible commands.
