## Locked contract

### D1 — one logical span, ordered per-tier events

Emit exactly one INTERNAL span for each public logical cache operation:

```text
span.name=cache.read|cache.write|cache.invalidate
netscript.operation=cache.read|cache.write|cache.invalidate
```

Each tier consulted emits an ordered `cache.lookup` event; write-through and promotion emit
`cache.write` / `cache.promote` events; invalidation emits a bounded per-tier aggregate event rather
than one event per raw key. Provider errors set the logical span ERROR, record the exception, and
emit the failing tier event.

Consequence: the issue's 41-span trace becomes **42 spans for one ordinary cache read**, whether the
provider has one, two, or three tiers. A stale background refresh whose completion outlives the read
may add one `cache.write` follow-up span (43 total), explicitly parented/linked to the read context;
it never adds a span per tier.

### D2 — canonical attributes live under `netscript.cache.*`

Publish the following constants and finite unions from `@netscript/telemetry/attributes`:

```text
netscript.operation=cache.read|cache.write|cache.invalidate
netscript.cache.system=<documented provider id>
netscript.cache.tier=l1|l2|durable
netscript.cache.namespace=<normalized contract/operation id>
netscript.cache.outcome=hit|miss|stale|error
netscript.cache.lookup_index=<non-negative integer>
netscript.cache.backend_executed=true|false
netscript.cache.entry_age_ms=<non-negative integer>
netscript.cache.ttl_ms=<non-negative integer>
netscript.cache.write_through=true|false
netscript.cache.inflight_joined=true|false
netscript.cache.topology_complete=true|false
```

`cache.promote` remains an **event operation**, not a fourth public method/span verb. Promotion is a
consequence within a read/write operation. This avoids an artificial public cache API while keeping
the path distinguishable from attributes alone.

Bare `cache.*` is rejected because OpenTelemetry 1.43 has no cache semantic convention and TC-6
requires proprietary attributes beneath `netscript.*`. Existing `netscript.kv.*` remains the
lower-level KV vocabulary and is not renamed or duplicated.

### D3 — exact mandatory seam: `CacheQuery` consumes required provider reports

Instrumentation attaches in `packages/sdk/src/cache/cache-query.ts`, around the existing
orchestration points (`store.get`, freshness decision, `queryFn`, `store.set`, delete/list), not in
Fresh and not independently in every Redis/Deno-KV adapter.

The public `CacheStore`/`CacheProvider` result contract becomes evidence-bearing:

- a bounded provider descriptor (`system`, default `tier`);
- a non-empty ordered lookup report for reads;
- bounded write/promotion reports for writes;
- bounded invalidation summaries;
- a `topologyComplete` flag that is false only for a compatibility/error path.

`CacheQuery` validates and emits those reports. A provider implementation therefore cannot silently
skip telemetry by omitting an instrumentation call: it returns operation facts, while package-owned
`CacheQuery` performs emission. Missing/invalid reports are visible as
`netscript.cache.topology_complete=false` plus an error outcome; raw provider implementations never
receive a tracer.

The existing arbitrary `setCacheProvider()` seam is also wrapped at registration/retrieval so a
custom provider cannot bypass the **logical operation span** or loader wrapper. The wrapper is an
ordinary object stored in the existing registry slot—no new module-local mutable singleton. The plan
must preserve the current public factory return values by unwrapping evidence internally; provider
implementors receive a documented pre-1.0 contract migration.

This is the minimum honest design that can show an internal two-tier chain. Instrumenting only
`KvCacheStore.get()` would show one opaque provider call and could not prove L1 miss → L2 hit → L1
promotion.

### D4 — backend execution is measured, never inferred

At `CacheQuery`'s loader boundary, wrap `queryFn` with a closure-local boolean. It flips to `true`
on function entry before awaiting the backing call. Final rules:

| Path                                               | `backend_executed`                                       |
| -------------------------------------------------- | -------------------------------------------------------- |
| cold miss then loader succeeds/errors              | `true`                                                   |
| fresh hit                                          | `false`                                                  |
| stale with background or blocking revalidation     | `true` once loader starts                                |
| provider error before loader                       | `false`                                                  |
| joining an already in-flight request               | `false` for the joining trace and `inflight_joined=true` |
| cache-only read (`getCachedData`/`getCachedEntry`) | `false`                                                  |

No store result, duration, miss, or revalidation flag may be used as a proxy. Background completion
must carry the captured read context explicitly if it ends after the caller returns.

### D5 — namespace is operation identity, never key identity

- Contract queries use normalized `${resource}.${action}` supplied where those static identifiers
  are known (`query-factory.ts:41-85`).
- Composite queries accept an explicit normalized operation id; absent input falls back to the fixed
  `composite` namespace rather than serializing props.
- Direct `CacheQuery` calls accept an explicit operation id; absent input uses fixed `direct`.
- Normalization lowercases, permits only `[a-z0-9._-]`, collapses separators, and caps length.
- The canonical query key, its JSON input segment, cache values, URLs, and user data are never read
  into telemetry attributes/events.

No hashed key correlation attribute ships in this slice. It is optional future scope only after a
keyed/HMAC design, opt-in control, rotation story, and cardinality budget are approved.

### D6 — no Fresh defer implementation change

The SDK span inherits the active request/page context. Because Fresh currently queues
`defer.cache.read` after cache/render state is known, this slice promises **same trace**, not false
parentage under that later span. If acceptance is interpreted as strict defer-span parenting, record
a dependency on the sibling Fresh owner to open the defer span around layer/cache execution. Do not
touch `packages/fresh/src/application/{defer,builders}/**` here.

Partial requests follow the identical cache path. No partial flag suppresses a read, seed, or event.

### D7 — public surface and compatibility

What becomes public:

- Telemetry: cache attribute constants, operation/outcome/tier finite unions, attribute builder, and
  cache tracer name/accessor if required by the implementation.
- SDK: provider/store descriptor and operation-report types, normalized operation-id option, and the
  provider migration needed for mandatory topology evidence.

All new exports receive explicit declaration types, one-line JSDoc, and examples where required.
README tables document provider ids (`deno-kv`, `redis`, `memory`, and extension naming), tier
meaning, bounded namespace rules, `backend_executed` semantics, and the span/event model. This is a
pre-1.0 contract change but still requires migration notes because `CacheStore` and `CacheProvider`
are already exported.

No global/singleton telemetry state is added. Tracer/reporting collaborators are constructor- or
factory-injected into `CacheQuery`; defaults use the existing telemetry facade. This avoids a second
SDK instance silently owning a different mutable telemetry registry.

## Acceptance tests — one distinct test per path

| Path                          | Setup and required assertions                                                                                                                                                                                                                                                           |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Cold                          | Fake reported durable miss; loader counter increments once; `cache.read` span has outcome `miss`, `backend_executed=true`; lookup index 0 and write event; no raw key/input/value.                                                                                                      |
| Warm-fresh                    | Seed fresh entry; outcome `hit`, age/TTL present, `backend_executed=false`; loader counter remains zero.                                                                                                                                                                                |
| Warm-stale/revalidate         | Seed stale entry; outcome `stale`, read returns stale under SWR, `backend_executed=true` when background loader starts, completion/write telemetry retains captured trace context. Blocking stale mode is a separate assertion if it uses a different path.                             |
| Provider error                | Store throws before loader; lookup/error attributes and ERROR span status present, exception recorded, `backend_executed=false`. A loader error subcase proves `true`.                                                                                                                  |
| Write-through/promotion       | Two-tier fake reports L1 miss then L2 hit and L1 promotion; ordered lookup indices 0/1, tiers and outcomes correct, `write_through=true`, promotion event present, `backend_executed=false`. Span count stays one.                                                                      |
| Invalidation                  | Seed multiple matching entries; one `cache.invalidate` span and bounded tier aggregate event distinguish success/error/count without emitting individual keys.                                                                                                                          |
| In-flight join                | Two concurrent reads; first trace owns loader execution, joining trace has `backend_executed=false`, `inflight_joined=true`; one loader call.                                                                                                                                           |
