# Plan — #1589 enforce a coherent Fresh/SDK cache-provider closure

Branch: `fix/1589-sdk-provider-closure`. Base: `main@fc312f211`. Research:
`slices/research-1589.md`. **PLAN-EVAL is required and is a hard stop before implementation.** The
draft PR must remain draft and at `status:plan` until the orchestrator records a separate-session
PASS.

## Contract

A NetScript-generated Fresh app must refuse to initialize or build when its effective Fresh root,
Fresh subpaths, SDK root/subpaths, and directly mapped telemetry package form more than one release
closure. It must fail before Vite emits runnable output, naming each resolved identity and telling
the operator to pin the closure together. The current coherent stable path and the verified full
canary workaround remain valid.

The forbidden runtime outcome is unchanged and explicit: this slice must prevent the app from
reaching `[NetScript SDK] Cache provider not initialized`; it must not suppress cache reads or seeds
for partial requests and must not touch `isPartial` policy.

## Archetypes, doctrine, and surface

- **Primary implementation archetype:** Archetype 6 (CLI/tooling), because enforcement is generated
  by `@netscript/cli` at scaffold/init and invoked by generated app tasks.
- **Affected framework contract:** Archetype 4 (`@netscript/fresh` and `@netscript/sdk`) with the
  frontend overlay. Their package source and public exports are not changed in this first cut.
- **Current doctrine verdicts:** CLI `Restructure`, Fresh `Restructure`, SDK `Keep`
  (`docs/architecture/doctrine/10-codebase-verdict-and-handoff.md`). The slice stays in existing
  vertical scaffold/template seams and does not deepen the recorded restructure debt.
- **Anti-patterns in scope:** AP-9 (do not generalize this into a universal dependency solver),
  AP-11/AP-25 (resolution/file reads belong in the generated edge preflight), AP-18 (semantic
  diagnostics, not giant snapshots), AP-22 (no new barrel), and AP-23 (no validation body embedded
  into CLI composition).
- **Published surface:** no Fresh/SDK/telemetry export or ownership change. No new CLI public
  export. Generated workspace tasks and a generated `.netscript` preflight are consumer-visible
  output. No dependency is planned; `deno.lock` must not move.

## Locked choice — option 1, reject incoherent closures

Choose **option 1** as the first cut. It preserves provider ownership and converts the dual-package
hazard into an early, version-specific operator error.

Trade-off: detection protects NetScript-generated workspaces and their normal bare-import contract;
it does not make arbitrary hand-authored multi-version module graphs safe. Existing generated apps
must regenerate/adopt the new preflight, while the coherent pin workaround remains the immediate
repair.

### Rejected for this cut

- **Option 2 — exact peer-compatible metadata:** Fresh already pins its internal SDK and telemetry
  dependencies exactly, yet Deno legitimately loads a consumer's differently pinned direct SDK. JSR
  package imports are not a singleton peer constraint. Metadata may document/strengthen the closure
  later, but it cannot replace consumer-boundary rejection and would widen publish-order and
  metadata scope.
- **Option 3 — `globalThis` provider registry:** this changes ownership semantics, violates the
  doctrine preference against hidden globals, and leaves an unresolved ABI question when two
  versions disagree about which implementation owns the key. It is the largest option and is not
  justified while a narrow preventive gate can eliminate the reported failure.
- **Documentation alone:** not mechanical and therefore outside the issue contract.

## Closure rule

Define one finite `NETSCRIPT_WEB_RUNTIME_CLOSURE` policy owned by CLI scaffolding:

1. Resolve the Fresh root and every currently exported Fresh subpath.
2. Resolve the SDK root and every currently exported SDK subpath, including `./cache`, `./query`,
   and `./query-client`.
3. Resolve telemetry when the active app exposes a direct `@netscript/telemetry` identity; absence
   remains valid because today's generated app does not directly map it.
4. Fresh root/subpaths must share one package name, version, and origin root. SDK root/subpaths must
   do the same.
5. Fresh and SDK versions must be exactly equal. Direct telemetry, when present, must equal that
   version. Stable and prerelease exact versions are both valid.
6. All members must use one source mode: canonical JSR identities, or local workspace package roots.
   A local/JSR mix fails even when version strings match.
7. An unresolved or unsupported identity fails closed with the specifier and resolution shown; it
   never falls through to the runtime provider error.

The finite Fresh/SDK subpath lists are checked against both packages' `deno.json` export maps in a
repo test so a newly published subpath cannot silently escape the closure policy.

## Enforcement points and operator experience

### Init

The app manifest generator validates the resolved import-map fragment before serializing it. A
custom/injected resolver that returns split versions makes `netscript init` fail immediately; no
incoherent app `deno.json` is written.

### Dev and build

Init writes a dependency-free `.netscript` closure verifier and a root `deps:closure` task bound to
the generated app config. Both generated app `dev` and `build` tasks run it before the existing npm
materialization/Vite command. The verifier uses `import.meta.resolve()` under the app's Deno config,
so an explicit subpath override is observed after Deno import-map resolution rather than inferred
from raw JSON.

Failure format (exact punctuation may change, content may not):

```text
NetScript dependency closure is incoherent.
  @netscript/fresh              -> jsr:@netscript/fresh@0.0.5
  @netscript/fresh/defer        -> jsr:@netscript/fresh@0.0.6-canary.3/defer
  @netscript/sdk                -> jsr:@netscript/sdk@0.0.5
  @netscript/telemetry          -> jsr:@netscript/telemetry@0.0.5
Pin @netscript/fresh, all @netscript/fresh/* and @netscript/sdk/* imports, and any direct
@netscript/telemetry import to one exact release (for example 0.0.6-canary.3), then rerun.
```

Exit is non-zero before Vite starts. The message must never be only "Cache provider not initialized"
and must not mention partial-navigation suppression as a remedy.

## False-positive policy

- Validate one app/config at a time. Two workspace members may legitimately use different releases
  when each member is internally coherent.
- Do not inspect or reject unrelated lockfile duplicates or other NetScript packages.
- Accept coherent stable, coherent canary, and coherent local-source closures.
- Accept absent direct telemetry; compare it only when directly resolvable by the app.
- Reject unused split Fresh/SDK aliases intentionally: the latent split violates the configuration
  contract even before a current route imports it.
- Reject mixed local/JSR identity intentionally: it creates distinct module instances despite equal
  version text.
- Scoped per-referrer import maps and direct literal `jsr:` imports are outside the generated
  workspace contract. They are safe to defer for this first cut because generated NetScript apps
  emit neither. This limitation must remain explicit in diagnostics/docs and in the PR; if PLAN-EVAL
  judges #1589 to require arbitrary manual graphs, the plan must rescope before code.

## Open-decision sweep

- **Safe to defer:** peer-compatible published metadata. Detection is sufficient for the first cut;
  metadata cannot prevent the known duplicate by itself.
- **Safe to defer:** provider relocation/global registry. It changes ownership/ABI semantics and is
  unnecessary if the gate proves the reported configuration cannot proceed.
- **Safe to defer:** arbitrary direct literal imports and per-referrer import-map scopes. They are
  not generated by NetScript; the limitation is explicit and is a PLAN-EVAL attention point.
- **Locked now:** telemetry absence is valid; a direct telemetry identity, when present, joins the
  exact closure.
- **Locked now:** separate coherent app configs may use different versions; validation is never
  workspace-global.
- **Locked now:** existing consumers need regeneration/manual adoption of the preflight; the fix
  cannot retroactively alter a stable generated script.

## Deferred scope
