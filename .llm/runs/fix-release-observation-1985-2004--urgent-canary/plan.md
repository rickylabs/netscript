# Plan

## Design and locked decisions

S1 existing GitHub release collector: export only tool-local fetchClosedIssues and native generateWhatsChanged for injected-transport tests, not package exports. Request per_page=100 with increasing page until raw item total reached or a short page exhausts results. Preserve newest-first API order and PR guard. Count raw items before filtering, deduplicate issue numbers preserving first occurrence. Validate HTTP, items, nonnegative integral total_count and incomplete_results false. Fail closed on malformed page, failed page, short page before total, unstable total, malformed non-PR issue or explicit search ceiling total_count >=1000. Error diagnostics identify page/status or incomplete/ceiling, never request token/body. Ceiling instructs narrowing the release window rather than silently emitting partial notes. Zero total is valid empty response. Native merged-PR generation receives no pagination change: long-body test proves full pass-through.

S2 owned Bash helper watch-canary-e2e.sh: validate numeric child ID and required GITHUB_OUTPUT, use native gh run watch for same ID, then always native gh run view JSON status/conclusion via jq TSV. Five bounded observation attempts, capped exponential sleep only between inconclusive observations; existing parent timeout bounds watch duration. A completed known success is green, completed known non-success conclusions are observed failure with exact allowlisted conclusion. Missing, malformed or nonterminal observation retries; exhaustion emits state=unknown and exits nonzero. No duplicate dispatch, manual green override or inferred child failure. Workflow await calls helper; failed-pair handler uses helper state/conclusion to distinguish observed terminal failure from unknown. Existing publishing, immutable dispatch, exact source pair, partial-publish handling and green default success gating unchanged. Put user-visible failure description selection in a small consumed shell helper so actual handler behavior is tested, not a mirror of YAML text.

S3 focused tests, recorded mutations, gate evidence and independent evaluator. Each slice under thirty files. S1 files github-release.ts plus focused github-release-pagination_test.ts. S2 files workflow and two consumed shell helpers plus focused watch-canary-e2e_test.ts; tests execute actual Bash with generated fake gh/sleep executable files under TMPDIR, no live calls. S3 harness artifacts only; generated carriers only if canonical generators show real source impact.
