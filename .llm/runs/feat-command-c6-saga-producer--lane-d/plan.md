## Architecture decisions LOCKED

1. Use the RFC focused subpaths and current package layouts, with root-level commands.ts/commands-relay.ts/commands-testing.ts manifests where needed rather than speculative nested barrels. Contracts adds ./commands; service adds ./commands, ./commands/testing and ./commands/relay; database adds ./commands, ./commands/testing and ./commands/adapters/postgres. No independent commands package or root-export enlargement.
2. C1 introduces service-owned CommandJson, actor/envelope, opaque immutable CommandDefinition and CommandFailure/CommandError, codec and identity contracts. An internal WeakMap binds handler to opaque definitions; a forged/foreign definition is refused. Contracts owns opt-in exact error schemas/map/builder and maps only safe structurally validated command failures. It preserves current BaseContractMeta. Contracts need not import the service implementation. No global conflict error.
3. Version the canonical protocol as jcs-v1 internally and expose the RFC definitionVersion replay boundary. JCS uses validated I-JSON, ECMAScript JSON.stringify numeric/string serialization and UTF-16 lexicographic key ordering; reject nonfinite numbers, lone surrogates, sparse arrays, undefined, exotic prototypes, symbols/functions, Date/BigInt, cycles and overflow. Defaults: maximum depth 64, aggregate items 10,000 and canonical bytes 1 MiB; configured bounds only tighten those safeguards. Stored canonical text must round-trip exactly after bounded parse/canonicalization, rejecting duplicate/noncanonical material and corrupt receipts. Add RFC 8785 normative vectors and equivalent-key-order/replay negatives.
4. jsonCodec remains synchronous as in the RFC: schemas returning a Promise are refused with a configuration diagnostic. This restriction is documented and tested; async worker schema validation may occur in the engine before the transition commit, outside handler side effects. No unvalidated codec value crosses persistence. StandardSchemaV1 is declared directly in service.
5. Required idempotency is the default; definitions may explicitly choose optional. Compute scope/fingerprint once per attempt over frozen values. Hash exact RFC request material and a separate key digest with Web Crypto; omit credential scheme, correlation, trace and raw key from identity. Version changes mismatch within the same receipt key; scope/name changes create a new namespace and require migration documentation.
6. C2 owns the database CommandStorePort<TTx>/CommandTransaction<TTx> contracts needed by its fake. All rows share the callback-derived transaction handle. Store callback and handler each run at most once. Busy is an internal terminal sentinel; no further callback query occurs and rollback completes before in_progress surfaces. Buffer policies, count/byte limits, isolation and cancellation are enforced. Handler business errors retain identity rather than being blanket storage-wrapped.
7. C3 directly consumes the provider's true transaction callback and generated delegate bridge; root lifecycle/nested transaction methods are excluded. Receipt/audit/outbox logical shapes are package-owned; reviewed schema and consumer-specific bridge fixtures are checked in. CLI generation remains stage 8 and is deferred; C3 ships migration/schema/bridge fixtures and explicit manual consumer binding, with no implicit schema injection or runtime DDL. Provider identifiers are generated constants and values are parameters.
8. PostgreSQL claims use ON CONFLICT DO NOTHING RETURNING and indexed winner select. Save/restore transaction-local lock_timeout on successful claims; 55P03 aborts the callback and rolls back. 40001/deadlock are surfaced retryable failures, with one callback invocation. Prove leader commit/rollback, follower usability, bounded wait, session hygiene and next clean transaction against a real provider.
9. C4 keeps command spans privacy-first; existing messaging/saga correlation attributes remain owned by those existing domains. Document this deliberate asymmetry and defer global deprecation. INTERNAL command.execute follows active server context; PRODUCER relay publication and consumer W3C/link relationships use exact tests. No raw identity, hashes, correlation, topic, destination, payload or receipt IDs enter command spans or metric dimensions.
10. C5 owns one generic relay, no queue dependency. Lease claims are bounded; due/unpublished/nonterminal rows only; mark/release compare tokens and retain stable ids. Lifecycle uses injected clock/ids, explicit max attempts/backoff, AbortSignal, drainOnce and stop waiting for active drains. Concurrency is configured and bounded; overlapping drains cannot share a claim. Classify malformed payload/trace, missing sinks and checked rejection into the RFC bounded failure classes.
11. Add an acknowledged sink receipt to the C5 contract for worker deliveries: validated target kind/id, nonempty acceptance/run identity and acceptedAt. Generic sinks may continue using their documented acceptance without a worker receipt. Worker sinks must return the checked receipt; the generic settlement request may carry only normalized identity/time and stores persist it with publishedAt in the same token-checked write. An invalid, mismatched, absent or unchecked worker receipt throws and leaves the row unpublished/retryable. No post-settlement receipt repair. Provider row schema and conformance include this extension in C5.
12. Worker, saga and stream sinks are core-owned adapters using existing checked boundaries. They propagate stable dedupe identity, correlation and valid W3C context and do not duplicate transport semantics. Correct WorkerIdempotencyPort wording: its claim/effect/mark window alone cannot prove exactly-once-effective remote work. Any demonstration of one effective application uses a downstream idempotent persistence operation explicitly proven by its fixture.
13. #1932 exports workerJobEffect(definition, payload, options) and workerTaskEffect(definition, payload, options) as distinct tagged effects from saga integration/workers. Definition-first generic inference (payload uses NoInfer) prevents a wrong payload from widening the definition. Require the selected definition's existing schema; reject missing-schema definitions. Extend workers-core task definition/builder with schema-bound payload overload matching the job approach; do not add a saga-owned payload brand/map. Constructor emits immutable data only; engine validates schema/codec before any store call. Async schema validation is permitted by this precommit engine step, while handlers remain synchronous and side-effect free.
14. Add an explicit SagaTransitionCommitPort with commitTransition(request, signal) and one optimistic version condition over next state, correlation, history and all command intents. A definition declaring durable worker effects requires the capability during runtime composition. Prisma implements it with one true callback-derived transaction and C5 outbox bridge; existing granular save paths are never used for a durable worker effect. In-memory test store implements identical atomic conformance. KV explicitly refuses durable worker-command composition with a missing atomic transition/outbox diagnostic, as allowed by #1932, rather than inventing a weak SQL+KV mode or a second KV relay. Existing non-command saga paths remain valid.
15. Derive intent identity by SHA-256 of a canonical tuple [sagaId, instanceId, nextVersion, effectOrdinal] plus a versioned namespace. Ordinal follows original handler effect order. Persist serialized intents within the Prisma transition callback; after commit the producer maps these rows to C5. No lease, backoff, settlement or retry implementation lives in saga. Forward correlation and trace. Native worker progress stays in #1592's execution stream; completion examples consume publishSagaOrThrow from #1365.
