# Rebasing generated prose without losing upstream context

The native prose generator rebuilds pages/* and llms entries, but deliberately preserves non-site entries such as context/*.mdx from its input carrier. A blanket feature-side conflict choice can therefore discard upstream context permanently even after regeneration. Resolve generated carrier conflicts to a fixed upstream base commit (normally ours during rebase); reset the prose input to that same fixed main again after replay, then run prose→MCP exports→assets barrel→publish assets. Verify every non-site byte against main, every upstream page retained, only approved page additions, no removals, row integrity and exact rendered-source equality. Also compare the old feature tip to explain upstream differences.
