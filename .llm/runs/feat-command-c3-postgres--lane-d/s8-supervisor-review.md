# S8 content review

PostgreSQL side-record methods close over the actual callback client, with fixed reviewed
identifiers and bound values. Unique INSERT ON CONFLICT returns the owner or indexed winner. The
real-provider harness observes the follower waiting on a provider lock before releasing its leader.
Successful claim restores transaction-local lock_timeout. Real Prisma lock-timeout errors are
recognized through native error classes and structured DriverAdapterError causes; no error-message
parsing or driver-looking business objects are classified. Busy revokes side delegates and forces
physical rollback before returning the busy result. There is no query in a failed claim finally
path.

The callback runs once, tracks owned incomplete receipts, rejects unknown completions, enforces
finite policy and cooperative checkpoints, and preserves arbitrary callback errors. Retained side
delegates are revoked at callback exit. Native serialization/deadlock tests prove retryable
classification without callback replay. The actual root-write negative control deliberately survives
callback rollback, preventing certification of split business/side commits. Six real-provider cases
each have an assertion-failing production mutation and restored pass; no unrelated compile failure
is counted.

The generated bridge must mask root operations at runtime because Prisma exposes nested transactions
on its callback. This is recorded implementation evidence for the approved true-TTx decision, not a
root assertion. Framework declaration policy remains enabled; the unmodified Prisma generated
consumer uses its separate config. Direct driver-adapter-utils dependency is already catalog-pinned;
the reviewed lock delta adds only its database workspace declaration, with no version changes.

Scoped check/lint/format, repository quality/architecture, frozen source check and isolated native
provider script all exit zero. Publication, generated consumers and independent IMPL-EVAL remain S9
gates; no readiness claim.
