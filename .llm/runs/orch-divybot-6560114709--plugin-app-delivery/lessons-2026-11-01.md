# Installed plugin delivery lessons

- Resolve app consumers before the scaffolder writes. Persist selection with the plugin's resource
  identity so subsequent reconciliation retains explicit app scope.
- Only API resources may become AppHost discovery references. In-process capabilities can have
  consumer metadata while exposing no plugin resource or endpoint.
- Read app reference arrays at AppHost execution time. A regenerated helper should not be required
  for an existing resource reference added to settings by hand.
- A callable adapter module and a package's executable CLI export are distinct contracts. Inspect
  the export map before invoking a local CLI file; root `cli.ts` need not run on import.
- Installation-generated registries require explicit test-owned removal in missing-registry
  negative controls. Keep actual overview readiness separate from listener readiness.
- Read-only leak reporters can write raw identity-bearing reports. Keep detailed evidence private
  and publish only resource counts and ownership verdicts.
