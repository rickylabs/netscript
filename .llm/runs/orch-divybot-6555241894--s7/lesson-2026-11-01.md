# Lesson — 2026-11-01

Static registry previews need both source fidelity and a real CSS document boundary. Loading a theme attribute without its actual preset stylesheet gives convincing markup but wrong geometry/fonts/colors. Mixing every isolated iframe palette into the outer docs policy instead invents role conflicts. Keep the outer auditor strict, attest every isolated shipped asset against canonical sources and the actual Lume minifier, and audit newly authored preview styles in their own canonical token context with negative controls. The wrong-stylesheet browser control and raw-color/misplaced-red controls demonstrate that those checks fail when they should.

Component identities often collide with ordinary framework vocabulary. Corpus-derived discovery is useful, but an exclusive component shortcut needs explicit component intent and negative examples for service pagination, worker progress and MCP search. Locked retrieval suites alone do not cover a newly introduced bypass.

Await the entire local-source init process, which applies the preset after package copy. The early scaffold success message is not the final result. Proof should compare complete selected resolved dictionaries and canonical CSS bytes, then actual independent app rendering. Normalize minifier syntax through browser color semantics; retain exact component geometry and typography checks.

No architectural debt accepted. Unshipped styles and unsupported free-form token axes are explicit phase-1 scope boundaries. Docker absence leaves full runtime UNPROVEN and must remain visible even when docs/browser and static package gates pass.
