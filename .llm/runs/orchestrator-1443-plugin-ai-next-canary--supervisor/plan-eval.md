## Open-decision sweep (evaluator-run)

1. Define the protocol as an atomic service-bearing or service-less shape. Decide whether `officialSource.{serviceEntrypoint,serviceConfigKey,servicePort}` is an all-present/all-absent union/refinement and how `provider.defaultServiceEntrypoint` normalizes into the existing CLI `string | null` contract. Deferring this changes public types, CLI consumers, and tests.
2. Define the actual export contract of generated `ai/mod.ts`. It must export exactly one valid `PluginManifest` for `loadRegisteredPlugins`, in addition to any app-owned exports. Mirroring `workers/mod.ts` is not evidence because that barrel exports job/task declarations, not a manifest.
3. Define installed-plugin identity independently of appsettings. With D2+D4, `assertPluginNameAvailable` checks only `plugins/<name>` and appsettings (`plan-plugin-install.ts:120-156`), so a second service-less install has no registration sentinel. The metadata loader also derives `plugins/<canonicalName>` rather than the configured module directory (`plugin-registry.ts:220-256`).
4. Resolve the selected frontend overlay before implementation. Either include its route/browser/loading-empty-error/responsive/contract gates, which conflicts with deferring route mounting, or remove/N/A the overlay with a scope-based rationale and retain the targeted compile/contract gates that #1443 actually requires.

## Findings

1. **Generated `ai/mod.ts` does not meet the configured-module contract.** `plan.md:62-73` defines an app-owned barrel. `packages/cli/src/kernel/adapters/config/plugin-registry.ts:363-402` imports every configured spec and accepts only a default or sole named export shaped as `PluginManifest`; otherwise it throws at line 373. `generate runtime-schemas` invokes that loader through `packages/cli/src/public/features/root/public-command-dependencies.ts:329-340`. **Required fix:** lock the generated module's manifest-bearing export, name its source (`@netscript/plugin-ai` re-export or a generated app-owned manifest), add the exact module contract test, and update S4 files/proof. Do not use the current workers barrel as the correctness reference.
2. **D1 is JSON-backward-compatible but not source-backward-compatible, and it permits partial service metadata.** The public field currently renders as required under `deno doc --filter PluginManifestProvider packages/plugin/mod.ts`. Widening it to optional makes `install-plugin.ts:618` incompatible with `PluginKindProvider.defaultServiceEntrypoint: string | null` at `plugin-kind.ts:75-76`; optionalizing `officialSource.serviceConfigKey` also invalidates assumptions in `plugin-reference-reconciler.ts:146-179`. Independent `.optional()` fields admit partial triples. **Required fix:** design an atomic service/no-service schema and derived type, specify normalization (`undefined` to `null` or a deliberate CLI type widening), inventory/update every consumer, add partial-shape rejection tests and existing-manifest equality tests, and include the CLI consumer type-check in S1.
3. **D2/D4 break installed identity and the valid list/doctor path when no appsettings entry exists.** Aspire helper generation itself is safe: `generate-register-plugins.ts:43-52` only loops actual `NetScript.Plugins` entries. The surrounding CLI is not. `plugin-registry.ts:191-256` finds metadata beside `ai/mod.ts` but then hardcodes workdir `plugins/<canonicalName>` and falls back from absent service fields to `provider.defaultEntrypoint`; list renders that as `Service` (`list-plugins-command.ts:45-61`) and doctor checks the nonexistent workdir (`doctor-plugin-use-case.ts:191-217`). A reinstall is not detected because `plan-plugin-install.ts:129-151` checks only `plugins/ai` and appsettings. The reconciler's installed-key set is also appsettings-only (`plugin-reference-reconciler.ts:47-58`) and its legacy `officialSource` guard requires `serviceConfigKey` (`:176-179`). **Required fix:** add a slice that makes configured module/manifest location the source of installed identity and workdir, defines service-less list output, preserves valid doctor output, blocks duplicate installs, and explicitly handles service-less declarations in reconciliation.
4. **Slice ordering violates the per-slice proof invariant.** S5 promises `deno check ai/**` clean before S6 emits the imported Markdown surface (`plan.md:191-193`). **Required fix:** land registry materialization before the full namespace check, or narrow S5's claim/gate to config/import-map mechanics and make S6 the first full namespace check. Each landed slice's named gate must pass before the next slice.
5. **The archetype and gate matrix are incomplete.** Doctrine assigns `packages/plugin` to ARCHETYPE-4, not ARCHETYPE-1 (`docs/architecture/doctrine/06-archetypes.md:368-380`). The plan omits ARCHETYPE-4 additions, F-CLI-1...31, the selected frontend overlay gates, and the post-publish gate/debt target required by `release-gates.md:31-40`. **Required fix:** correct the archetype, enumerate every applicable universal/archetype/overlay gate with PASS/PENDING_SCRIPT/DEBT handling, resolve overlay applicability, and add the `e2e-cli-prod` post-canary obligation.
6. **The planned jsr-audit surface is incomplete.** S2/S4-S8 change behavior shipped by `@netscript/cli`, but `plan.md:157-168` audits only `packages/plugin` and `plugins/ai`. A local dry-run cannot prove the embedded registry path over the published graph. **Required fix:** add `packages/cli` full-export doc-lint/publish dry-run to the planned rubric, retain `plugins/ai` publish-include/freshness checks, and bind the exact canary to `e2e-cli-prod` after publish.
7. **D6's core feasibility holds, but its emitted surface is understated.** `registry.ts:85-101` selects `FRESH_UI_REGISTRY_CONTENT` when `registryRoot` is absent; `resolve-ui-app-root.ts:27-33` accepts an explicit path; and `registry.ts:261-283` maps `@ui/` under that path. The call always writes `assets/styles.css` (`registry-styles.ts:7-38`) and `markdown` recursively pulls `theme-seed` and `citation-chip`, three files, eleven npm dependencies, and CSS imports (`packages/fresh-ui/registry.manifest.ts:633-678`). **Required fix:** replace the implementation-time contingency in `plan.md:96-99,176` with this locked exact emitted-file/dependency contract and assert that complete set in S6. No plugin-local Markdown fork is required.
