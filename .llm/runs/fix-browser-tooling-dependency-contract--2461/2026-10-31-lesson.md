# 2026-10-31 — Ownership-aware dependency coverage

Distinguish repository-owned npm tools from published Deno workspace members. Dependency wrappers may themselves ship to consumers: inspect consumer-tools.json before adding repository-specific imports. A root task router can preserve consumer source bytes while exposing additional repository scope.

Do not infer freshness from cold npm outdated output: npm11/12 can return an empty object for older locked releases without node_modules. Read the owning lock and reuse the existing stable resolver, naming direct scope and method. Never convert a failed lookup into up-to-date data. Keep severity-threshold audit findings separate from total advisories.

A cached-only Deno child test must statically import its exact graph so a cold CI shard owns its cache prerequisites. Prove it with a new isolated module cache. Workflow gate assertions should identify actual runnable steps and reject removal, names/comments, conditions, failure suppression, ordering, cwd and unuploaded evidence paths using in-memory copies.
