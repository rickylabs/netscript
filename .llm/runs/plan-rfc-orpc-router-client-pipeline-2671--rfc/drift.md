# Drift & Diagnostic Notes — RFC A (`plan/rfc-orpc-router-client-pipeline-2671`)

No framework runtime or build drift was encountered during Round-0 authoring, Round-1 revision, or Round-2 revision.

## Notable Architectural Observations (Pre-existing on `main` `87965d800`, source-inspected)

1. **Uncorrelated `requestId` between Hono and oRPC:** `packages/logger/middleware.ts` extracts/generates `X-Request-ID` on Hono context, while `packages/logger/orpc-plugin.ts` (`createRequestId()` at line 371) generates a separate random 8-char `requestId` per RPC invocation. Addressed in RFC A Stage 1a.
2. **Implicit `CORSPlugin` in `packages/service/src/primitives/handlers.ts:112`:** `createRPCHandler` and `createOpenAPIHandler` mount oRPC's `new CORSPlugin()`, and `packages/service/tests/cors-response-authority_test.ts:442-480` explicitly asserts origin reflection for standalone handlers and services without `withCors()`. Deferred to breaking Stage 2 (`0.1.0`, aligned with companion PR #2674 head `6501e41c` §4.4, adding opt-in `RPCHandlerConfig.cors`).
3. **`ServiceBuilderImpl.buildRpcContext()` overwrite order:** `packages/service/src/builder/service-builder-impl.ts:336-341` spreads `...this.contextFactory(c)` *before* `principal: c.get('principal')`, so HTTP-edge scoped branding (`VerifiedPrincipalRecord`) must happen inside `createAuthnMiddleware`.
4. **Global `INTERNAL_PRINCIPALS` WeakSet & shallow-frozen `claims`:** `packages/service/src/auth/internal-credential/internal-credential-authenticator.ts:15,84,108-110` checks `INTERNAL_PRINCIPALS.has(principal)` without verifying `principal.claims.audience === currentServiceName` AND shallow-freezes `{ ...result.principal }` sharing `matched.claims` from `packages/service/src/auth/static-credential-authenticator.ts:98` (`Object.isFrozen(principal.claims) === false`, verified). RFC A §3.4 closes both via private `record.internalAudience` enforcement and deep-freezing `claims` per authentication.
5. **Silent `defined: false` downgrade on router-level `ORPCError` without schema-matching `data` (oRPC v1 only):** Verified empirically against `@orpc/server@1.15.5` + `@netscript/contracts` `commonErrorMap`. On oRPC v2 (`2.0.0-beta.53`, per PR #2674 prototype evidence), `ORPCError` drops constructor `defined` and reconciles via `reconcileORPCError`.
6. **Cross-RFC alignment verified (PR #2674 `6501e41c` & PR #2659 `f8c8d8fd`):** PR #2674 (`6501e41c`) aligns with RFC A on both v1/v2 `contract-procedure-index.ts` retention and deferring `CORSPlugin` removal to `0.1.0`. PR #2659 (`f8c8d8fd`) and RFC A now share the exact same `Symbol.for('@netscript/async-context/active-store-probes')` global ALS probe registry for composition-root snapshot capture. Neither PR #2674 nor PR #2659 was touched during RFC A Round 2.
