## Current and incoming MCP map

- Current `@netscript/mcp` serves initialize, `tools/list`, and `tools/call` over handwritten
  2025-11-25 framing; it advertises tools only. There are no resources, prompts, or subscriptions.
  Tool results use text JSON plus `structuredContent`.
- Current docs corpus ports provide list/search/get, with filesystem and embedded adapters. The
  release generator is `.llm/tools/generate-publish-assets.ts`; `check:publish-assets` and the
  release/publish workflow protect generated bytes. JSR exports root, CLI, and OpenAPI projection.
- PR #1404 adds `findGuidance(intent)` and the 22nd read tool, `find_guidance`; both corpus adapters
  share a deterministic guidance index. Its signals are BM25-like lexical ranking, exact phrase and
  heading boosts, curated concepts, and one-hop internal links. Route hints/exact matches dominate;
  ties resolve by slug/section.
- Incoming asset evidence: 12-document embedded selection is 253,511 bytes under 262,144; full
  compressed corpus is 1,331,984 bytes for 174 documents, 4,591,109 source bytes, and 3,777 heading
  sections. Baseline full corpus was 166 docs / 3,497 headings / 1,175,931 compressed bytes.
- The RFC therefore preserves #1404 as the byte-parity fallback and refactors only enough to expose
  signal-specific candidate ranks.

## Architecture seams and debt

- Doctrine requires package-owned narrow ports, one technology per adapter, inward dependencies,
  `AbortSignal` on async I/O, a pure factory composition root, explicit testing adapter, and no
  environment/global reads in core.
- The proposed runtime shape is Archetype 2 Integration under `SCOPE-docs.md`; this lane itself is
  docs-only. Existing MCP horizontal-shape debt `MCP-A6-V2-SHAPE` is acknowledged, not expanded or
  resolved. Database debt `AP-17` is unrelated.
- `@netscript/database` is a Prisma application database abstraction and is the wrong domain seam.
  `@netscript/ai` has a reusable narrow `EmbeddingProviderPort`; its AgentMemory and vector-memory
  ports are thread/transcript concepts, and its generic retriever lacks release corpus identity and
  MCP provenance. A package-owned MCP semantic index port is required.
- `deno why` found no current use of `@tursodatabase/database`, `@libsql/client`, or
  `@huggingface/transformers`. Related #317/#455 are other application/desktop Turso seams; #499 is
  conversational memory; #238 keeps application knowledge bases outside generic AI.

## EIS-chat comparison

`eis-chat` uses `@tursodatabase/database` 0.6.1 with `vector32`, cosine linear scan, dimension
checks, `LIKE` fallback, scalar alpha blending, and citation numbering. Adopt the actual local API,
dimension checks, bounded vector search, fallback discipline, and citations. Reject ASCII `LIKE`,
incomparable raw-score blending, unstated tie behavior, console-only errors, and its mixed
knowledge/memory boundary. NetScript already has the stronger deterministic channel; use RRF.

## Primary-source technology findings

### New Turso database rewrite

- Current reviewed stable package is `@tursodatabase/database` 0.7.1 (MIT, pre-1.0). Official
  sources document native local and in-memory operation, Deno compatibility, and vector32/vector8
  cosine functions. Vector8 uses roughly one byte/dimension plus overhead versus four for vector32.
- Vector semantic search is a linear scan. The official code-indexing guide uses vector8 and RRF
  with `k=60`, matching this corpus scale.
- FTS/index methods and multiprocess WAL are experimental. MVCC/concurrent write features are
  irrelevant to immutable read-only artifacts. Browser/WASM is a separate package/surface.
- Decision: single-process read-only native adapter, bounded linear vector scan, no Turso FTS,
  multiprocess, vector index, cloud, legacy libSQL, or `@libsql/client`.
- Sources: `docs.turso.tech/guides/code-indexing`, `docs.turso.tech/llms.txt`, TypeScript/vector/
  experimental/multiprocess references, and the 2026 rewrite/PostgreSQL project reports linked in
  the RFC.

### MCP

- The 2026-07-28 server specification distinguishes model-controlled tools, application-controlled
  resources, and user-controlled prompts. Tools can return resource links and structured content.
  Immutable release resources do not need subscriptions/list-changed.
- Decision: retain `find_guidance`; add stable docs resources/resource links and reads; no prompts
  or subscriptions. Treat official v2 SDK/protocol modernization as a compatibility slice rather
  than coupling it to retrieval domain work.

### Models and runtime

- Selected encoder: `intfloat/multilingual-e5-small` (MIT, 384 dimensions, query/passage prefixes,
  L2 normalization) through pinned Xenova ONNX revision `761b726dd34fb83930e26aab4e9ac3899aa1fa78`.
  Quantized ONNX is 118,308,185 bytes, SHA-256
  `f80102d3f2a1229f387d3c81909990d8945513e347b0eab049f7de3c6f98c193`; tokenizer is 17,082,730 bytes,
  SHA-256 `0b44a9d7b51c3c62626640cda0e2c2f70fdacdc25bbbd68038369d14ebdf4c39`.
- Runtime: `@huggingface/transformers` 4.2.0, Apache-2.0; WASM default, WebGPU only after capability
  detection, all assets self-hosted, no CDN.
- Optional reranker: Apache-2.0 MS MARCO MiniLM L6, pinned 23,143,499-byte quantized ONNX SHA
  `e9d8ebf845c413e981c175bfe49a3bfa9b3dcce2a3ba54875ee5df5a58639fbe`. It is English-oriented, top-12
  only, experimental, and off until a separate multilingual/no-regression gate passes.

## Design conclusions

- Release-built immutable database pinned by docs/model/chunker/generator identities; full artifact
  distributed as a verified GitHub Release asset. Cache key is package version + artifact SHA.
- `vector8` candidate with a ≤0.005 nDCG@5 loss gate against vector32; artifact caps 24 MiB raw / 8
  MiB compressed. Encoder download ≤140 MiB; optional reranker ≤25 MiB.
- Weighted RRF v1: `k=60`; lexical 1.00, concept 0.90, graph 0.35, vector 0.80; exact/route/rare
  protected tier; top-40 signal lists, top-8 output, stable deterministic tie chain.
- Modes `off`, cache-only `auto`, explicit `download`, and `shadow`; all semantic failures return
  the original deterministic output. `AbortError` propagates.
- Minimum 120-intent versioned corpus with exact/rare, paraphrase, unsupported, ambiguous,
  multilingual/cross-lingual, and adversarial strata; gates and rollout are fixed in the RFC.
