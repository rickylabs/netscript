# Generated BFF test import resolution

The BFF template now uses `@std/http/cookie` (consumer lint forbids inline registry imports); browser-auth reconciliation writes the consumer alias. Dynamic imports in Deno tests inherit the parent process map rather than the generated project map. Root `deno.json` must declare the same alias for isolated topology/conformance/auth-policy tests. Guarded-client docs and generated-guarded-service subprocess maps spread root imports, so the same root alias covers them without rewriting generated BFF behavior. `jsr:@std/http@^1/cookie` reuses the existing locked std/http resolution; no dependency upgrade. Adding the root alias requires exactly one workspace.dependencies metadata line in each of root deno.lock and packages/fresh-ui/deno.lock; native `deno install --lockfile-only --frozen=false` and `deno task --cwd packages/fresh-ui lock:update` write it. Verify all non-workspace lock fields remain equal, and explain the necessary metadata exception in the PR.

CI durable test reports are inside each `ci-check-test-shard-test-N-gate-receipts-<run>-<attempt>` artifact, named `test.report.json`; job console summaries alone do not expose all causes. Inspect `failures[].tests` across every red shard, then use run-deno-test.ts on that exact file set.
