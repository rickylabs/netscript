# 2026-10-31 — Prove conditional persistence through the consumer

A plugin's adapter schema pointer, static installer metadata and persisted infrastructure flags are separate surfaces. Selecting the backend only in the runtime adapter leaves install planning and schema copying wrong. Resolve a finite, plugin-declared selector before provisioning, specialize all metadata together and pass the exact selected value to scaffold/runtime configuration.

A negative control must inspect copied tables, not just a boolean. Source installs need source-package schema fragments; checking only generated userland directories can hide missing better-auth tables. Conversely, KV on an existing SQL project must add no auth fragment and switching backends must preserve existing consumer data.

A consumer init/install/generate/doctor check catches package-resolution gaps that contract-only tests miss. Do not substitute every local export in the fixture to make a failing consumer pass. Fix the actual local package alias seam and keep public-init and maintainer-init fixtures distinct.
