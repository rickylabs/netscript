# Watch lifecycle lessons — 2026-10-31

- A removed watch root can emit a remove event without throwing. Detect root loss before filtering requested file-event kinds; an invalid OS subscription must reach its supervisor.
- Opening the real native resource is the readiness boundary. Allocating a wrapper or waiting for a matching file event cannot establish useful watch health.
- Retry must release both the OS watcher and the external AbortSignal listener. Closing only the wrapper can leak a watcher per retry, and cancelling an iterator without closing its OS resource can deadlock drain.
- Per-source availability and aggregate processor readiness are separate facts. Missing user-created roots must be visible while unrelated sources remain usable; test the actual generated starter definition.
- Negative controls should alter behavior while keeping types intact. Real root recreation, permission-denied native setup, listener release, and health transport tests prove more than a fabricated iterator alone.
- Inspect browser failure diagnostics before changing UI code. A screenshot protocol failure with the other 139 tests passing cleared on retry without changing assertions.

- Readable metadata is not a successful polling scan: use the existing access-failure grace budget, and publish readiness only after a full scan succeeds.
- An external drain guarantee must not make callbacks await their own task. Use async callback scope to separate reentrant cancellation from external drain, and test both paths plus adapter reuse.
