The fencing works and is well tested against the real streams service. But turning on `producer` silently stops saving the native `newMessages` batch that main persists, so a fenced turn stores less than an unfenced one.

### Findings

1. **major: the fenced path drops main's native message persistence.** `packages/fresh/src/runtime/ai/fenced-chat-session-writer.ts:752-756`
   - **What:** Without `producer`, `defaultToResponse` (`create-chat-connection.ts:617`) echoes through `chatMessageChunks(newMessages)`. That writes the text echoes plus one `CUSTOM` `netscript.chat.messages` batch holding the full native UI/Model messages: attachments, tool calls/results, reasoning, metadata. The fenced writer calls upstream `toMessageEchoChunks` only, so the native batch is never written.
   - **Effect:** A worker-hosted fenced turn stores only reduced text. `createChatMessageReplay` / `resolveChatSnapshot` therefore cannot restore native parts or seed tool cards for that turn. The test fixes this behaviour in place (`ECHO_CHUNK_COUNT = 3` in `chat-producer-fencing_test.ts`; the unfenced path would write 4).
   - **Docs:** Neither the README nor `docs/site/ai/durable-chat.md` mentions it. Both still say native batches are persisted and present `producer` as only adding fencing. So the issue's "appends carry the tuple" holds only for a reduced payload, and producer is not "current behavior plus fencing".
   - **Fix:** In `writeEcho`, append `chatMessageChunks(input.newMessages)` (from `internal/chat-message-replay.ts`) so the native batch takes its own `seq` after the echoes. Then:
     - update the seq expectations (echo count 4);
     - add a regression in which a fenced turn with a non-text part (for example a tool-call or file part) round-trips through `resolveChatSnapshot` / the replay;
     - add a stale-epoch case showing the zombie's native batch is not stored either.

2. **minor: unrelated README reflow.** `packages/fresh/src/runtime/ai/README.md`

   - **Fix:** Revert the rewrap and keep only the `producer` paragraph and the two table rows.

     - Site docs "Appends go through the upstream transport exactly as before": the same inaccuracy.
   - **Fix:** Say "the default (unfenced) NetScript path is used unchanged". Once finding 1 is fixed, also state that fenced turns persist the same native batch.
