## 2. #1999 vs #2025 — unauthenticated `GET /api/v1/auth/me` → 400

**Verdict: still valid on main. #2025 duplicates #1999, which is canonical.**

### Root cause
- `packages/plugin-auth-core/src/contracts/v1/auth.contract.ts:340` defines `const meRouteInput = z.undefined().optional();` and uses it at lines 483-487 (`GET /me`).
- The OpenAPI GET adapter decodes the absent query string into `{}`. `z.undefined()` rejects that before the handler runs (stack trace in `@orpc/server@1.15.5`).
- `/session` uses `SessionInputZodSchema.optional()`, which accepts `{}` (lines 337-338).
- This is the only `z.undefined()` input anywhere in packages/ or plugins/.
- The handler itself would answer `{ authenticated: false }` (`plugins/auth/services/src/routers/v1-handlers.ts:291-307`).
- The schema is unchanged in published plugin-auth-core 0.0.7 and 0.0.8-canary.2.

### Reproduction (in-process, main)
The script `audit-work/1999/me_repro_test.ts` composes the service exactly as `plugins/auth/services/src/main.ts` does: real router, `withAuthRequest`, kv-oauth on `MemoryKvAdapter`, and `createPluginService` with the public opt-out and `openApi`, on port 0.

Command:
```
cd <main> && deno test --no-lock -A --config deno.json audit-work/1999/me_repro_test.ts
```
It passed (1 passed). The full log is in `audit-work/1999/repro.log`. Key output lines:
```
RESULT REST me, no credential :: GET /api/v1/auth/me -> 400 {"defined":false,"code":"BAD_REQUEST","status":400,"message":"Input validation failed","data":{"issues":[{"expected":"undefined","code":"invalid_type","path":[],"message":"Invalid input: expected undefined, received object"}]}}
RESULT REST me, synthetic-invalid bearer :: GET /api/v1/auth/me -> 400 (same body)
RESULT REST me, empty query string :: GET /api/v1/auth/me? -> 400 (same body)
RESULT REST session, no credential :: GET /api/v1/auth/session -> 200 {"authenticated":false}
RESULT RPC me POST, {} body :: POST /api/rpc/v1/auth/me -> 200 {"json":{"authenticated":false}}
RESULT RPC me POST, no body :: POST /api/rpc/v1/auth/me -> 200 {"json":{"authenticated":false}}
RESULT RPC me POST, {json:{}} body -> 400 (client explicitly sends an object; expected)
RESULT SDK typed RPC client.me() -> {"authenticated":false}
```
The REST body matches #2025's verbatim quote byte for byte.

**Doc contract:** `docs/site/tutorials/workspace/02-auth.md:251` says `curl .../api/v1/auth/me` returns `{ "authenticated": false }` before login. That settles #2025's "which outcome" question in favour of 200 with `{authenticated:false}`.

**Test gap:** `plugins/auth/tests/services/auth-service_test.ts:91,162` call the handler directly, so nothing tests the HTTP boundary.

### Canonical choice
**#1999 is canonical** because it is:
- earlier (2026-09-07);
- p1;
- reproduced on the published 0.0.7 native install;
- explicit that the regression must sit at the OpenAPI adapter boundary, and that RPC and OpenAPI must be checked separately.

#2025 adds the following, which should be carried into #1999:
- the verbatim body;
- the /session and 404 contrast;
- "the body must distinguish signed-out from malformed request";
- "any remaining 400 must name the missing input".

The consolidated acceptance draft is `canonicalAmendmentDraftFor1999` in `audit.json`. The duplicate-closure comment for #2025 is `closureCommentDraft` there.

**Leaf 1999-L1:** fixes lane, size S. It changes `meRouteInput`, which alters the type of `AuthContractDefinition['me']`; a no-argument `client.me()` call must still type-check. It also adds an HTTP-boundary test in `plugins/auth/tests/services/`.
