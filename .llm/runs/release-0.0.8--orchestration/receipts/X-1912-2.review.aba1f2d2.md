   - **Reproduced:**

   - **Fix:**

2. **major** — `installed-runtime-registry-generator.ts:133-147` together with `check-plugin-registries.ts:135-138`.
   - **What:** when a protocol-2 target renders `content: null`, generation skips the write but leaves the previously generated file in place. Check then reports that file as `extra`. Re-running `generate plugins` exits 0 ("1 written") and the check stays `drift`. No generator action can make the surface `current` again. The docs forbid hand-editing `.netscript/generated/**`, so the user has no sanctioned way out. The stale file also keeps importing deleted sources.
   - **Reproduced** (public CLI, writes denied for check):
     - AI tool edited into a non-tool, then `generate plugins`, then `--check`: `drift [{"path":".netscript/generated/plugin-ai/tools.registry.ts","kind":"extra"}]`.
     - Last `workers/jobs/*.ts` deleted, then regenerate, then check: `drift [{"path":".netscript/generated/plugin-workers/job-registry.ts","kind":"extra"}]`.
   - **Why the tests miss it:** `plugin check detects edits to an existing AI source…` asserts the `extra` finding but never regenerates. The skipped-AI test deletes the stale output by hand first.
   - **Fix:** for a `content: null` target, protocol-2 generation should remove an existing file at the declared path only when it carries this producer's exact marker. Alternatively, render an empty registry. Then add a test that does regenerate-then-check and expects `current`.
