The verbatim mode, the paged `full` mode, mode reporting and the benchmark all hold up and reproduce. Acceptance box 2 does not: on the real docs corpus, the extractor keeps whole prose paragraphs and drops the fenced code blocks that come after them. That is the failure #2010 describes.

### Findings

1. **major** — `packages/mcp/src/domain/docs/faithful-extraction.ts:29` (the `protected` classifier) and `:76-78` (greedy selection in document order). **What:** a paragraph counts as "protected" if it contains any inline backtick, any `[...]`, any URL, or any line starting with `word:`. Most prose paragraphs match. All protected blocks then compete in source order on equal terms, so intro paragraphs that mention inline code use up the 12 KiB budget before the later fences, commands and config blocks get a turn. Measured over the site corpus at this head: 93 documents go to `extract` mode. Across them, 91 of 412 fenced blocks are dropped, 1,917 prose paragraphs are kept whole (about 915k characters), and 39 documents lose fences while keeping unreduced paragraphs that contain inline code. Examples:
   - `reference/ai` keeps 2 of 12 fences and 6 of 29 headings.
   - `tutorials/storefront/02-catalog-service` drops a 26-character fence and keeps 0 of 9 headings.

   Counted over extract-mode documents only, the fallback proxy is 0.76 and the token ratio is 0.78. That is exactly the "material past the cut" problem the issue describes, and it contradicts the box: "Fenced code blocks, command invocations, config keys and outbound links are carried through verbatim … only prose around them is reduced." The acceptance-2 test misses this because its filler prose contains no inline code or links. **Fix:**
   - Select in tiers. First fences, command lines and config-key lines (cheapest-first, or by section, so one early oversized block cannot starve the rest). Then heading lines. Then link or inline-code prose, reduced to the sentence that holds the protected span. Then plain first sentences.
   - Add a negative-control test: several over-budget paragraphs containing inline code and links before a late fence must still return the fence and the headings.
   - Report the benchmark table for extract-mode rows separately.
2. **minor** — `packages/mcp/src/application/runner/mcp-server.ts:140,164` and `packages/mcp/src/application/tool-registry.ts:75`. **What:** the generic runner and the registry hard-code `tool.name === 'get_doc'` to bypass truncation, check the response envelope and replace the description. That violates open/closed. The intake asked for a per-tool policy. **Fix:** give each tool definition its own truncation and description policy (for example `truncation: 'exempt'` plus `envelopeCheck: true`), set on `get_doc`.
3. **minor** — `packages/mcp/src/infrastructure/filesystem-docs-corpus.ts:123-125,227-229,296-298`. **What:** one oversized source throws a plain `Error` while the whole corpus is being processed. That takes down `search_docs`, `list_docs` and `find_guidance` along with `get_doc`, and the caller only sees the opaque `docs_corpus_error` with no file named. The public `maxDocumentLength` option and the `MAX_INDEXED_DOC_LENGTH` export (`mod.ts:144`) have also changed meaning: they used to truncate and now reject. **Fix:** throw a typed error that names the slug, and reject only the offending document (or skip it during indexing). Record the change to the public option's meaning in Drift.
4. **minor** — `packages/mcp/benchmarks/doc-retrieval.ts:88,146-155`. **What:** the retention and fallback figures are averaged over all documents, including the verbatim ones that pass trivially. "Snippets" are defined by the extractor's own over-broad `protected` classifier, so the benchmark grades itself. The PR table (snippet retention 0.81, fallback 0.41) therefore overstates how well extraction works. **Fix:** report extract-mode-only aggregates. Measure fences, commands and links with a classifier independent of the extractor.
5. **nit** — `packages/mcp/src/application/runner/mcp-server.ts:27`. The server instructions still say "`get_doc` for exact retrieval". The CLI guidance template was updated, but this text was not, and extract mode is not exact.
6. **nit** — `faithful-extraction.ts:87`. Retained blocks already end with their own blank-line separators, and joining them with `'\n\n'` adds more, so the extract has extra blank lines.
7. **nit** — in `get-doc-flow.ts:84`, a section-scoped extract returns the outline of the whole document rather than of that section. This is not documented.
