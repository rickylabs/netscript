### Findings

1. **minor** — `packages/cli/src/kernel/adapters/config/plugin-manifest/configured-plugin-manifest-probe.ts:36-46`. The plugin-manifest probe used to run with `--allow-all` and the lockfile. It now runs with `--allow-read/env/net --deny-write --deny-run --no-prompt --no-lock` for normal generation as well as inspection. The Drift/Debt section does not mention this.
   - Effect on third-party plugins: a plugin whose import graph touches `sys`/`ffi` at import time now drops to the degraded probe path in normal generation and fails in `--check`.
   - Effect of `--no-lock`: the probe can resolve a plugin version other than the locked one.
   - First-party plugins are not affected. All six (ai, auth, sagas, streams, triggers, workers) resolve under the new flags; I checked this locally.
   - Fix: record the change in Drift/Debt. Consider `--frozen` instead of `--no-lock` so the lockfile is still respected but never written.
2. **minor** — `packages/cli/src/public/features/generate/aspire/generate-aspire-command.ts:33`. On the `--check` path, `checkAspire` gets an injected formatter but no `process`. The config and plugin probes therefore fall back to a fresh `DenoProcess`, while the formatter uses `dependencies.process`. Fix: pass `process: dependencies.process` so both use the same injected seam.
