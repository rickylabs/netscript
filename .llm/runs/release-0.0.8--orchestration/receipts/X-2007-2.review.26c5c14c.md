### Findings
1. **minor** — `packages/cli/src/public/features/init/init-command.ts:162-173`: the agent install runs after the scaffold has succeeded, and nothing guards it.
   - **What:** if `initAgent` throws, the command exits non-zero after the project has already been written. Triggers include both `.zed` and `.vscode` existing when re-initialising with `--force`, or a malformed existing `.mcp.json`/`opencode.json`. In `--json` mode this error follows the single JSON result that was already printed. The user gets no hint about how to recover.
   - **Fix:** catch the error, name the recovery (`netscript agent init --host <h>`, or re-run with `--no-agent`), and decide deliberately whether the exit code should be non-zero.
2. **minor** — `packages/cli/src/public/features/root/public-command-dependencies.ts:313-319`: the adapter wiring is duplicated.

Each copy is its own composition point. The integration fixture also overrides `initAgent`, so no test exercises the production closure.
   - **Fix:** have `agent-group.ts` reuse `dependencies.initCommandDependencies.initAgent`, or share one factory.
