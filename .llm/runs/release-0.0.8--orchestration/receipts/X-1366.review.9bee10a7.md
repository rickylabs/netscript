The L1 contract and L2 runtime wiring are sound and the scoped gates reproduce green, but the new child wrapper hides fatal bootstrap errors completely, and the tests add an `as unknown as` cast that the review rules forbid.

### Findings

1. **major**: `packages/plugin/src/presentation/run-child-health-process.ts:42-56`. The wrapper drops fatal bootstrap errors without logging them, and the failed process never exits.
   - **What:** `failed` takes no argument, so the rejection reason of `run` is discarded. Nothing is logged. The process then waits for SIGTERM forever and exits 0.
   - **Reproduced:** `PORT=0 deno run --no-check -A --unstable-kv packages/plugin/tests/health/fixtures/child-process.ts registry-failed` prints only `Listening on …`. There is no error output and it is still running at the timeout (exit 124).
   - **Before this PR:** the workers and triggers glue was a top-level `await startCombinedProcess()`. A registry, KV or bootstrap failure printed a stack trace and exited non-zero, so Aspire showed the resource as Exited with the cause in its logs.
   - **Now:** the generated AppHost probes only the sagas runner (`generate-register-background.ts:135-141`). The rule-based child probes are L3 and still deferred. So a dead workers or triggers child shows as **Running**, has no error in its logs, and serves a 503 that nothing reads. That is less visible than main, which is the opposite of #1366's goal.
   - **The PR body is inaccurate here:** it says "original raw errors remain available to existing in-process diagnostics". That is true for listener failures (`reportListenerFailure`), but not for errors caught by this wrapper.
   - **Fix:**
     - Pass the cause to `failed(cause)` and `console.error` it on the server side. Redaction is only required for the public payload.
     - Set `Deno.exitCode = 1` so a later shutdown is not reported as clean.
     - Either exit after a bounded grace period, or keep exit-on-fatal for children the AppHost does not yet probe, until L3 lands.
     - Add a test that the cause reaches stderr and is absent from the payload.
2. **major**: `plugins/workers/worker/listener-supervisor_test.ts:26`. New `as unknown as` cast, which review rule 8 forbids.
   - **What:** `listener.snapshot()` is already typed with `childHealth` on this branch. The cast exists only so the test runs against main for the negative control.
   - **Fix:** use `listener.snapshot().childHealth` directly. A type-check failure on main is still a valid failing negative control. If a runtime negative control is wanted, keep it in the run record, not in shipped tests.
3. **minor**: `plugins/triggers/src/runtime/trigger-child-health_test.ts:55`. `kv as never` is the same kind of type-escape cast. Use a typed stub instead, for example `Pick<Kv, 'get'>` through a narrow port, or a fake implementing the interface.
4. **minor**: `packages/plugin/src/runtime/child-health-monitor.ts:69` together with `plugins/workers/worker/listener-supervisor.ts:55`. With the listener's default backoff (100/200/400 ms), three restarts happen in under 1 s. A brief Redis blip or failover therefore latches `crash-looping` (HTTP 503) for the rest of the child's life, even after the child recovers. The coordinator chose the threshold; making the latch permanent was the author's choice. Either document the operator expectation (manual restart), or let the latch clear after a full clean window. Revisit this when L3 wires the probes.
5. **minor**: `packages/plugin/tests/health/child-process_test.ts:2`. Inline `jsr:@std/async@^1` specifier. Add `@std/async` to `packages/plugin/deno.json` imports, or drop it. Line 30's `await delay(30)` is a timing sleep: bootstrap state is already settled in a microtask before `onListen`, so it can be removed.
6. **minor**: `plugins/workers/src/aspire/workers-contribution.ts:79` and the sagas/triggers `declareHealthChecks` implementations. These overrides of the now-`@deprecated` base method are not marked deprecated, and they still advertise the API `/health` as the plugin's health. Mark them `@deprecated` to match the base, or track them in the L3 follow-up.
7. **minor**: the workers and triggers children now bind a health listener on `0.0.0.0` at a random port (no `withHttpEndpoint` / `PORT` from the AppHost) that nothing probes until L3. The payload is bounded and redacted, so this is low risk, but say so in the Drift section.
8. **nit**: `plugins/workers/src/adapter/resources/glue/runtime.stub.ts`. The removed glue header held a warning against re-resolving the registry path ("a second resolver is how a compiled job ends up missing"). Keep it.
9. **nit**: sagas startup failures inside `createDefaultRuntime` (the KV probe) report `registryReady: false` even though the registry did load, because `registryLoaded()` follows `runtime.register`. In the wrapper path, `registryReady` is always false when `startSagaRunner` throws.
