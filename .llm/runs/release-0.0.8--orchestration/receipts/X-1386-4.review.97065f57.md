1. **blocker** — `packages/cli/src/kernel/adapters/plugin/browser-auth-reconciler.ts:97`: the `allowAnonymous` list the PR injects does not match the paths the scaffold actually serves.
   - **What:** It injects `['/health', '/api/v1/${router}', '/api/rpc/v1/${router}']`. Generated REST routes come from `createCrudContract({ resource: '<service>' })` (`packages/contracts/crud/create-crud-contract.ts:351-375`) under the `/api` prefix, so they are `/api/<service>` and `/api/<service>/{id}`. The path `/api/v1/<router>` does not exist. The authn middleware is registered before the OpenAPI and docs routes (`service-builder-impl.ts:511` vs `:551/:563`), so those are guarded too.
   - **Reproduced** with `createService` plus the remote verifier and this exact list, for a `users` service:

     | Path | Status |
     | --- | --- |
     | `/api/users` | 401 |
     | `/api/users/health` | 401 |
     | `/api/openapi.json` | 401 |
     | `/api/docs` | 401 |
     | `/api/rpc/v1/users/list` | 200 |
     | `/api/v1/users` | 404 |

The golden test only checks that the substring `authenticator: browserAuthenticator` appears. The conformance test uses a hand-built service, so it never exercises the generated policy.
   - **Fix (preferred):** Express publicness through the existing procedure-policy seam (`access: { authentication: 'none' }` meta on the generated demo contract), not through path prefixes.
   - **Fix (minimum):** Derive the prefixes from the real resource path (`/api/<serviceName>`, `/api/rpc/v1/<camelCase>`) and decide explicitly whether `/api/openapi.json` and `/api/docs` stay public.
