The binding, hook, Expo wrapper and docs are sound, and every gate I re-ran reproduces. One major finding blocks the merge: a new `as unknown as` in the SDK tests. It is the first one in `packages/sdk`, and it hides the fact that the public collection type can't be passed to TanStack's query builder.

### Findings

1. **major**: `packages/sdk/tests/streams/stream-collection_test.ts:75`
   - **What:** `binding.collection as unknown as Collection<Task, string>` is a new double cast, which criterion 8 forbids. `packages/sdk` has none on `origin/main`.
   - **Why it matters beyond the test:** the cast shows that the public `StreamCollectionV1<T>` cannot be used in `q.from(...)` without unsafe casting. `docs/site/reference/sdk/index.md` says "`StreamCollectionV1<T>` is a real TanStack DB collection". That holds at runtime but not at the type level. A React Native consumer who needs a filtered, joined or projected live query has to copy this cast. Only a whole-collection live query works without one, through `useStreamLiveQueryV1`.
   - **Fix:** narrow with TanStack's own type guard instead of casting. `isCollection(value): value is Collection<any, any, any>` is in `@tanstack/db` 0.6.17 (`live-query-adapter.d.ts:20`), and the hook already uses it. Alternatively, export a typed accessor or adapter from `@netscript/sdk/streams/collections` and use it in the test. Then either fix the reference-doc sentence or document the query-builder limitation as public-surface debt. The PR's Drift section mentions "rich upstream query-builder types" but not the cast or the doc claim.

2. **minor**: `packages/sdk/src/client/stream-collection/application/create-stream-collection.ts:56-90`
   - **What:** a fatal source error, such as an invalid entity or a non-retryable `error` event, is thrown inside `onEvent`, so TanStack never sees it. If this happens before the first `upToDate`/`streamClosed` control:
     - `collection.status` stays `loading` and `collection.preload()` never settles.
     - `StreamLiveQueryResultV1` has no `error` field, so the hook shows `isLoading: true` forever.
   - The how-to tells callers to watch `binding.done`, but the `preload()` hang is not documented.
   - **Fix:** do one of the following, in a follow-up if preferred:
     - call TanStack's error path (`markReady` + error status) when `done` rejects;
     - document that `preload()` can hang on a fatal error before the first control;
     - add an `error` field to the hook result.

3. **minor**: `packages/sdk/src/client/stream-collection/ports/stream-collection.ts:44`
   - **What:** the public port exposes `cleanup()`. `gcTime: Infinity` stops TanStack's garbage collector from cleaning the collection up, but an explicit `cleanup()` call still works. A later subscriber, such as a remounted hook, restarts TanStack sync. The `sync` callback then calls `bindStreamEventSourceV1` again on the single-use `source`, which was already cancelled.
   - No test covers this path.
   - **Fix:** do one of the following:
     - drop `cleanup` from the port and keep `binding.dispose()` as the only teardown;
     - make the `sync` callback refuse to restart after disposal;
     - add a test proving the behaviour.

4. **minor**: two materializers now exist side by side.
   - **What:** issue #2100 item 3 asks for "the same stream-to-collection / live-query binding the web SDK uses". The web path is `@netscript/fresh` `createNetScriptStreamDB`, built on `@durable-streams/state` `createStreamDB`, multi-type `StateSchema` and a recovery adapter with a `failed` status. This PR adds a second, single-type materializer in the SDK. That is a reasonable result of L1 (#2212) putting the fetch source in the SDK, and both share TanStack DB. But it is a new parallel seam, and its semantics may drift from the web path's (status, failure, schemas).
   - **Fix:** record it as drift or debt in the PR, with a follow-up to converge or document the two paths.

5. **nit**: version skew and a deprecated test dependency.
   - React versions differ: tests pin `npm:react@19.2.8`, while the reference app pins `react@19.2.3`, including `jsxImportSource`.
   - `react-test-renderer` is deprecated upstream for React 19.
   - Consider aligning the pins. The test dependency can stay for now.

6. **nit**: `packages/sdk/src/client/stream-react/use-stream-live-query.ts:41`
   - **What:** after the `isCollection` guard, the code adds `as Collection<TData, string> & NonSingleResult`. It is a single `as`, which rule 8 allows. Moving the guard into a typed helper would remove it.
