**New at this head**

11. **minor** — `packages/plugin-sagas-core/src/stores/saga-kv-retention.ts` (`sagaRetentionRemaining`) and `packages/plugin-triggers-core/src/stores/kv-trigger-runtime-stores.ts` (`remainingRetention`). **Fractional retention days break Deno KV writes.**
   - **What:** these functions compute `days * 86_400_000` with no rounding. Deno KV rejects a non-integer `expireIn` (`TypeError: expireIn must be a non-negative integer`).
   - **Why it's reachable:** the root `@netscript/config` schema accepts `completedDays: z.number()` and `kvDays: z.number()`. The sagas core schema adds only `min(1)`.
   - **Effect:** a value such as `1.1` or `2.3` days makes every terminal saga save, or terminal trigger save, throw on Deno KV. Integer values, and fractions like `1.5`, are unaffected.
   - **Fix:** wrap the result in `Math.ceil`, or add `.int()` to the config schemas. A follow-up PR is fine.

12. **nit** — `plugins/sagas/src/runtime/saga-runner.ts`. When neither env nor appsettings sets a backend, the runner defaults to `kv`, while the service throws. Consider sharing one resolver so the two cannot drift.

13. **nit** — `KvSagaAppliedKeyStore.record` now throws `retry the message` when the state changes concurrently. This matches the store's existing optimistic version-mismatch semantics; a note in the README would help.
