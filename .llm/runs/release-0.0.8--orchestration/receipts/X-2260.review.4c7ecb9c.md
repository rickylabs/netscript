### Findings

1. **minor** — `.llm/tools/deps/bump-version.ts:179`: the bump can silently skip the root lock when the checkout sits inside an excluded folder.
   - **What:** `discoverVersionFiles` tests `RELEASE_SCAN_EXCLUSIONS` against the absolute path (`join(root, path)`), not the path relative to `root`.
   - **When it bites:** the checkout lives under a folder that matches an exclusion: `.claude/worktrees/`, `.llm/tmp/`, `.llm/runs/`, `fixtures/`, `.data/` or `node_modules/`. The repo's documented scratch folder is `.llm/tmp/`, so this is a realistic place for a local dry-run. In that case the root lock and member locks drop out of the bump set.
   - **Reproduced:** a git repo at `…/.claude/worktrees/rel/` with a tracked `deno.lock`. Main includes `deno.lock` in the bump set; this PR leaves it out.
   - **Why it's silent:** `findVersionResidue` already had the same absolute-path blind spot on main (residue was `[]` in both cases). `auditLockstepAndResidue` uses the same discovery, so neither gate catches the missing lock.
   - **Why not a blocker:** the CI release path (`release-canary.yml` on a GitHub runner) and the disposable `$TMPDIR` checkouts used for dry-runs are not affected.
   - **Fix:** test `relative(root, path)` in the tracked-files loop, and pass relative-path matching to both `walk` calls. Add one regression test with the root under `.claude/worktrees/`.
2. **nit** — `bump-version.ts:39`: `RELEASE_SCAN_EXCLUSIONS` is now shared by discovery and the residue scan, but it is typed as a mutable `RegExp[]`. Prefer `readonly RegExp[]`.
3. **nit** — `bump-version.ts:184-189`: the fallback walk has both `match: [/deno\.lock$/]` and an `entry.name === 'deno.lock'` check. They are redundant; keep one, or anchor the regex on a path separator.
4. **nit** — `bump-version.ts:57`: the JSDoc for `coordinateVersionBump` still says "scaffolds, and lock". It now covers every tracked live lock.
5. **info** — CI:
   - `close-gate` is red. That is expected: the mirror only runs once `status:ready-merge` is applied, which the coordinator does.
   - The `check-test-shard` jobs and `quality` were still pending when this review ran.
   - The PR body has no leaked local paths or hostnames.
