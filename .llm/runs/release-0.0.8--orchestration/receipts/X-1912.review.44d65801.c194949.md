The latest main merge put a write to authored files back inside `generate aspire`. Main's browser-auth reconciler (#2221) now runs inside `regenerateAspireHelpers`. In any project with the auth plugin it can rewrite `appsettings.json` and service source files. This PR's adopted decision and its docs say generation never does that, and `--check` cannot see those writes. Everything else holds: the CLI tree type-checks clean, 597 affected tests pass, and every carrier is fresh.

### Findings

1. **major**: `packages/cli/src/kernel/adapters/service/workspace-mutator.ts:145-147` (merge resolution) and `packages/cli/src/kernel/adapters/plugin/browser-auth-reconciler.ts:140-143`
   - **What:** Main's #2221 put `reconcileBrowserAuth` inside `regenerateAspireHelpers`. The merge kept it there, so non-dry-run `generate aspire` now runs it before rendering. When an auth plugin is configured, the reconciler:
     - rewrites matching service sources to wire `browserAuthenticator`;
     - adds the auth plugin to `PluginReferences`;
     - re-serialises the whole `appsettings.json` whenever its bytes differ from `JSON.stringify(..., 2)`.
   - **Conflict with this PR:** For auth-plugin projects this breaks:
     - the #1912 decision this PR adopted ("generation never writes authored inputs");
     - its docs, `docs/site/reference/cli/commands.md` §Aspire generated-surface check: "Root `appsettings.json` remains an authored authority… generation reads that configuration";
     - its claim that normal generation preserves authored `appsettings.json` bytes.
   - **Why `--check` is affected:** The inspection renderer does not run the reconcile. In an unreconciled project, `--check` can say `current` while `generate aspire` would change `PluginReferences`, and with them the `register-services` output. A check that reports current while generation would still change bytes defeats its purpose.
   - **Tests miss it:** The existing hostile and authored-formatting tests use no auth plugin.
   - **Fix:** Give the browser-auth reconcile the same treatment this PR gave `reconcilePluginReferences`:
     - Move it out of `regenerateAspireHelpers` into the flows that own it: plugin install/remove and service add/remove. `generate aspire` then only reads authored inputs.
     - Correct the docs if any part of it stays in generation.
     - Add a negative-control test: a project with the auth plugin and non-canonically formatted `appsettings.json`, where `generate aspire` leaves `appsettings.json` and service sources byte-identical and `--check` stays `current` afterwards.

2. **minor (procedural)**: The PR body's Definition of Done box is unticked, so `close-gate` stays red. The coordinator ticks it after evaluation and runtime evidence.
