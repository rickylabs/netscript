Verdict: REVISE at adb562c123b90968858456bff7fd2351935cc9be

The stdin channel itself is well built, follows the existing seams, and is proven by 13 tests that genuinely fail on main. But the PR also turns the issue's *optional* output caps into a 1 MiB kill limit for every polyglot task and queued job, so healthy tasks that print a lot of logs now fail.

### Findings

1. **major** — `packages/plugin-workers-core/src/executor/adapters/dax-process-runner.ts:76-77, 151-158, 168-172`: output caps are on by default and kill healthy tasks.
   - **What:** `outputLimit()` defaults to 1 MiB, and `streamOutput` kills the subprocess once the *total bytes read* pass that limit. This applies to every runtime (deno, python, shell, dotnet, executable), including queued polyglot jobs (`plugins/workers/worker/job-execution.ts` `executePolyglotTask`) and registry tasks (`job-dispatcher.ts`). Neither path passes a limit, and no job or task definition field can raise it. The adapter-level override exists only on `ExecutableRuntimeAdapter`.
   - **Issue mismatch:** #2110 asks for "*Optional* stdout/stderr byte caps on the executable runtime".
   - **Repro (run in this review):** a default-executor task that streams about 2 MiB of progress lines and then prints `{"done":true}`, with an `onStdout` consumer attached:
     - main: `{"status":"completed","success":true,"exitCode":0,"result":{"done":true}}`
     - branch: `{"status":"failed","success":false,"exitCode":-1,"error":"StdoutLimitExceeded: output exceeds 1048576 bytes."}`
   - Any long-running ETL or ML job with chatty logs now fails and retries in production. The CHANGELOG does not flag this as breaking.
   - **Fix:** keep memory bounded without killing anything. By default, cap the *retained* `stdout`/`stderr` buffers (truncate, and keep the tail so the last-line JSON result still parses), but keep reading and streaming. Fail closed with `Stdout/StderrLimitExceeded` only when the caller sets `stdoutLimitBytes`/`stderrLimitBytes` (execution option or adapter option). Add a test proving a chatty task with no caps set still completes, and that it fails on the current head.

2. **minor** — `packages/plugin-workers-core/deno.json` imports: `@david/dax` is now unused anywhere in the package (src or tests), but it is still declared. Remove it, or record it as debt in the PR's Drift / Debt section. "No lock churn" does not justify leaving a dead dependency.

3. **minor** — `runtime-adapter-base.ts:60-64` and `dax-process-runner.ts:70-76`: the stdin precedence rule is written twice, and the payload is copied up to four times per execution.
   - **Copies:** builder `slice` → `build()` `slice` → adapter `encodeTaskStdin` → runner `encodeTaskStdin` again on an already-encoded `Uint8Array`.
   - **Fix:** resolve precedence once, in the adapter. In the runner, treat `input.stdin` as already-encoded bytes and only check its size.

4. **minor** — `dax-process-runner.ts:59-66`: `stop()` sends SIGKILL to the direct child only. A shell or `cmd` wrapper's grandchild can keep the stdout/stderr pipes open after a timeout or abort, so `Promise.all` can hang after `failure` is set. Main had a similar exposure. Consider cancelling the readers in `stop()`, or bounding the wait after the kill.

5. **minor** — Windows: moving from Dax's command resolution to plain `Deno.Command` drops Dax's PATHEXT-aware lookup, so `.cmd`/`.bat` shim entrypoints may stop resolving. The PR has no Windows evidence. Either verify, or note it in Drift / Debt.

6. **minor** — docs (`polyglot-tasks.md` "Send private input on stdin", and `run-a-polyglot-task.md` §2a):
   - "the phone and web app need not remain open" is internal golden-rule wording and makes no sense to framework users. Drop it.
   - Say plainly that builder `.stdin()` applies only when you call the executor directly. KV registration (`registerTask` validates through zod, which strips the field) and queue dispatch do not carry it.

7. **nit** — `TaskStdin`/`TaskStdinJson` are re-exported from seven barrels as separate trailing `export type` statements. They should be merged into each barrel's existing grouped `./task.ts` export block.

8. **nit** — `polyglot-task-execution.svg`: only the diagram's alt text and caption were updated to mention stdin; the image itself presumably still shows only argv + env.

9. **nit** — the PR body says "No `e2e-cli-gate` label was added", but the label is now on the PR (presumably added by the coordinator). Worth a one-line correction so the body stays accurate.

The PR body has no public-hygiene leaks (no local paths, hostnames, or tokens).
