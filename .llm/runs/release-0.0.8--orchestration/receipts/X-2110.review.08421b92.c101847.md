All nine earlier findings are resolved or recorded as debt. But the process-tree fix added one new regression: `detached: true` puts each task in its own POSIX process group, so pressing Ctrl+C on a worker or the `ns-workers` CLI no longer stops running polyglot tasks.

### Findings

1. **major (new)** — `packages/plugin-workers-core/src/executor/adapters/dax-process-runner.ts:83-84` (`detached: Deno.build.os !== 'windows'`): task processes are orphaned when the worker gets Ctrl+C.
   - **What:** the task now runs in its own process group, so signals sent to the parent's process group no longer reach it. That covers terminal Ctrl+C on `deno task dev` or an `ns-workers` CLI run, and any supervisor that signals the whole group.
   - **Why it bites:** nothing in the workers stack (`plugins/workers/worker`, `plugins/workers/bin`, `plugins/workers/src/cli`, `plugin-workers-core`) installs a SIGINT/SIGTERM listener that would abort running tasks. The worker dies, and the task tree keeps running unsupervised. Its result is never recorded, and the job can be retried on the next start, which risks duplicate side effects. The graceful-stop path (`worker.ts` `waitForActiveJobs`) never runs when the process is signalled.
   - **Repro (run in this review):** a `setsid` parent runs `createDefaultTaskExecutor().execute({ type: 'executable', entrypoint: 'sh', args: ['-c', 'echo $$; exec sleep 41'] })`, then SIGINT is sent to the parent's process group.
     - origin/main: the task process dies with the worker.
     - this head: the task process stays alive and is orphaned.
   - **Fix (either):**
     - **(a) Recommended:** drop `detached`. In `terminateProcessTree`, walk the descendants of the owned `child.pid` (Linux `/proc/<pid>/task/*/children`; macOS `pgrep -P`, recursively) and SIGKILL them leaves-first, then the child. Keep `taskkill /T` on Windows.
     - **(b)** Keep the dedicated group, but while owned children are live, register SIGINT/SIGTERM/SIGHUP listeners that terminate those groups, then restore the default disposition and re-raise.
   - **Test:** add a Linux-only regression test (group SIGINT to a `setsid` parent → the task PID is gone), using owned PIDs only. It must fail at this head.

2. **minor** — `src/executor/adapters/dax-process-runner.ts:41-42, 73-74` and `src/executor/output-tail.ts:9-12`: wasted allocation on every run.
   - `OutputTail` eagerly allocates a 1 MiB `Uint8Array` per stream, so every execution pays 2 MiB however little it prints.
   - The placeholder tails created before `try` are thrown away and re-created, so each run allocates 4 MiB.
   - **Fix:** grow the ring lazily up to the cap, and create the tails once.

3. **minor** — `src/builders/task-builder.ts:292`: `build()` now hands out the builder's own `Uint8Array`.
   - Every built task, and the builder itself, shares one mutable buffer (the new test asserts this identity on purpose). A caller that mutates `task.stdin` silently changes later builds.
   - **Fix:** either copy once in `build()` (1 MiB at most, paid per build rather than per run), or document that the buffer is shared and must be treated as read-only.

4. **minor** — the Windows verification debt (previous finding 5: `taskkill /T`, and `Deno.Command` not doing Dax's PATHEXT `.cmd`/`.bat` lookup) is recorded only in the PR body. Track it in a follow-up issue or a doctrine debt entry so it outlives this PR.

5. **nit** — `src/public/root.ts:2`: the `export type { TaskStdin, TaskStdinJson }` line sits in the middle of the import block. Move it into the file's export section.

6. **nit** — `OutputTail.text()`: when the tail cut lands inside a UTF-8 sequence, decoding yields a leading U+FFFD. This is harmless, but you could skip the leading continuation bytes.
