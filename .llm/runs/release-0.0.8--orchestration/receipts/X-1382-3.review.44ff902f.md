### Findings

1. **blocker**: `packages/cli/src/kernel/assets/service/routers/v1.ts.template:9` and `routers/v1.memory.ts.template:9`
   - **What:** the template calls `.$context<ServiceHandlerContext>()` on a leaf procedure implementer (`v1.<svc>.session`). oRPC's `ProcedureImplementer` has no `$context` member, because `$context` exists only on the root implementer. Every service generated from these templates fails its own `deno task check`:
     - `TS2339 Property '$context' does not exist on type 'ProcedureImplementer<…, ZodObject<{ authenticated: ZodBoolean }>…>'`
     - `TS7031 Binding element 'context' implicitly has an 'any' type`
   - **Evidence:** CI `check-test-shard (test-5)` fails on this head. Both cases in `packages/cli/e2e/tests/application/gates/service-handler-generated_test.ts` fail ("add-handler binds and type-checks a real memory/prisma ServiceScaffolder project"). Main CI at the merge base `a1ac07a4f` is green, so this PR introduced the failure. It also puts the generated-workspace type-check step of `scaffold.runtime` at risk.
   - **Fix:** use the documented root-implementer idiom (`docs/site/tutorials/workspace/05-route-authz.md:206`): `session: v1.<svc>.$context<ServiceHandlerContext>().session.handler(({ context }) => …)`. Alternatively, export a context-typed implementer from the contract template. Add `service-handler-generated_test.ts` to the PR's validation set.

2. **major**: `packages/cli/e2e/tests/application/gates/scaffold/generated-browser-auth-policy_test.ts:217-224`, plus the PR body's Validation section and DoD.
   - **What:** the body says "Generated templates are type-checked after rendering by the executable integration proof", and the DoD box "Required local gates are green…" is ticked.    - **Fix:** after fixing finding 1, find out why this check accepts invalid code, or rely on the real-scaffold check. Then correct the DoD/Validation text to match a green CI head.

3. **minor**: `packages/cli/src/kernel/adapters/plugin/browser-auth-reconciler.ts:85`
   - **What:** the reconciler decides whether to emit the app route by regex-sniffing the contract source (`/\bsession:\s*baseContract\b/`). This is a fragile text heuristic. A reformatted or renamed builder silently skips the route, and a comment or string match can emit a route against a contract that has no `session`.
   - **Fix:** acceptable for now. Prefer a structural marker (a template-owned sentinel or a manifest/settings flag), or at least record it as debt.
