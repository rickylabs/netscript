Verdict: REVISE at 801118fe27a9935886da48045e42bb718af572a8

The retention design is sound: terminal-anchored TTL, atomic record/index pairs, and open replay data kept until terminal. But this head has two blockers and two majors: the saga retention sweep breaks on the production Deno KV adapter, the gate claims don't reproduce at this head, the Prisma-backed sagas API loses its query model, and the remaining-scope list leaves out one key family.

### Findings

1. **blocker** — `packages/plugin-sagas-core/src/stores/saga-kv-retention.ts:85-89`. **The saga retention sweep exceeds Deno KV's 100-check limit.**
   - **What:** each `cleanup()` page puts these checks in one atomic op: the cursor, the state key, and one check per listed entry (`...entries.map(...)`). The default `limit` is 100, so up to 102 checks. Deno KV allows at most 100. `DenoKvAdapter.atomic` passes checks straight through.
   - **Reproduced:** with `DenoKvAdapter` over `Deno.openKv(':memory:')`, one saga instance with 120 `Tick` messages, then `Done`, then `store.cleanupRetention()`, the call throws `Too many checks (max 100)`. Any terminal instance with 99 or more transitions or applied keys triggers it.
   - **Consequences in `plugins/sagas/src/runtime/create-durable-saga-runtime.ts`:**
     - `:133` runs `await store.cleanupRetention()` during startup, so the saga runtime fails to start whenever such an instance is the next cursor.
     - `:150` stores the first rejection in `failure` and ends the background loop for good. Retention stops silently until `stop()` rethrows the error.
   - **Why tests miss it:** they only use `MemoryKvAdapter`, which has no check limit.
   - **Fix:**
     - Cap the page so checks plus mutations stay within Deno KV limits (for example, entries ≤ 98), or stop checking entry versionstamps one by one.
     - Make the loop log the error, back off and keep running on a transient failure instead of ending.
     - Don't let the startup sweep fail runtime start.
     - Add a test that uses the Deno KV adapter.

2. **blocker** — `packages/fresh-ui/deno.lock` (not updated). **`arch:check`, `quality:gate` and CI fail at this head; the PR body says they pass.**
   - **What:** this PR adds `@netscript/config` to `plugins/sagas` and `plugins/triggers`. That leaves the Fresh UI private lock out of date: `FAIL DEPS-PRIVATE-LOCK packages/fresh-ui/deno.lock workspace drifts from root deno.lock at members.plugins/sagas, members.plugins/triggers`.
   - **Locally:** `deno task arch:check` and `deno task quality:gate` both exit 1.
   - **CI:** `code-quality`, `fresh-ui-quality`, `check-test-shard (test-5)` and `check-test` all fail on the same out-of-date lock (`The lockfile is out of date … +"jsr:@netscript/config@0.0.7"`).
   - **PR body:** the Validation table says `quality:gate` and `arch:check` both exited 0, and the Definition of Done says "Every required local gate is green". Neither is true at this head.
   - **Fix:** run `deno task --cwd packages/fresh-ui lock:update`, commit the lock, and re-paste real gate output.

3. **major** — `plugins/sagas/src/runtime/saga-runner.ts:183` with `plugins/sagas/src/runtime/saga-instance-projection.ts:122` and `plugins/sagas/src/runtime/load-saga-retention.ts:25,31`. **The Prisma-backed sagas API loses its query model.**
   - **What:** `PrismaSagaInstanceProjection` now skips writes unless `archiveToDb` is true. Both the schema default and `loadSagaRetention` default it to `false`.
   - **Why it breaks:** with `--saga-store-backend prisma`, `plugins/sagas/services/src/main.ts:85` sets `useKvProjection = false`. `listInstances` then reads `db.sagaInstance`, the table that only this projection fills.
   - **Effect:** on a default config, a Prisma-backed sagas API returns no instances. The stream mirror's `sagaInstance.findMany` hydration also comes back empty.
   - **Coverage:** the new test `archiveToDb: false prevents Prisma writes` locks the regression in. E2E only runs `--saga-store-backend kv`, so it doesn't catch it.
   - **Fix:** keep the Prisma read model whenever it is the API's query source (prisma backend). Alternatively, read from KV whenever `archiveToDb` is false. Add a service-level test for the Prisma backend.

4. **major** — `packages/plugin-triggers-core/src/stores/kv-trigger-runtime-stores.ts:50`. **The remaining-scope list leaves out deferred trigger events, which never expire.**
   - **What:** only `completed`, `failed` and `dlq` events get a TTL. A `deferred` event never moves to a terminal status: nothing in the core or the plugin calls `updateStatus` after a deferral fires. So every deferred event record and its `by-trigger` index entry is kept forever.
   - **PR body:** it presents "deferred events survive" as intended behaviour, and the Remaining scope list for #2109 doesn't mention it.
   - **Rule:** a `Refs #N` PR must state its remaining scope honestly.
   - **Fix:** do one of these:
     - mark the event terminal when the deferred action fires;
     - give deferred events a TTL from their fire time plus the retention window;
     - list it explicitly under Remaining scope on the PR and on #2109.

5. **minor** — `packages/plugin-sagas-core/src/stores/saga-kv-retention.ts:42,90` and `packages/kv/adapters/memory.adapter.ts:155`. **`list({ start })` behaves differently per adapter.**
   - `MemoryKvAdapter` treats `start` as exclusive; Deno KV treats it as inclusive.
   - On Deno KV, the public `cleanupRetention(1)` therefore re-lists the same entry on every call and never makes progress. The test passes only because it runs on the memory adapter.
   - Larger limits just overlap pages by one entry.
   - **Fix:** advance the cursor past the last key, or reject `limit < 2`.

6. **minor** — `plugins/sagas/src/runtime/create-durable-saga-runtime.ts:166-168`. **The background sweep polls every 100 ms with no idle backoff.**
   - That is about 10 KV `list` calls per second per saga process even when there is nothing to do, and Deno Deploy KV bills reads.
   - Under a backlog, each tick handles only one page of one instance.
   - **Fix:** back off exponentially when the retention prefix is empty, and keep looping without a delay while there is a backlog.

7. **minor** — `packages/plugin-sagas-core/src/stores/kv-saga-runtime-stores.ts:133`. **Applied-key retention reads state outside the atomic write.**
   - `KvSagaAppliedKeyStore.record` reads the state but doesn't include it in the atomic check.
   - If an applied key is written after the instance's terminal sweep has finished, it gets no TTL and is kept forever. The same is true of a key recorded for an instance that never saves state.
   - **Fix:** add the state versionstamp to the checks.

8. **minor** — `packages/plugin-sagas-core/src/stores/kv-saga-store.ts:93,139,157`. **Every saga step now costs about three extra KV reads.**
   - Each `save`, `appendTransition` and `saveCorrelation` now does an extra `get` or `load`.
   - Consider passing the known envelope or status down from the engine instead.

9. **nit** — `plugins/sagas/src/runtime/saga-instance-projection.ts:87`. `KvSagaInstanceProjection` uses `Date.now()` instead of an injectable clock, unlike the stores.

10. **nit** — `KvSagaAppliedKeyStore` now silently ignores `activeTtlMs` (marked `@deprecated` only). This changes published behaviour for existing callers, so it needs a CHANGELOG or migration note.

**Hygiene:** the PR body has no local paths, hostnames or session IDs, and the diff adds no `deno-lint-ignore`, `as unknown as`, `@ts-ignore` or `any`, and nothing under `.llm/runs/`.
