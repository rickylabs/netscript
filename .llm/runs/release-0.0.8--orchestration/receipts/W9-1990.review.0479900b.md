### Findings

1. **major — `packages/plugin-sagas-core/src/adapters/saga-bus-bridge.ts:235`: throwing handlers persist partial in-place mutations.** `executionRequest` shares `request.state` with the compensator. When a handler mutates that object and throws, the catch commits the already-mutated `request.state`. Reproduced with `saga.state.first = true; throw new Error(...)`: both plain and atomic stores persist `first: true`, status `failed`, version 2. This contradicts the documented guarantee that partial mutations are discarded. The added test replaces `saga.state`, which misses the aliasing defect. **Fix:** execute compensation against a cloned state and retain an untouched snapshot for failure persistence. Add regression tests for direct and nested-object mutations followed by a throw, in both store modes.

2. **major — `packages/plugin-sagas-core/src/adapters/saga-bus-bridge.ts:195` and `packages/plugin-sagas-core/src/runtime/saga-engine.ts:243`: distinct sibling compensations are mistaken for replay.** Every effect returned by one `.on()` receives the same state/version context; compensation identity contains only the instance and that version. With `[sagaCompensate(First), sagaCompensate(Second)]`, both handlers execute, but the second commit is suppressed as a duplicate. Reproduced in both store modes: First returns `[]`; Second changes state and returns `sagaFail(...)`; the store remains `compensated` at version 2 with only First’s state. Second’s state and terminal outcome are lost silently. **Fix:** carry the latest committed state/version through sequential sibling compensation dispatch and ensure distinct steps cannot share a replay identity. Add a two-branch regression proving both state changes and the second terminal outcome persist, while genuine replay remains write-free.
