Verdict: REVISE at 665a265f4bf02557cbadca152895c2e9865caca4

Headline: the code is sound and idiomatic, but the shipped guidance gets TTL semantics backwards. On the server this repo locks, a TTL slides with every append or read; the docs say it runs from creation. The main thing users are told to rely on would therefore not bound an active stream.

### Findings

1. **major** — `docs/site/durable-workflows/how-to/bound-stream-retention.md:17`, `:51`; `docs/site/durable-workflows/streams.md:219`; `docs/site/reference/plugin-streams-core/index.md:149-150`; `packages/plugin-streams-core/README.md:190` (also copied into the regenerated MCP fallback and the CLI agent-docs carriers).
   - **What the docs say:** "A TTL starts at creation, not at the latest append" and "appends do not renew it".
   - **What the server does:** the locked `@durable-streams/server` (`~0.3.7`, which the streams plugin runs through `DurableStreamTestServer` and the file-backed store) expires a TTL stream at `lastAccessedAt + ttlSeconds`. Both the in-memory and file-backed stores label this "sliding window from last access", and `touchAccess` runs on every read and append. The upstream client skill says "seconds from creation", but the server we ship does not behave that way.
   - **Runtime proof at this head:** I created a stream through the PR's own `DurableStreamProducerTransport` with `{ kind: 'ttl', ttlSeconds: 2 }`, then appended once a second for 4 s. `DurableStreamAdmin.head` still returned metadata after 4 s. After 2.5 s with no access it returned `null`, and `delete` then returned `{ deleted: false }`.
   - **Impact:** a producer that keeps writing with `ttl` never expires. That defeats the "bound a stream" goal, and agents will repeat the claim through `find_guidance("stream retention")`.
   - **Fix:**
     - Describe `ttl` as an idle or inactivity window that appends and reads renew.
     - Name `expires-at` (or rotating day segments) as the hard bound.
     - Correct the reopen/renew wording to match the server.
     - Regenerate `gen:agent-docs-prose`, `gen:assets-barrel` and `gen:publish-assets`.
     - Add a reference-server test that pins the behaviour, along the lines of the probe above.
2. **minor** — `packages/plugin-streams-core/src/application/durable-stream-producer-support.ts:90-92` and `src/domain/producer-contract-v1.ts:117-118`.
   - **What:** the public `StreamProducerTransportFailureKindV1` union gains `unauthorized` and `timeout`. Any consumer that switches exhaustively on it will break.
   - **What:** `isRetryable` now retries `timeout`, but the producer transport never emits it. That changes supervisor behaviour for custom transports, with no test and no mention in the PR body.
   - **Fix:** note the widening in Drift/Debt. Either test the new retry rule or drop it until a producer adapter emits `timeout`.
3. **minor** — `packages/plugin-streams-core/mod.ts:70-80` and `admin.ts:5-26`.
   - **What:** the helpers, `StreamAdminError` and every admin type are exported from both `.` and `./admin`. That gives two public import paths for the same symbols.
   - **Fix:** keep the helpers and types in root, and make `./admin` carry only the adapter (`DurableStreamAdmin`). Alternatively, record the duplication as an intentional choice.
4. **minor** — PR body, Validation section.
   - **What:** every recorded gate cites head `770eb24`. The current head is `665a265` (a merge of main plus four regeneration commits).
   - **Fix:** refresh the validation head. My scoped re-runs reproduce at `665a265` (see below).
5. **minor** — `.llm/tools/generate-publish-assets.ts:33`.
   - **What:** the MCP fallback cap rises from 256 KiB to 320 KiB, mostly to embed the whole streams reference page. It is disclosed and still finite, but it is a budget decision for the coordinator.
   - **Fix:** get the coordinator to acknowledge it, or embed only the retention section or how-to.
6. **nit** — `src/ports/stream-admin-port.ts:30` and `src/application/administer-durable-stream.ts:80` use inline `import('…')` type references. Use top-level `import type` to match the rest of the package.
7. **nit** — `administer` builds a fresh `StreamsInstrumentation` and `DurableStreamAdmin` on every call. It is cheap, but a module-level default would avoid repeated tracer/meter lookups in sweep loops.
