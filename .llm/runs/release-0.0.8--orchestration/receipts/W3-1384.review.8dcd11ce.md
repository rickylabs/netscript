### Findings

1. **major — `packages/auth-kv-oauth/src/store.ts:230`, `packages/auth-kv-oauth/src/backend.ts:263`: Global logout silently misses sessions persisted before this upgrade.** Enumeration reads only the new subject index, with no migration or fallback for existing session records. The newly indexed session was revoked. **Fix:** provide migration-safe subject revocation and add an upgrade regression test covering existing, unindexed sessions. Rotation-dependent backfill does not fulfill global logout.

2. **major — `packages/auth-better-auth/src/better-auth-backend.ts:104`, `packages/auth-workos/src/workos-backend.ts:109`: Subject-wide revocation remains unsupported in two shipped backends.** Both new implementations always throw; their added tests explicitly assert unsupported behavior. 3. **major — `packages/cli/src/public/features/plugins/auth/auth-plugin-command.ts:157`, `packages/cli/src/public/features/plugins/auth/auth-session-client.ts:31`: `session list` still permits an anonymous request.** Without an injected context or `NETSCRIPT_AUTH_TOKEN`, the command passes undefined options and the adapter uses optional authentication metadata. I reproduced a successful command invocation sending a fetch with no Authorization header. Only operator revocation refuses missing credentials. **Fix:** require a credential for both session commands and add a list test asserting refusal before fetch when none is available.

4. **major — `packages/auth-kv-oauth/src/backend.ts:261`: Global logout performs unbounded work and allocation inside one HTTP request.** It scans the entire subject index, performs sequential per-session reads and revocation writes, and retains every revoked `AuthSession` in an array before auditing. Revoked entries remain indexed for the store TTL, so later calls also scan historical sessions. There is no session-count bound, paging contract, or cancellation input. **Fix:** bound request work and memory while preserving complete logout—for example, immediate subject-level invalidation with bounded cleanup, or an enforced session bound and bounded processing. Add scale coverage for historical entries.

5. **minor — `packages/plugin-auth-core/src/contracts/v1/auth.contract.ts:538`: Existing file-size debt is deepened without a debt-registry update.** The contract grows from 546 to 615 lines. The PR acknowledges this in prose, but supplies no scoped registry entry with an owner, target, and closing gate. **Fix:** split the contract by concern or record the increased debt with a bounded remediation plan.
