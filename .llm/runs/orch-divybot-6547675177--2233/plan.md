## Locked decisions

Restore the exact historical row labels. Source row is `sha256:<digest>` of canonical
JSON `{schemaVersion:1,files:<sorted decoded prose map>}`, including derived llms-full.
Extraction row is `release:<framework version>`; document these compatibility labels.
Compute at installation from decoded corpus so no global digest causes carrier conflicts.
API generation time retains its separate caller clock and is fixed in parity fixtures.

Strict byte parity test builds its expected complete manifest independently from the
canonical carrier read by the generator tooling, then compares generated bytes and real
`initAgent --with-docs` filesystem bytes. No fixture docs generator in this test.
A second clock proves only API generation time changes. Negative controls remove either
row or substitute volatile provenance and require the strict parity test to fail.

## Risks and mitigations

- Aggregate metadata conflicts: derive at runtime; leave sidecar unchanged.
- Tautological parity: independent expected full manifest from canonical carrier input,
  real generator and real installer; negative mutations must fail.
- Volatility: source identity independent of clock and Git; clock-specific test.
- Version mismatch: use existing release/version guards and fixed API runner.
