# Listener recovery continuation

Preserve cumulative published metrics while resetting an independent burst budget.
An elapsed-time window must exclude backoff and remain separate from crash-loop
health. Keep tests on all listener composition paths: jobs, tasks and triggers.

After merging main, a backend fault-injection test can compile while no longer
injecting a fault. Require the expected refusal and inspect the negative assertion;
a timeout is not evidence of budget exhaustion. Receipt-based Redis claims now need
Lua-command ACL denial rather than denial of the previous dequeue command.

Use typed dependency errors before message matching where the package supplies a
stable code. Always test that the resulting HTTP health uses fixed safe text.

Changed guides and public exports have generated CLI/MCP carriers. Check their
freshness before handing off; regenerate through the repo tasks and inspect the
changed package rows. Preserve exact-pushed-head review by publishing final verdicts
as PR comments rather than moving the head with an evidence-only commit afterward.

## R2 integration

Carrier conflicts are resolved by recomputing from the merged authoritative source;
combining generated payloads manually would discard main's new ListenOptions fields.
Prove both supervisor recovery and upstream queue concurrency when integrating a
supervisor with a changed backend lifecycle. A positive test alone is weaker than
its explicit budget-exhaustion reset-revert control. The unchanged source and main-
owned files can be checked byte-for-byte before signoff. Preserve the final review
SHA by posting final evidence on the existing PR rather than adding a trailing
artifact commit. Assignment report-file handoff queues publication, not acceptance.
